## 11. 本次长会话新增决策与经验

### 11.1 小程序与客户端的关系

- 小程序不是重新设计一套业务，而是客户端 V0.7.0 功能的移动端重排。
- 首页只保留概览和今日工作入口；工作台按客户端原有“常用、学习分析、班级事务”分类承载模块；设置承载数据、授权、帮助、更新和关于。
- 移动端可以使用卡片、分步表单、抽屉或滚动布局，但不能删除客户端已有核心动作。
- 字段名称、集合名称、稳定 UUID 和状态值必须保持一致，不能为了界面方便改成另一套数据模型。

### 11.2 数据和同步原则

- 云端数据按微信身份隔离，不能相信客户端传入的 `ownerId`。
- 班级业务必须同时带 `datasetId` 和 `classUuid`，避免跨数据集或跨班级读写。
- 默认软删除；彻底删除前必须检查表现量化、历史记录等引用关系。
- 当前 `sync-data` 只有状态检查，不能称为双向同步。真正同步必须包含首次确认、变更队列、游标、增量批次、冲突、重试和可恢复状态。
- 当前多数交换功能使用“复制 JSON 到剪贴板”，这是安全的移动端等价方案，但不等于 Excel 文件导入导出。

### 11.3 开发者工具排错经验

- 看到 `file not found`、`Page has not been registered`、`subPackages of undefined` 时，第一检查项是开发者工具项目根目录和缓存，不要直接重写业务页面。
- 正确项目根目录是 worktree 根目录，不能选父目录，也不能只选 `miniprogram` 子目录。
- 开发者工具会自动改写 `project.config.json`，可能产生未提交的默认字段或换行差异；新会话应先检查 `git status`，不要误提交这些工具副作用。
- `getSystemInfo`、`SharedArrayBuffer`、`reportRealtimeAction not support` 通常是开发者工具提示，不应与业务错误混淆。
- `simulator not found` 可能是 app 配置读取失败后的连带错误，先修复项目配置并重载项目。

### 11.4 当前实现质量结论

- 当前已经从“只有页面骨架”推进到多个模块具有真实 CloudBase 读写闭环。
- 但仍不能称为“全部客户端功能完成”，因为 Excel、文件、完整备份、双向同步、身份绑定和部分统计仍缺失。
- 每个后续节点都应采用：桌面端功能核对 → 数据契约设计 → 小程序实现 → 空/错/无权限处理 → 自动化测试 → 微信开发者工具验证 → 分支提交。
