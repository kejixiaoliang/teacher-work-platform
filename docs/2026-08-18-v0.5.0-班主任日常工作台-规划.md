# 教师工作台 v0.5.0 班主任日常工作台规划

> 规划日期：2026-08-18  
> 目标版本：v0.5.0  
> 基线版本：v0.4.2  
> 状态：已发布（2026-08-25；发布标签：`v0.5.0`）

本文件保留为 v0.5.0 的立项规划记录。实际交付范围、发布证据和未完成验收项以同版本的[版本总结](2026-08-21-v0.5.0-班主任日常工作台-版本总结.md)和[发布检查清单](2026-08-21-v0.5.0-班主任日常工作台-发布检查清单.md)为准。

## 一、版本定位

将教师工作台从“班级数据管理工具”推进为“班主任每日打开即可处理工作的本地工作台”。

v0.4.0—v0.4.2 已经完成表现量化、稳定性审计、完整备份恢复和文件访问安全。本版本不再继续扩展底层安全边界，而是把现有学生、考勤、请假、值日、成绩、表现量化和家校沟通能力串成可执行的日常工作闭环。

## 二、当前基线

### 已完成

- 学生档案、健康数据、跟进状态和学生统一时间线。
- 成绩、考勤、请假、值日、家校沟通和表现量化模块。
- 全局搜索、班级切换、学生详情跳转和基础统计概览。
- 数据库与附件 ZIP 完整备份恢复。
- 一次性文件授权、文件签名校验和便携版发布 QA。

### 部分完成

- 首页已有统计和快捷入口，但缺少“今天要处理什么”的聚合视图。
- 学生有“需关注/跟进中/已处理”状态，但缺少带截止时间、处理结果和历史状态的跟进事项。
- 学生时间线可以查看来源记录，但还不能直接创建和关闭跟进任务。
- 各模块可以分别导出，但缺少统一的学生报告和班级月报。

### 暂未纳入本版本

- 账号、多人协作、云同步和家长端。
- 移动端重写和在线消息发送。
- AI 自动判断学生风险或自动替教师发送通知。
- 复杂的学校级权限和多租户模型。

## 三、核心目标

1. 打开首页即可看到当天和近期需要处理的事项。
2. 每个事项都能直接跳转到原始业务页面或学生档案。
3. 关注学生能够形成“发现—跟进—沟通—完成”的闭环。
4. 常见家长沟通和班级管理场景可以生成可打印、可导出的报告。
5. 继续保持本地优先、单机可用、数据可迁移。

## 四、功能范围

### P0：班主任工作台首页

新增或重构概览首页，按当前班级和本地日期聚合：

- 今日考勤状态和未完成考勤。
- 今日请假学生及待确认事项。
- 今日值日组和未完成值日提醒。
- 近期考试及待录入成绩提示。
- 需关注学生和逾期跟进事项。
- 最近备份时间和备份状态提醒。

每个卡片必须提供明确的跳转入口；空数据时显示可执行的下一步，而不是只显示“暂无数据”。

### P0：跟进事项闭环

在保留现有学生 `follow_up_status` 的基础上，新增结构化跟进事项：

- 关联学生、标题、内容、创建日期、截止日期。
- 状态：待处理、跟进中、已完成、已取消。
- 可关联成长记录、家校沟通或表现量化记录。
- 支持从学生详情和首页创建。
- 支持按状态、截止日期和学生筛选。
- 记录完成时间和处理结果。

现有跟进状态继续作为学生级摘要；跟进事项作为可追踪的明细，不直接破坏已有数据。

### P1：学生成长报告

在学生统一时间线基础上增加只读报告视图，聚合：

- 基本档案和健康快照变化。
- 成绩趋势和最近考试结果。
- 考勤、请假和表现量化摘要。
- 家校沟通记录。
- 未完成和已完成跟进事项。

第一版支持打印和导出 HTML/Excel；PDF 是否纳入取决于现有桌面打印链路验证结果。

### P1：班级月度报告

提供统一的班级报告入口，至少包括：

- 出勤和请假统计。
- 表现量化分类统计。
- 成绩概况和变化趋势。
- 需关注学生名单。
- 家校沟通和跟进事项汇总。

报告必须显示统计周期、当前班级和生成时间，避免不同页面筛选口径混用。

### P2：本地提醒和事项管理

- 支持手动新增班级临时事项。
- 支持截止日期和完成状态。
- 首页显示逾期和即将到期事项。
- 暂不实现系统级通知、后台常驻提醒或云端推送。

## 五、建议的数据与接口边界

建议新增独立的 `follow_up_tasks` 表，不把跟进事项继续编码在学生备注中。初步字段：

```text
id, class_id, student_id, title, content,
status, due_date, created_at, completed_at, result, source_type, source_id
```

后端建议按以下边界提供接口：

- `GET /api/workbench/today`：首页聚合数据。
- `GET/POST/PUT /api/follow-up-tasks`：跟进事项查询和维护。
- `GET /api/students/:id/report`：学生报告数据。
- `GET /api/classes/:id/report`：班级周期报告数据。

首页聚合接口只负责读取和汇总，不在一次请求中隐式修改考勤、请假或成绩数据。

## 六、实施顺序

1. 先建立跟进事项数据模型、校验、迁移和 API。
2. 增加跟进事项前端入口和学生详情关联。
3. 重构概览首页为今日工作台，接入现有模块的只读摘要。
4. 增加学生成长报告。
5. 增加班级月度报告。
6. 根据真实数据量评估列表分页、聚合缓存和大数据量性能。

## 七、验收标准

- 打开首页后，可以看到当前班级当天至少三类可执行事项或明确的空状态引导。
- 首页事项可以跳转到学生、考勤、请假、值日、成绩或跟进事项原页面。
- 创建、编辑、完成、取消跟进事项后，学生详情和首页状态一致。
- 跟进事项与家校沟通记录可以互相定位，原有时间线记录仍可定位到来源模块。
- 学生报告和班级报告的统计周期、班级范围和生成时间明确。
- 旧版 v0.4.2 数据库升级后，原有学生、成绩、考勤、请假、文档和表现量化数据不丢失。
- `npm test`、`npm run build`、数据库迁移测试和便携版 QA 通过。

## 八、风险与决策点

- 首页聚合如果直接复用多个页面的加载逻辑，容易出现重复请求和统计口径不一致，应优先设计统一只读聚合接口。
- 跟进事项与现有学生跟进状态可能产生双重状态，必须明确“学生级摘要”和“事项级明细”的关系。
- 报告导出会涉及 Excel、打印和文件权限，应先做数据口径和 HTML 打印，再决定是否引入 PDF 生成依赖。
- 本版本不引入云端和账号系统，所有事项、报告和历史仍保存在本机 SQLite 中。
