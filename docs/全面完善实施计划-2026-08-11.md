# 教师工作台全面完善实施计划

计划日期：2026-08-11  
执行分支：`codex/comprehensive-improvement`  
目标：在不破坏现有 Web/Tauri 共用业务代码的前提下，修复审计问题、完善高频功能并增加可追溯的工作台能力。

## 1. 执行原则

- 先数据安全与一致性，再交互优化，最后扩展新功能。
- 每个阶段都必须有最小回归测试、构建验证和独立提交。
- 破坏性操作必须先生成可恢复快照；导入、恢复、删除要能说明影响范围。
- API 契约优先：统一状态码、错误码、分页/批量结果和日期格式。
- Web 与 Tauri 共用同一业务实现，桌面差异只放在运行时适配层。

## 2. 阶段计划

### 阶段 A：安全与输入边界（P0，第一优先级）

工作项：

1. 建立后端统一校验工具：正整数 ID、外键存在性、日期/月、枚举、有限数值、字符串长度和数组上限。
2. 收紧备份恢复：校验应用版本/数据版本/表集合/schema/行规模/字段类型；增加预检模式、事务回滚、恢复后 `foreign_key_check` 和快照状态。
3. 加固文件上传：内容签名校验、单文件/目录/批次配额、文件名和 MIME 安全策略、失败清理、孤儿文件检测。
4. 收敛本地 API：统一 body/上传限制、超时和错误响应；移除长期 query token，或改为一次性下载授权。
5. 对依赖漏洞建立处理记录：尝试安全升级；若无可行修复，记录受影响路径、缓解措施和复查日期。

验收：非法 ID/外键/日期/超额 payload 均返回稳定 4xx；坏备份不改变数据库；伪装扩展名文件不能被当作可执行/可内联内容；恢复前后均有可验证快照。

提交建议：`安全：统一 API 校验与资源配额`、`安全：加固备份恢复与文件上传`。

### 阶段 B：数据一致性与高频缺陷（P0/P1）

工作项：

1. 将批量学生、成绩、考勤、值日操作统一为“事务 + 明细结果”契约。
2. 抽取健康快照、请假联动和删除/恢复逻辑，使用结构化来源字段替代备注字符串约定。
3. 统一本地日期工具，修复东八区午夜、月份切换和快速切班竞态。
4. 增加数据库约束、索引和迁移失败恢复测试；补齐软删除对象不能写入业务数据的测试。

验收：批量部分失败行为可预测且可恢复；请假变更不会覆盖人工考勤；健康字段真实变化会写入一条来源明确的历史快照；切班后不会出现旧班数据覆盖新班。

提交建议：`修复：统一批量写入与跨模块数据一致性`、`修复：统一日期时区与页面竞态`。

### 阶段 C：成绩与考勤功能完善（P1）

工作项：

1. 增加可复用科目模板、考试科目排序与复制。
2. 增加 Excel 导入预览：表头识别、重复科目、未知学生、越界分数、空值和重复行汇总；确认后一次事务提交。
3. 完善成绩矩阵空数据、切班、切考试、未保存离开和导出回读流程。
4. 增加考勤“默认出勤—请假建议—教师确认/覆盖”流程和月度统计边界。

验收：导入失败行不污染有效行；修改考试科目不会静默删除已有成绩；五类考勤/请假场景均可保存、重载和解释。

提交建议：`功能：完善成绩科目模板与导入预检`、`功能：完善考勤请假联动工作流`。

### 阶段 D：工作台与可追溯能力（P1/P2）

工作项：

1. 学生详情增加统一时间线，只读聚合成长、健康、成绩、考勤、请假和沟通来源。
2. 首页增加今日待办、请假提醒、近期考试、值日安排和可关闭告警。
3. 增加班级日历、提醒和可复用通知模板；先做本地数据，不引入账号/云同步。
4. 增加操作日志/恢复中心：删除、恢复、导入、备份恢复均记录操作者来源、时间、对象和结果。

验收：从学生详情可定位到原始记录；首页事项可跳转并标记处理；关键破坏性操作可查、可恢复。

提交建议：`功能：增加学生统一时间线与首页待办`、`功能：增加操作日志与恢复中心`。

### 阶段 E：质量门禁与发布验证（持续执行）

每次提交至少执行：

```text
npm test
npm run build
node --check <涉及的后端 JS>
```

涉及依赖、数据库、上传、恢复或发布脚本时，追加对应集成测试、`npm audit` 结果记录和便携包 QA。每个阶段完成后提交一次；跨阶段前确认工作区干净、提交信息清楚，必要时推送远端。

## 4. 明确不纳入本轮

本轮暂不引入账号系统、云同步、多人协作、移动端重写或复杂权限模型；先把本地单机数据的正确性、可恢复性和教师高频工作流做稳。
