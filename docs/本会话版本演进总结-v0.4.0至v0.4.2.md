## 二、v0.4.0：学生表现量化模块

### 版本目标

在教师工作台中建立可长期使用的学生日常表现量化系统，让班主任能够按统一规则记分，并按月度和学期查看结果。

### 主要功能

- 新增行为分类、行为项目和固定分值规则。
- 支持规则新增、编辑、停用、启用和删除。
- 支持手动多选、全班、值日组和班委组批量记分。
- 支持月度统计、学期累计、学生排名和分类贡献统计。
- 支持查看学生加分/扣分明细。
- 支持 Excel、CSV、JSON 导出。
- 记录编辑、撤销、恢复及修正原因。
- 保存行为分类、项目名称和分值快照，保证历史可追溯。
- 防止删除学生或班级时级联破坏量化历史。

### 重点问题处理

- 修复值日组选择误选全班学生的问题。
- 修复量化页面操作列按钮堆叠、截断和右侧空白。
- 修复图表首次进入时尺寸异常。
- 修复概览数据被流水筛选影响。
- 修复统计周期与导出内容不一致。
- 增加月份、日期和非法输入校验。

## 三、v0.4.1：全面审核与稳定性加固

### 版本目标

对 v0.4.0 的前端、后端、数据库、文件安全、构建和便携发布链路进行全面审核，并修复已经确认的 P1/P2 问题。

### 后端与 API

- 将多个 HTTP 200 + `{ ok: false }` 的失败响应统一为正确的 4xx/5xx 状态码。
- 统一参数校验，拒绝 NaN、小数、负数、非法日期和跨班级学生。
- 补齐资源不存在、业务冲突和无效输入的稳定错误码。
- 加强学生、文档、座位、请假、值日、成长记录和沟通接口。

### 数据库、备份与文件安全

- 备份导入增加重复主键和非法字段预检。
- 增加记录数量限制、字段名限制、外键检查和恢复前数据库快照。
- 增加上传文件扩展名和内容签名校验。
- 新增 BMP、WebP 和旧 Office 文件签名校验。
- 文件响应增加 `nosniff`、`no-referrer` 和 `no-store`。

### 前端稳定性

- `Assessment.vue` 增加班级快照和请求序列保护，避免旧请求覆盖新页面状态。
- 学生和值日批量删除从 `Promise.all` 改为 `Promise.allSettled`。
- 批量操作显示成功数量、失败数量和首条错误信息。

### 依赖与发布链路

- 将 `nanoid` 从 `3.3.17` 升级至 `3.3.18`。
- `npm audit --omit=dev --audit-level=moderate` 达到 `0 vulnerabilities`。
- 在 VS Build Tools x64 环境完成 Tauri Release 构建。
- 完成 Windows 便携包首次启动、数据库创建和正常退出 QA。

## 四、v0.4.2：备份归档与一次性文件授权

### 版本目标

完成上一版本留下的两个高价值优化：

1. 备份不仅保存数据库，还要携带上传文件本体，支持跨目录、换电脑恢复。
2. 文件预览和下载不再把长期 API token 放到 URL 中。

### 备份 ZIP

新版完整备份结构为：

```text
教师工作台完整备份.zip
├── backup.json
└── files/
    ├── 2026-xxx.pdf
    └── 2026-yyy.jpg
```

具体能力：

- 全量备份包含数据库表、文件清单和附件本体。
- 班级删除前的自动备份也包含该班引用的附件。
- 恢复支持新版 ZIP。
- 兼容 v0.4.1 及更早版本的 JSON 备份导入。
- ZIP 只允许 `backup.json` 和 `files/<basename>` 条目。
- 拒绝绝对路径、目录穿越、重复条目、超出文件数量或大小限制的归档。
- 恢复前校验文件大小和 SHA-256。
- 恢复失败时清理临时目录，并恢复原附件目录。
- 数据库继续保留恢复前快照，便于人工回滚。

### 一次性文件授权

文件访问流程变为：

```text
API Token
   ↓ 申请
30 秒文件 Token
   ↓ 绑定文档 ID
单次文件读取
   ↓
立即失效
```

具体能力：

- API token 只用于申请短时文件 token。
- 文件 token 有效期为 30 秒。
- token 绑定具体文档，不能访问其他文档。
- 成功读取后立即失效，不能重复使用。
- 一次性文件 token 不能访问普通 API。
- 前端通过认证 fetch 获取 Blob，再生成临时 Blob URL。
- 图片、PDF、文本预览和下载都不再拼接长期 API token。
- 文件响应继续保持 `nosniff`、`no-referrer` 和 `no-store`。

### 便携包问题与修复

v0.4.2 第一次便携 QA 未通过，原因是新增的 `archiver` 和 `unzipper` 没有被写入便携运行时依赖清单，导致内置 Node 后端启动失败、数据库未创建。

随后修复 `scripts/package-portable.mjs`，补齐便携运行时依赖，并重新打包验证通过。这次问题也说明：新增服务端依赖必须同步检查开发环境依赖和便携运行时依赖两套清单。
