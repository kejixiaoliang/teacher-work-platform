# 教师工作台 · 全面审查报告与解决方案

> 归档说明：历史审查资料，结论可能已被后续版本修复或替代。

> 审查范围：`server/`（db/seating/10 个路由）+ `web/src`（13 个页面 + App/store/api/router/EChart）
> 审查维度：后端性能与安全、前端功能逻辑、前端性能、交互与 UI 一致性
> 日期：2026-07-31 ｜ 分支：`style/content-lab`

---

## 〇、总体结论

- **没有 SQL 注入、没有路径遍历**（全部 SQL 参数化；文件名为服务端随机生成）
- 所有批量写操作均使用 `db.transaction`，无半程数据不一致风险
- 索引覆盖总体良好，高频查询命中现有索引
- 主要问题集中在：**切班级/离开页面时未保存数据丢失**、**快速切班竞态覆盖**、**上传内容校验缺失（潜在 XSS）**、**构建体积大（bundle 3.38MB）**、**响应式缺失**

## 一、功能与逻辑（P0 = 必修，P1 = 应修）

### P0：未保存数据丢失（最严重）

| # | 位置 | 问题 |
|---|---|---|
| 1 | `Scores.vue:302-314` | **切班级时不拦截未保存成绩**：`scoreDirty=true` 直接丢弃，无确认（App 顶栏只拦 Seats） |
| 2 | `Scores.vue` 全文 | **缺 `onBeforeRouteLeave`**：录入中直接点菜单去别的页，成绩静默丢失 |
| 3 | `Attendance.vue:84-92` | 切班级确认框「取消」后：班级已切换但 rows 仍是旧班数据，且再切会重复弹窗 |
| 4 | `Attendance.vue` | 缺 `onBeforeRouteLeave`，考勤登记中离开即丢 |
| 5 | `Scores.vue:333-352` | 切班级重置不完整：`allStudents` 未重置 + loadExams/loadStudents 并发无序 → 录入表可能显示**错班学生** |

**方案**：① 统一「离开拦截」：App 顶栏 `onClassChange` 增加对 Scores/Attendance dirty 的确认；② 各页面补 `onBeforeRouteLeave` + 浏览器 `beforeunload`；③ Scores 切班 watch 先重置 `allStudents` 并串行化加载；④ Attendance 取消确认时回滚 date。

### P1：竞态覆盖（快速切班/切学生显示错数据）

| # | 位置 | 问题 |
|---|---|---|
| 6 | 几乎所有 `watch(currentClassId, load)` | 无竞态防护，旧班级响应可能后返回覆盖新班级（仅 Seats 用了 loadSeq） |
| 7 | `Overview.vue:205-232` | 6 请求 Promise.all 无 seq；且任一失败 → 全部 6 组数据不更新 |
| 8 | `Students.vue:390-397` | 详情抽屉 3 个并发请求无竞态，快速点开不同学生会被覆盖 |
| 9 | `store.js:20-26` | `loadClasses()` 无 try/catch，接口失败应用启动即报错 |

**方案**：① 提取可复用的 `useSeqLoad()`（自增 seq，响应回来时比对，旧 seq 丢弃）；② Overview 的 Promise.all 改为 `Promise.allSettled` + 逐项落值；③ loadClasses 加 try/catch 兜底。

### P2：状态与资源

| # | 位置 | 问题 |
|---|---|---|
| 10 | `Seats.vue:355-356` | `store.seatsDirty` 离开页面未重置（幽灵脏标记） |
| 11 | `Students.vue:358` | `debounceTimer` 离开页面未 clearTimeout |
| 12 | `Documents.vue:186-201` | `load()` 双请求（带筛选 + 全量收集标签），每次搜索/切班重复 |

## 四、后端性能与安全

### 高优先级

| # | 位置 | 问题 |
|---|---|---|
| S1 | `documents.js:157-160` | **存储型 XSS 风险**：只按扩展名白名单，不校验真实内容；预览用客户端可伪造的 `req.file.mimetype` 作 Content-Type 并以 inline 渲染，且无 `X-Content-Type-Options: nosniff` |
| S2 | `documents.js:161` | `createReadStream().pipe(res)` 无 error 监听，下载时文件被删/IO 错误 → 进程崩溃 |
| S3 | `index.js:39` | 全局错误处理把 `err.message` 直接返回客户端，泄露 SQLite 内部细节 |
| S4 | `seats.js:37-53` | 保存布局只对 student_id 去重，两个学生可挤同一 (row,col) → UNIQUE 冲突 500 |

### 中优先级

- `leaves.js`/`duties.js`：写入不校验 `student_id ∈ class_id`，可跨班写脏数据
- `leaves.js /today`：日期范围查询无 (class_id, start_date) 复合索引
- `documents.js:62-80`：上传无 try/catch，class_id 非法时文件已落盘成孤儿
- 敏感信息：学生列表全量下发 phone/parent_phone/birth_date/health_note；`app.listen` 默认 0.0.0.0 且无认证（本地单机设计可接受，但若局域网使用需注意）
- 输入校验缺失：days/score/role/date 无范围/枚举校验，非法值可致 500

### 低优先级

- scores.js:13 / classes.js:16 相关子查询 COUNT（N 次）可改 LEFT JOIN 聚合
- seats PUT 每次保存写全量 JSON 快照，`seat_layouts` 无限膨胀（建议限最近 N 条）
- 各类 DELETE 不校验记录存在（幂等但掩盖错误）

## 六、风险与收益预估

- **第一批**：消除「录了半天成绩/考勤，切一下班级全没了」的体验事故（用户最痛的场景）
- **第三批**：bundle 3.38MB → 首屏 0.8-1.2MB，CSS 380KB → ~100KB，启动明显变快
- **第四批 S1**：堵住「上传伪装图片的 HTML 被浏览器执行」的安全隐患
- 全部改动均在 `style/content-lab` 分支进行，每批完成后构建验证 + review 复查再提交
