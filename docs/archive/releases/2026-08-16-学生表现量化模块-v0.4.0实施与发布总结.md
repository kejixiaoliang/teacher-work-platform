# 学生表现量化模块 v0.4.0 实施与发布总结

> 归档说明：历史版本资料，仅用于追溯当时的实现与发布过程。

> 模块：学生表现量化 / 学生日常考核量化

## 一、项目背景

本次版本在教师工作台中新增“学生表现量化”模块，用于按照学生日常行为表现进行统一记分，并支持月度管理、学期评价、统计分析和结果导出。

设计原则是：规则统一维护、记分记录容易统计、历史结果稳定可追溯、操作过程适合班主任日常使用。

## 二、最终确认的业务方案

### 1. 规则体系

- 全部班级共用一套行为量化规则。
- 规则分为“行为分类”和“行为项目”两级。
- 每个行为项目包含行为名称、说明、固定分值和重复记分规则。
- 预置基础行为项目，系统安装后即可使用。
- 支持自主新增分类和行为项目。
- 支持停用、启用、编辑和删除。
- 停用规则不影响历史记录，只影响未来新增记分。
- 停用分类下的行为项目不能继续新增记分。

### 2. 记分对象

一次行为记录支持同时选择多名学生，选择方式包括：

- 手动多选学生。
- 一键选择全班。
- 按值日组选择。
- 按班委组选择。

其中值日组会根据当前选择的具体组别，只自动选中该组成员，不会误选全部班级学生。

当前系统已有值日组和班委组，暂未扩展宿舍组、学习小组等其他分组。

### 3. 历史数据策略

- 已有记分记录不会因规则修改而重新计算。
- 记分记录保存行为分类名称快照、行为项目名称快照和分值快照。
- 修改行为项目名称或分值只影响之后的新记录。
- 已录入记录允许编辑，但必须填写修正原因。
- 每次编辑、撤销和恢复都记录修正历史。
- 历史记录优先展示当时快照，不依赖当前规则名称和分值。
- 普通删除学生或班级时，如果存在量化历史，系统会阻止删除，防止历史数据被级联删除。

### 4. 统计和导出

统计视图支持：

- 月度统计。
- 学期累计。
- 学生排名。
- 分类贡献统计。
- 学生净分趋势图。
- 分类加分/扣分图表。

支持导出：

- Excel。
- CSV。
- JSON。

导出数据会按照当前统计周期重新读取明细，保证页面统计结果和导出结果一致。

## 三、主要实现内容

### 1. 数据库和后端接口

新增并接入以下量化数据表：

- `assessment_categories`：行为分类。
- `assessment_items`：行为项目。
- `assessment_records`：学生记分记录。
- `assessment_record_revisions`：记分记录修正历史。

后端新增或完善：

- 分类和行为项目的增删改、启用/停用接口。
- 批量记分接口。
- 记分记录列表、编辑、撤销、恢复接口。
- 修正历史查询接口。
- 月度统计接口。
- 学期统计接口。
- 学生个人统计明细接口。
- 量化数据备份和恢复支持。

### 2. 批量记分优化

批量记分原先可能对每个学生单独查询是否重复，形成 N+1 查询。

本次改为一次性读取当前班级、行为项目、行为日期下已有记录的学生 ID，再在内存中判断重复，减少数据库往返。

同时，接口会返回结构化跳过信息，包括：

- 学生不属于当前班级或已被删除。
- 本次操作重复选择学生。
- 学生当天已记录过同一行为。
- 行为分类已停用。
- 行为项目已停用。

前端会展示成功数、跳过数和逐行跳过原因。

### 3. 统计明细功能

在学生排名表中增加“操作”列和“查看明细”按钮。

点击后打开右侧抽屉，展示：

- 加分总计。
- 扣分总计。
- 净分。
- 记录次数。
- 行为日期。
- 行为分类。
- 行为项目。
- 分值。
- 备注。

明细接口支持月度和学期筛选，并使用记录中的历史快照字段。

### 4. 响应式 UI 优化

针对实际浏览器截图中出现的布局问题，完成了多轮调整：

- 将量化记录表和规则表改为更可控的原生 CSS Grid 布局。
- 操作列使用单行按钮布局。
- 调整操作列宽度，防止按钮被截断。
- 取消排名表操作列的固定定位，解决固定列产生的白色空白占位。
- 设置排名表各列明确宽度。
- 将“查看明细”改为带边框、阴影和交互反馈的胶囊按钮。
- 增加按钮 hover 和 active 状态。
- 窄屏下允许表格横向滚动，避免页面整体横向溢出。
- 限制量化页面和主内容区的横向滚动，避免浏览器缩放后出现页面级空白区域。
- 对统计图表容器设置稳定的最小宽度和响应式布局。

## 四、过程中遇到的主要问题及解决办法

### 问题一：值日组选择后误选全班学生

现象：选择值日组后，系统默认选中了全部班级学生。

原因：原先“值日组”只作为一个范围模式，没有继续根据具体组号筛选成员。

解决：

- 先读取当前班级的值日组数据。
- 按具体组号生成值日组列表。
- 选择某个组后，只将该组的学生 ID 作为批量记分对象。
- 在界面展示当前组名称和人数，帮助教师确认记分范围。

### 问题二：操作列按钮纵向堆叠、按钮被截断

现象：编辑、历史、撤销等按钮上下排列，或者第三个按钮只显示一部分。

原因：表格自动列宽、固定列、嵌套容器宽度和按钮最小宽度相互影响。

解决：

- 将操作区设置为 `display:flex`，禁止按钮换行。
- 为按钮设置稳定宽度和最小高度。
- 调整表格操作列的最小宽度。
- 对规则表和记分流水表分别设置合理的 Grid 列模板。
- 对窄屏保留表格内部横向滚动，而不是让整个页面溢出。
- 最终排名表取消固定操作列，避免 Element Plus 固定列复制层造成空白区域。

### 问题三：操作列调整后页面右侧持续出现大面积空白

这是本次 UI 调整中耗时最长、反复验证最多的问题，必须单独记录。

现象：

- 操作列按钮看起来已经缩小，但表格右侧仍然保留很宽的白色空白区域。
- 浏览器窗口改变尺寸后，空白区域的宽度会变化，甚至出现按钮显示不完整、表格边框和内容区域不对齐的情况。
- 在规则管理、日常记分流水和统计排名等不同页面宽度下，问题表现不完全一致。
- 部分情况下，页面刷新后布局异常，拖动浏览器窗口后才暂时恢复。

根因：

1. Element Plus 表格自动布局与固定操作列同时存在，固定列会生成独立的定位层和占位结构。
2. 表格外层卡片、内层表格容器和页面主区域各自存在宽度约束，列宽计算没有形成单一的布局边界。
3. 操作按钮设置了固定宽度，但操作列和表格总宽度没有同步收敛，导致“按钮实际宽度”和“表格预留宽度”不一致。
4. 窄屏场景下同时使用页面级横向溢出和表格级横向滚动，造成滚动容器嵌套，视觉上表现为右侧空白。
5. 图表和表格在窗口缩放后重新计算尺寸，但滚动位置和旧布局状态没有及时重置。

最终解决过程：

- 先收紧量化页面和主内容区的横向布局边界。
- 将量化记录表和规则表从不稳定的自动列宽方案改为原生 CSS Grid，明确每一列的宽度策略。
- 将操作区改为单行 Flex 布局，按钮不再换行。
- 对操作列设置最小宽度和按钮最小宽度，确保编辑、历史、撤销/恢复、删除能够完整显示。
- 移除排名表操作列的 `fixed="right"`，消除固定列复制层造成的空白占位。
- 对窄屏只保留表格内部横向滚动，禁止页面整体横向滚动。
- 在页面切换、数据刷新和窗口 resize 后重置页面及表格滚动位置。
- 最后通过宽屏、窄屏、窗口缩放和统计表格场景反复构建验证，确认右侧空白、列错位和按钮截断问题不再出现。

这个问题最终不是简单“把前面的列宽调小”就能解决，而是同时修正了固定列、自动列宽、容器边界、滚动层级和按钮宽度五个方面。

### 问题四：统计图表首次打开显示异常，缩放后才恢复

现象：图表首次进入页面时尺寸计算不正确，需要拉动浏览器窗口后才正常。

原因：图表在父容器尺寸尚未稳定时初始化，且统计区域的 Grid 宽度变化没有及时触发图表 resize。

解决：

- 让图表父容器具备稳定的宽度约束。
- 统计图区域使用响应式 Grid，在窄屏时切换为单列。
- 页面切换和窗口变化时触发表格滚动位置重置，减少布局状态残留。
- 图表内容从净分绝对值改为加分、扣分两个方向，避免视觉数据被错误合并。

### 问题五：分类贡献图只能看到净分，无法区分加分和扣分

现象：原先使用绝对值展示，分类净分为零时还可能被过滤，无法判断加扣分方向。

解决：

- 分类统计保留 `positive`、`negative` 和 `net` 三个口径。
- 图表改为加分和扣分两个柱状系列。
- 保留净分为零的分类数据，使零值状态可解释。

### 问题六：规则停用后无法重新启用

现象：停用分类或行为项目后，操作列只剩编辑按钮。

原因：前端操作列只根据启用状态显示“停用”，没有为停用状态提供反向操作。

解决：

- 启用状态显示“停用”按钮。
- 停用状态显示“启用”按钮。
- 后端同步校验状态变更。
- 历史记录不受启用/停用影响。

### 问题七：概览数据受流水筛选影响

现象：切换流水记录月份后，页面顶部“本月加分、扣分、净分”可能显示其他月份的数据。

原因：顶部概览直接复用了流水记录数组。

解决：

- 增加独立的概览数据加载流程。
- 概览固定读取当前自然月。
- 流水筛选只影响流水列表，不影响顶部概览。

### 问题八：统计页面导出内容与当前统计周期不一致

现象：统计页面选择某个月或某个学期后，导出的明细可能仍然来自日常流水页面。

原因：导出逻辑复用了流水记录数据，没有根据当前统计条件重新查询。

解决：

- 月度统计导出按 `class_id + month` 重新获取记录。
- 学期统计导出按 `class_id + academic_year + term` 重新获取记录。
- Excel、CSV、JSON 共用同一批当前周期明细。

### 问题九：历史修正内容展示不完整

现象：修正历史中的行为名称、分类名称或分值可能反查当前规则，无法准确反映当时状态。

原因：历史展示逻辑依赖当前行为项目和分类数据。

解决：

- 在修正前后快照中保存分类名称、行为名称和分值。
- 修正历史优先读取快照字段。
- 修正历史默认按最新时间倒序显示。

### 问题十：删除学生或班级可能级联删除量化历史

现象：数据库外键原本使用级联删除策略，删除班级或彻底删除学生可能连带删除表现量化记录。

原因：量化记录的历史保留要求与原有删除策略冲突。

解决：

- 学生彻底删除前检查是否存在量化历史。
- 班级删除前检查是否存在量化历史。
- 存在历史时返回明确错误码并拒绝删除。
- 保留现有数据和修正历史，避免普通管理操作造成不可逆的数据损失。

### 问题十一：月份和日期边界校验不严谨

现象：`2026-13`、`2026-00` 等非法月份可能通过格式校验；月底统计用字符串拼接下一个日期可能生成不存在的日期。

解决：

- 统一使用严格月份校验。
- 使用 UTC 日期计算月份范围和下一天，避免字符串直接拼接。
- 对学生明细、月度统计、流水查询和导出查询统一进行参数校验。

## 七、当前已知事项和后续建议

本次发布已经完成 v0.4.0 的核心量化功能和发布闭环，但以下事项适合后续迭代：

6. 对 Release 下载资产增加独立的下载后校验脚本或 CI 校验。

## 八、结论

本次 v0.4.0 已完成从需求确认、数据模型、后端接口、前端 UI、统计导出、历史保护、测试构建到 GitHub Release 的完整闭环。

核心结果是：教师可以用统一规则快速记录学生日常表现，并在月度和学期维度查看排名；当需要解释排名结果时，可以直接进入某名学生的加分和扣分明细；规则后续调整不会破坏历史结果，适合长期使用和学期评价。
