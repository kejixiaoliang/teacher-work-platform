# v0.4.2 备份恢复链路修复总结

> 归档说明：历史版本资料，仅用于追溯当时的实现与发布过程。

> 修复日期：2026-08-24  
> 基线版本：v0.4.2  
> 工作分支：codex/v0.4.2-backup-restore-fix

## 一、根因

服务端 ZIP 导入已经完成数据库事务和附件恢复，但首页恢复回调调用了不存在的 `store.loadClasses()`。实际函数是从 `store.js` 单独导出的 `loadClasses()`，导致恢复成功后刷新阶段抛出 `is not a function`，用户因此同时看到“恢复成功”和“恢复失败”。

退出程序后再次进入并不是程序重新自动恢复，而是此前的恢复已经成功提交，前端错误发生在提交之后。

## 二、本轮修复

- 首页恢复流程改为调用导出的 `loadClasses({ throwOnError: true })`。
- 服务端导入成功与前端刷新失败分开提示，刷新失败不再伪装成恢复失败。
- multipart 网络异常统一提示本地服务不可连接或恢复请求超时。
- 增加 ZIP 恢复后的班级、学生、附件和恢复前数据库快照断言。
- 增加外键损坏备份的失败恢复测试，验证原数据不被破坏。
- 审计确认现有数据库事务和文件回滚边界有效，本轮未进行无关服务端重构。

## 三、验证结果

- `npm test`：53/53 通过。
- `npm run version:check`：通过，产品版本保持 0.4.2。
- `npm run build`：通过；保留既有大体积 chunk 警告。
- 备份归档、ZIP 恢复、迁移回归测试：通过。
- `git diff --check`：通过，仅有 Windows 换行提示。

## 四、用户复测步骤

1. 启动修复后的程序并创建一个班级、学生和附件。
2. 执行完整备份并下载 ZIP。
3. 修改或删除一项数据。
4. 从 ZIP 恢复。
5. 应看到一条恢复成功提示，首页数据自动刷新；若刷新失败，只提示“数据已恢复”，不会再提示恢复失败。
6. 退出并重新进入程序，确认班级、学生和附件仍然存在。

## 五、限制

本轮没有重新执行 Windows 便携包完整 GUI QA；该验证需要在干净的桌面运行环境中完成。
