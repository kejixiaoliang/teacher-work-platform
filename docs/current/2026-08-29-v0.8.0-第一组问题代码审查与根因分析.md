# 教师工作台 v0.8.0 第一组问题代码审查与根因分析

> 审查日期：2026-08-29  
> 文档类型：代码审查与根因分析  
> 审查范围：座位表、文档上传、文档预览、文档下载  
> 当前基线：`codex/v0.8.0-known-issues`（`master@54f4744`）  
> 审查状态：已完成根因初判，待进入修复设计  

## 1. 审查结论

第一组反馈不是一个单一问题，而是三类情况：

1. 座位表在小尺寸屏幕上的布局确有可复现的 CSS 根因。
2. 文档功能的上传状态和文件操作已有基础实现，但反馈不完整，且按钮事件存在重复触发风险。
3. “不支持预览的文件应告诉用户路径”属于当前行为与目标体验不一致，需要补充桌面版文件定位能力。

本次只完成审查，没有修改业务代码。

## 2. 座位表审查

### 2.1 现有布局数据流

- 行数和列数直接来自当前班级的 `seat_rows`、`seat_cols`，默认值为 6 行、8 列：`web/src/views/Seats.vue:235-237`。
- 座位网格按行、列渲染，每个座位卡片还会显示姓名、身高、视力、近视和锁定状态：`web/src/views/Seats.vue:106-134`。
- 座位布局尺寸可以在左侧面板修改，并保存回班级配置：`web/src/views/Seats.vue:288-298`。

### 2.2 确认的根因

当前样式同时存在以下约束：

- 左侧控制面板固定宽度 250px，且不收缩：`web/src/views/Seats.vue:723-729`。
- 右侧画布自身设置 `overflow: auto`，并使用 `align-items: center`：`web/src/views/Seats.vue:745-749`。
- 每个座位宽度至少为 76px，座位之间有 10px 间距；双走道还额外增加 30px 左边距：`web/src/views/Seats.vue:761-764`。
- 座位卡片最小高度为 78px，姓名不换行，信息标签也有最小内容宽度：`web/src/views/Seats.vue:769-797`。
- 应用主内容区明确禁止横向溢出：`web/src/App.vue:424-434`。

以 8 列双走道为例，仅座位列宽和间距就约为 8 × 76 + 7 × 10 + 30 = 708px，还未计算画布内边距、控制面板、导航和窗口边框。小屏幕必然进入溢出场景。

### 2.3 为什么左侧列可能“永远看不到”

右侧画布是一个可滚动容器，但其子内容使用居中对齐。当网格宽度大于容器宽度时，网格会以中心为基准向左右同时溢出。右侧的正向溢出可以通过滚动条访问，左侧的负向溢出没有等价的可滚动空间，于是最左侧座位可能被裁掉。

这解释了截图中的两个现象：

- 大尺寸显示器无需滚动，因为网格总宽度小于可用空间。
- 小尺寸屏幕出现滚动，但向右滚动仍无法找回左侧两列，因为问题不只是“内容太宽”，还包括“超宽内容居中导致左侧负溢出”。

### 2.4 根因级修复方向

修复设计应同时处理四件事：

1. 超宽网格从左侧可访问位置开始布局，不能继续依赖居中产生负向溢出。
2. 允许在可用空间内自动缩小座位卡片，但设置可读性的最小尺寸。
3. 缩小到下限后保留横向滚动，并保证滚动范围覆盖完整网格。
4. 小屏幕下允许折叠或压缩控制面板，并增加明确的适应窗口/缩放操作。

单独把 `overflow-x` 改成 `auto` 不足以解决问题，因为应用主内容区仍隐藏横向溢出，而且无法解决居中布局的负向溢出。

## 3. 文档上传审查

### 3.1 上传链路

前端逐个处理选择的文件，创建 `FormData`，带上文件、班级和标签，然后调用上传 API：`web/src/views/Documents.vue:227-245`。

上传队列有三种状态：

- `null`：上传中。
- `true`：成功。
- `false`：失败并显示错误文本。

对应界面位于 `web/src/views/Documents.vue:93-99`。

服务端使用 Multer 写入文件，完成扩展名、文件签名、容量、班级存在性校验后写入 `documents` 表：`server/routes/documents.js:26-90`、`server/routes/documents.js:96-140`。

### 3.2 确认的体验缺口

当前实现能表达成功和失败，但存在以下缺口：

- 上传按文件串行执行，多文件时后面的文件会长时间保持“上传中”。
- 只有 15 秒超时，没有上传进度百分比或当前阶段说明：`web/src/api.js:115-131`。
- 上传完成后调用 `load()`，但没有等待列表刷新，也没有显示“列表已更新”的明确状态：`web/src/views/Documents.vue:244-245`。
- 用户关闭弹窗时直接清空队列，即使仍有请求在进行：`web/src/views/Documents.vue:101-103`。

因此，“一直显示上传中”不一定意味着服务端未完成，更可能是请求仍在等待、队列中存在后续文件，或用户关闭/切换界面后失去了完成反馈。

### 3.3 服务端边界

服务端成功返回前已经完成文件落盘和数据库写入：`server/routes/documents.js:122-134`。失败时会清理已落盘的孤儿文件：`server/routes/documents.js:135-138`。

这条链路目前没有发现“成功后永远不返回”的确定性代码错误；需要在修复阶段补充慢请求、超时、网络中断和大文件场景的回归测试。

## 4. 文档预览与下载审查

### 4.1 当前支持范围

前端把“图片、PDF、文本”判定为可内嵌预览，其他类型直接调用下载：`web/src/views/Documents.vue:252-270`。

服务端只对图片和 PDF 设置 `inline`，对 Word、Excel、PPT、压缩包和媒体等类型设置 `attachment`：`server/routes/documents.js:236-253`。

这个边界与“简单格式可以预览，不支持的直接告诉路径”的产品方向基本一致，但当前用户提示还没有实现。

### 4.2 已确认的前端缺陷风险

文件卡片本身绑定了 `@click="preview(f)"`，卡片内的“预览”和“下载”按钮也分别绑定点击事件，但没有阻止事件冒泡：`web/src/views/Documents.vue:49-61`。

因此：

- 点击“下载”可能先执行下载，再冒泡到卡片执行预览。
- 对支持预览的文件，点击“预览”可能触发两次预览请求。
- 对不支持预览的文件，按钮操作可能被重复触发。

这属于确定的事件边界问题，应在修复设计中优先处理。

### 4.3 预览反馈缺口

预览逻辑先打开弹窗，再异步读取文件：`web/src/views/Documents.vue:259-266`。弹窗内没有独立的读取中状态，因此在授权、网络或大文件读取期间，用户看到的可能是空白区域，容易误判为“点击无反应”。读取失败只显示通用文本和消息：`web/src/views/Documents.vue:267-270`。

下载流程同样只有异常消息，没有统一的“准备文件、正在保存、已完成”状态：`web/src/views/Documents.vue:272-276`。

### 4.4 文件路径需求的实现边界

服务端实际存储文件名经过随机化处理，文件位于应用数据目录，而不是用户上传时的原始文件名路径：`server/routes/documents.js:26-38`。

因此不能简单把 `stored_name` 直接展示给用户。桌面版应提供：

- 当前文件的实际完整路径。
- 复制路径。
- 打开所在文件夹并选中文件。
- 另存为。

浏览器版受浏览器权限限制，不能直接打开本机文件夹，只能显示提示并下载/另存为。路径和“打开所在文件夹”属于桌面版能力，需要通过 Tauri 桥接或受控本地 API 暴露，不能把长期 API Token 放进文件 URL。

## 6. 修复前需要确认的验收边界

进入实施计划前，需要把以下行为写成测试或手工验收项：

- 1280px、1024px、1366px 和小于 900px 的窗口宽度。
- 6×8、8×8、10×10 等不同座位网格和三种走道模式。
- 超宽网格可以从第 1 列滚动到最后 1 列，不能出现负向不可达区域。
- 图片、PDF、TXT/Markdown 的加载中、成功和失败状态。
- Word、Excel、PPT、压缩包等不支持预览类型的路径提示。
- 点击卡片、预览按钮、下载按钮时每个动作只执行一次。
- 多文件上传、慢请求、超时、失败重试和关闭弹窗时的状态。
- 桌面版路径复制、打开所在文件夹和另存为；浏览器版的降级提示。

## 7. 下一步

根因审查已完成，建议下一步单独撰写修复设计和实施计划，再进入代码修改。座位布局与文档文件操作可以分成两个小批次实施，分别测试和验收，避免把 CSS 布局问题与文件访问链路问题混在同一次改动中。

## 8. 实施结果（2026-08-29）

- 座位表：`.ws-body`、`.ws-canvas` 增加收缩边界，网格改为 `max-content + min-width: 100%`，超宽时从第 1 列开始横向滚动。
- 文档操作：预览/下载按钮阻止冒泡；预览增加加载、错误和重试状态；下载显示进行中与完成反馈；上传中禁止关闭后清空队列。
- 文件定位：新增 `GET /api/documents/:id/location`，仅对未删除文档返回服务端生成的实际路径和文件存在状态；前端对不支持格式显示路径并支持复制。
- 文件读取：文件流 fetch 增加 15 秒 AbortController 超时，并保留短时、单次文件访问授权。
- 验证：`npm test` 全量 92 项通过，`npm run build` 构建通过；仍需在 1280px、1024px、1366px 及小于 900px 的真实窗口完成手工视口验收。
