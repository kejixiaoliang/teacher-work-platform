# 教师工作台 v0.9.0 Windows 发布检查清单

本清单用于 v0.9.0 安装版、便携版和自动更新发布。没有完成的项目不得把 `latest.json` 指向生产用户。

## 已在当前分支完成

- [x] package、Cargo、Tauri 配置和前端版本统一为 `0.9.0`。
- [x] 安装版使用 current-user NSIS，数据目录为 `%LOCALAPPDATA%\TeacherWork\data`。
- [x] 便携版保持 EXE 同级 `data`，两种交付形式共用数据库迁移和备份格式。
- [x] Tauri updater 只在安装版启用，便携版继续手动升级。
- [x] 更新前阻止未保存座位变更，创建带附件的 `pre-update-*` 恢复点。
- [x] 安装包、`.sig`、`latest.json` 和 SHA-256 清单有生成与校验脚本。
- [x] 本地 fixture 覆盖无更新、发现更新、签名错误、资源不存在和断网。
- [x] 全量 Node 测试、Vite 构建、便携构建和安装版测试密钥构建通过。
- [x] v0.8 风格旧库升级到数据库版本 8 后，记录、附件和迁移恢复点仍存在。

## 发布电脑上必须补做

- [ ] 使用生产签名私钥构建，不把私钥写入仓库、日志或发布资产。
- [ ] 完成 Windows Authenticode 代码签名，并记录证书指纹和签名时间。
- [ ] 在干净 Windows 10/11 x64 虚拟机执行安装、首次启动、重启和卸载。
- [ ] 验证安装路径包含空格、中文用户目录、普通用户权限和重复安装覆盖。
- [ ] 验证卸载不删除 `%LOCALAPPDATA%\TeacherWork`，重新安装可读回旧数据。
- [ ] 用真实 v0.8.0 安装版和便携版数据分别执行完整备份互导。
- [ ] 用生产公钥构建后验证无更新、可更新、下载失败、签名错误和断网行为。
- [ ] 上传不可变版本目录中的安装包和 `.sig`，从公网重新下载并复核 SHA-256。
- [ ] 最后上传 `stable/latest.json`，确认清单中的 URL、签名、版本和 notes 均正确。

## 发布后回滚规则

1. 先停止发布 `latest.json` 的更新。
2. 保留用户数据目录和 `pre-update-*` 恢复点，不删除或覆盖原始备份。
3. 回退时同时使用匹配版本的程序和数据库/完整备份，不只替换 EXE。
4. 修复发布问题时递增版本号和不可变资产路径，不原地替换已发布安装包。
