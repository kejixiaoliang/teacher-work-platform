# 教师工作台 v0.8.0 用户反馈问题分类与修复范围

> 编写日期：2026-08-29  
> 文档类型：需求分类与版本范围说明  
> 当前基线：教师工作台 v0.7.0  
> 目标版本：v0.8.0  
> 文档状态：第一组已完成修复，第二/三组保留后续版本讨论  

## 1. 版本范围结论

v0.8.0 以修复现有问题、完善已有功能和提升可配置性为主，不新增独立业务模块。

本版本纳入以下方向：

- 修复座位表、文档上传与文件操作等现有问题。
- 完善学生字段、考试科目和值日规则的配置能力。
- 改善已有功能的入口、状态反馈和使用说明。

本版本暂不新增以下模块：

- 学生作业管理。
- 班主任日常台账。

上述两个新模块保留需求背景，后续单独讨论、设计和排期。

## 2. 第一组：现有问题修复

### 2.1 座位表显示不完整

用户反馈：

- 座位表无法完整显示。
- 左侧两列不可见。
- 使用底部横向滚动仍无法看到被遮挡的座位。
- 不同窗口大小和屏幕尺寸下表现不一致。

初步判断：

- 左侧控制栏占用固定宽度。
- 座位卡片存在最小宽度，列数较多时网格宽度超过右侧画布。
- 超宽网格采用居中对齐后，左侧内容可能进入无法滚动到的负向溢出区域。
- 当前实现缺少明确的缩放控制和适应可用空间的显示策略。

本版本目标：

- 确保任意受支持的行列数都能查看全部座位。
- 修复横向滚动无法到达左侧座位的问题。
- 支持按可用空间自动适配。
- 评估增加座位尺寸或缩放比例调节。
- 保持拖拽、选择、右键操作和打印功能正常。

实施结果：已通过窄屏布局契约和座位移动回归测试；网格从第 1 列起始，超宽时允许横向滚动。

### 2.2 文档上传状态不明确

用户反馈：

- 上传文件后长期显示“上传中”。
- 用户无法判断文件是否上传完成。

本版本目标：

- 明确显示等待、上传中、成功和失败状态。
- 上传成功后刷新文件列表并给出完成提示。
- 上传失败时展示可理解的原因并允许重试。
- 关闭上传窗口前提示仍在进行中的任务。

实施结果：上传队列保留成功/失败状态，上传期间禁止清空队列，并在结束后刷新列表。

### 2.3 文档预览和下载缺少有效反馈

用户反馈：

- 点击“预览”或“下载”后没有明显反应。
- 预览与下载的体验相似，用户不清楚两者区别。
- 文档预览目前使用弹窗，用户对这种方式存在疑问。

现有能力：

- 图片、PDF 和文本可以在应用内预览。
- Office 等不适合直接内嵌的文件会转为下载或外部打开流程。

本版本目标：

- 图片、PDF 和文本继续提供应用内预览。
- 对不支持内嵌预览的类型明确说明原因，并提供“另存并打开”操作。
- 下载成功后显示保存位置或保存结果。
- 所有文件操作都必须有加载、成功或失败反馈。
- 评估弹窗预览与独立预览区域的交互差异，优先保证行为清晰。

实施结果：预览增加加载/失败/重试提示，下载按钮增加进行中和完成反馈；Office、压缩包、媒体等不支持内嵌预览的文件显示实际路径并支持复制。

### 2.4 已完成问题

以下反馈已在此前版本完善，本版本只做回归检查：

- 自定义保存文件路径。
- 学生导入模板下载无反应。
- Excel 导出缺少保存结果反馈。
- 已录入学生资料无法修改。

## 3. 第二组：已有功能的配置能力与可发现性

### 3.1 部分词条允许自定义

用户希望修改部分系统词条，但目前尚未明确允许修改的范围。

本版本讨论范围：

- 模块内的业务称谓。
- 学生字段的显示名称。
- 值日角色或分组名称。
- 其他不影响数据语义的展示文字。

约束：

- 不允许直接修改数据库字段名或内部接口字段。
- 自定义名称只影响显示层和导入导出映射。
- 系统应保留稳定的内部标识，避免改名导致历史数据失效。

### 3.2 考试科目配置

用户反馈：不同省份和学校使用的考试科目不同，应允许修改。

现有能力：

- 新建和编辑考试时可以添加、删除或调整科目。
- 可以保存并复用科目模板。
- 成绩 Excel 导入会读取表头中的科目。

初步判断：

该问题更可能是入口不明显、提示不足或操作流程不直观，而不是完全缺少功能。

本版本目标：

- 提升科目编辑入口的可见性。
- 明确提示科目可以自由添加、删除和排序。
- 优化科目模板的创建、应用、修改和删除流程。
- 保证成绩录入、统计、导入模板和导出文件使用同一组考试科目。

### 3.3 值日管理规则

用户习惯：

- 全班分成五个值日小组。
- 五个小组分别对应周一至周五。
- 值日表应突出当天的值日学生。

现有行为：

- 系统默认按周轮换一个值日组。
- 已支持为小组设置值日星期，但值日表仍以周轮换为主要表达。

本版本目标：

- 在现有模块内完善“按星期固定分组”的使用方式。
- 默认支持五组对应周一至周五。
- 值日表优先显示当天日期、星期、值日组和值日学生。
- 保留现有按周轮换能力，避免影响已有数据。
- 让两种规则的选择和当前生效规则清晰可见。

## 4. 第三组：学生字段与 Excel 模板

### 4.1 用户需求

- 学生信息表头可以按学校情况调整。
- 可以增加身份证号等学校常用字段。
- 没有住宿场景的学校可以隐藏“住宿”字段。
- Excel 导入模板和导出文件应随字段设置同步变化。

### 4.2 推荐方向

不采用“任意修改数据库真实列名”的方案，采用“稳定核心字段 + 可选标准字段 + 自定义扩展字段”的配置模型。

字段分为三类：

1. 核心字段：姓名、学号、班级等维持稳定，不允许删除。
2. 可选标准字段：住宿、身高、视力等可以启用、隐藏或调整显示名称。
3. 扩展字段：允许学校增加身份证号及其他本地需要的信息。

### 4.3 联动范围

同一份字段配置应驱动：

- 学生列表表头。
- 新增和编辑学生表单。
- 学生详情页。
- Excel 导入模板。
- Excel 导入字段识别。
- Excel、CSV 和其他数据导出。

### 4.4 数据与隐私约束

- 内部字段标识必须稳定，修改显示名称不能破坏历史数据。
- 导入时应支持标准名称、用户自定义名称和兼容别名。
- 隐藏字段不等于删除已有数据。
- 身份证号属于敏感个人信息，应默认隐藏或脱敏显示。
- 敏感字段应受教师模式保护，并谨慎处理导出和备份。
- 是否允许保存完整身份证号，需要在正式设计时单独确认。

## 5. 第四组：后续独立模块需求

以下需求有实际价值，但不属于 v0.8.0 的问题修复范围。

### 5.1 学生作业管理

需求背景：

- 记录作业任务。
- 登记学生是否上交。
- 记录批改和订正状态。
- 主要由课代表操作登记，不要求上传作业内容。

建议后续作为独立模块设计，不并入学生表现量化或文档管理。

### 5.2 班主任日常台账

需求背景：

- 安全教育记录。
- 班级活动记录。
- 其他班主任过程性记录。

建议后续作为结构化台账模块设计。文档管理负责附件存储，台账模块负责日期、类型、内容、参与人员和查询统计，两者可以关联但不应混为同一模块。

## 6. v0.8.0 建议处理顺序

1. 修复座位表显示、滚动和自适应问题。
2. 修复文档上传、预览和下载反馈问题。
3. 完善考试科目配置入口和模板操作。
4. 调整值日表，使其支持按星期固定分组并突出当天值日生。
5. 设计并实现学生字段配置及 Excel 联动。
6. 对已经完成的问题执行回归测试。

学生字段配置会影响数据库、页面、导入导出和隐私边界，正式实施前需要单独完成设计确认。其他问题可以按模块逐项形成较小的修复方案。
