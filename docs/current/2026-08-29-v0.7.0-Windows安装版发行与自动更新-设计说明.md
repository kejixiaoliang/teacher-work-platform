# 教师工作台 v0.7.0 基线 Windows 安装版发行与自动更新设计说明

> 编写日期：2026-08-29  
> 文档类型：设计说明  
> 当前基线：教师工作台 v0.7.0 Windows x64 绿色便携版  
> 目标方向：增加 Windows 安装版，采用 Tauri 官方更新机制，并继续保留便携版作为辅助发行包  
> 文档状态：重要讨论结论归档，尚未实施  
> 目标版本：待单独立项确认；本文中的 v0.8.x 仅作流程示例，不对应此前废弃的小程序实验分支
> 文档分类：当前发行方案参考资料  

## 1. 文档结论

教师工作台未来推荐采用双发行方式：

```text
同一套教师工作台源码
├─ Windows 安装版 Setup.exe
│  ├─ 面向绝大多数普通用户
│  ├─ 安装到当前用户目录
│  ├─ 支持应用内检查、下载和安装更新
│  └─ 用户数据保存在独立的本机数据目录
│
└─ Windows 便携版 Portable.zip
   ├─ 面向 U 盘、临时电脑和无安装条件场景
   ├─ 解压后运行
   ├─ 用户数据保存在便携目录
   └─ 初期继续采用手动更新
```

两种版本不是两个产品，也不应维护两套业务代码。它们必须共用：

- Vue 页面；
- Express API；
- SQLite 表结构；
- 数据库迁移脚本；
- 导入、导出和完整备份格式；
- 业务规则和数据校验；
- 产品版本和发布说明；
- 绝大多数 Tauri 桌面代码。

两种发行包最主要的差异只有：

1. 程序如何进入用户电脑；
2. 程序文件保存在哪里；
3. 用户数据目录如何定位；
4. 如何完成程序更新和卸载。

## 2. 为什么考虑从“只提供便携版”调整为“双发行”

当前便携版的优势是：

- 解压即可运行；
- 不要求管理员权限；
- 可以复制到 U 盘或其他电脑；
- 程序和数据都在可见目录中；
- 适合学校电脑、临时电脑和离线场景。

但是，便携版要实现可靠自动更新，需要自行解决：

- 正在运行的 EXE 不能覆盖自身；
- 内置 Node 服务和资源文件可能被进程占用；
- 用户可能随意移动、重命名或复制目录；
- 程序目录可能只读；
- 必须自行建设稳定启动入口和独立更新器；
- 必须管理新旧版本目录和切换状态；
- 必须自行处理安装失败、启动失败和版本回滚；
- 程序目录和数据目录紧密相邻，更新器必须格外谨慎；
- 卸载、快捷方式和系统注册信息都没有标准入口。

普通安装版使用 Windows 安装器和 Tauri 官方 updater 后，程序替换、安装位置、快捷方式和卸载入口都能采用成熟机制。项目可以把主要工程精力放在：

- 数据库迁移；
- 数据备份；
- 未保存内容保护；
- 更新提示体验；
- 历史数据兼容；
- 发布和验收。

## 3. 最终用户看到的安装版体验

### 3.1 第一次安装

```text
用户下载“教师工作台-v0.8.0-Setup.exe”
  → 双击安装
  → 安装到当前 Windows 用户目录
  → 创建桌面和开始菜单快捷方式
  → 用户点击快捷方式
  → 教师工作台启动
  → 首次创建本机数据目录和 SQLite 数据库
```

推荐采用“每用户安装”，程序安装在当前用户目录，尽量不申请管理员权限。

建议程序目录：

```text
%LOCALAPPDATA%\Programs\TeacherWork\
```

建议用户数据目录：

```text
%LOCALAPPDATA%\TeacherWork\
├─ data\
│  ├─ teacher.db
│  └─ files\
├─ backup\
├─ logs\
└─ config\
```

程序目录和用户数据目录必须分开。安装新版、修复程序或卸载程序时，不应默认删除用户数据。

### 3.2 日常打开

用户以后不必寻找安装目录，只需：

```text
双击桌面“教师工作台”快捷方式
→ 打开当前已安装版本
```

### 3.3 发现新版本

```text
工作台正常启动
  → 首页加载完成
  → 后台异步检查 latest.json
  → 发现云端版本高于本机版本
  → 显示“发现新版本”提示
```

推荐提示：

```text
发现新版本 v0.8.1

本次更新：
· 优化完整备份恢复
· 改进成绩导入
· 修复若干已知问题

[查看详细说明] [下载更新] [暂不更新]
```

### 3.4 用户手动下载

工作台不应在用户不知情时下载大型安装包。推荐：

```text
用户点击“下载更新”
  → Tauri updater 开始下载
  → 页面显示下载进度
  → 下载完成后验证更新包签名
  → 显示“更新已准备完成”
```

### 3.5 用户确认安装

```text
v0.8.1 已下载并验证完成

更新前将自动创建本地数据恢复点。
安装时工作台会暂时关闭。

[退出并更新] [下次再说]
```

用户点击“退出并更新”后：

```text
检查未保存内容
  → 创建数据库和必要附件恢复点
  → 正常关闭内置 Node 服务
  → 调用 Tauri updater
  → 当前程序退出
  → NSIS 安装器替换程序文件
  → 启动新版工作台
  → 新版执行数据库迁移和健康检查
```

### 3.6 关闭生命周期门禁（v0.9.0 实际修复）

更新前的“正常关闭内置 Node 服务”不是一句 UI 提示，而是安装包能够替换文件的前置条件。v0.9.0 发现便携版关闭窗口后可能留下主程序和 `resources/runtime/node.exe`，导致文件句柄、SQLite 和端口继续占用；该现象在 v0.8.0 便携包中也能复现。

桌面层统一采用以下退出链路：窗口 `CloseRequested` 进入 `RunEvent::WindowEvent` 后调用 `window.destroy()` 绕过 WebView 的 `beforeunload` 阻塞，再调用 `app.exit(0)`；窗口 `Destroyed` 事件也会请求应用退出；在 Tauri 的 `ExitRequested`/`Exit` 生命周期中取出唯一的 `Child`，执行 `kill()` 后 `wait()`；不在窗口或运行事件回调中调用 `std::process::exit(0)`。清理必须幂等，因为一次窗口关闭可能经过多个退出事件。

因此，安装版自动更新和便携版手动升级都必须把“主程序退出、内置 Node 不残留”作为发布门禁。详细问题现象、根因和回归测试见：[v0.9.0 便携版关闭生命周期问题与修复记录](./2026-08-29-v0.9.0-便携版关闭生命周期问题与修复记录.md)。

## 4. 安装版和便携版是一套源码吗

是。推荐构建关系如下：

```text
package.json / Vue / Express / SQLite / Tauri
                  │
                  ├─ 构建 NSIS 安装包
                  │   └─ 教师工作台-v0.8.0-Setup.exe
                  │
                  └─ 构建绿色便携包
                      └─ 教师工作台-v0.8.0-Portable.zip
```

不得出现：

- 安装版单独维护一套 Vue 页面；
- 便携版单独维护一套数据库结构；
- 两种包使用不同备份格式；
- 同一个产品版本对应不同数据库版本；
- 同一个功能在两种发行方式中产生不同业务数据。

推荐仅在桌面启动层区分运行配置：

```text
安装版
→ 数据根目录来自 LOCALAPPDATA

便携版
→ 数据根目录来自 EXE 所在的便携目录
```

业务代码只接收一个已经解析和验证过的 `dataDir`，不应在各模块中自行判断安装版或便携版。

## 5. 两种版本的数据能否互相迁移

可以，而且必须把它作为正式兼容承诺。

推荐交换方式：

```text
安装版
  → 导出“完整备份 ZIP”
  → 便携版执行预检和导入

便携版
  → 导出“完整备份 ZIP”
  → 安装版执行预检和导入
```

完整备份应包含：

- 班级、学生、座位、成绩、考勤、请假等业务记录；
- 文档记录和 `data/files/` 附件；
- 产品版本；
- 数据库版本；
- 备份格式版本；
- 导出时间和唯一导出 ID；
- 文件清单、大小和 SHA-256；
- 数据完整性校验信息。

不建议让普通用户直接复制正在运行的 `teacher.db`，原因包括：

- SQLite 可能存在 WAL 内容；
- 附件不会自动跟随数据库；
- 新旧版本数据库结构可能不同；
- 用户可能复制错误文件或错误目录；
- 复制过程中应用仍可能写入。

正式交换流程应为：

```text
识别备份格式
→ 历史格式迁移
→ 完整性校验
→ 显示导入预览
→ 创建恢复前快照
→ 执行导入事务
→ 验证记录和附件
→ 输出导入报告
```

## 6. 数据兼容方向

两种发行方式必须执行同一兼容规则：

- 同版本安装版与便携版必须完全互通；
- 新版本必须能够导入已承诺支持的旧版本数据；
- 新版本可以输出最新备份格式；
- 旧版本不一定能导入新版本新增的格式；
- 旧版本遇到不认识的新版格式时必须安全拒绝并解释；
- 不允许强行导入并静默丢弃字段；
- 稳定 UUID、状态枚举和业务语义必须跨发行方式保持一致。

建议优先保持两端产品版本一致：

```text
安装版 v0.8.1 ↔ 便携版 v0.8.1
```

如果版本不一致，应先读取备份中的格式版本并走正式迁移器。

## 7. 哪些内容不应随业务备份迁移

以下内容属于本机运行状态，通常不进入完整业务备份：

- 安装目录；
- 窗口大小和位置；
- 最近打开路径；
- 下载中的更新包；
- 自动更新检查时间；
- 本机临时缓存；
- 本地诊断日志；
- 一次性文件访问令牌；
- 与当前设备强绑定的安全凭据。

可迁移的是教师业务数据；不可迁移的是某台电脑的临时运行状态。

## 8. 卸载策略

安装版卸载不能默认删除教师数据。

推荐默认行为：

```text
卸载教师工作台程序
→ 删除程序文件、快捷方式和卸载项
→ 保留 %LOCALAPPDATA%\TeacherWork\ 中的数据和备份
```

如果需要提供彻底删除，应明确二次确认：

```text
是否同时永久删除本机教师工作台数据？

这将删除班级、学生、成绩、附件和本地备份，且无法恢复。

[保留数据并卸载] [同时删除全部数据]
```

默认选项必须是“保留数据并卸载”。

重新安装时，如果发现已有数据目录，应继续使用原数据，并先完成数据库版本检查。

## 9. 安装版是否导致日常开发必须反复安装卸载

不会。安装版是交付给最终用户的发行方式，不是日常开发运行方式。

### 9.1 日常页面和接口开发

```text
修改源码
→ npm test
→ npm run dev
```

不需要安装。

### 9.2 日常桌面联调

```text
修改源码
→ npm run tauri:dev
→ 直接测试 Tauri 窗口、本地服务和文件能力
```

不需要安装。

### 9.3 接近正式环境的 EXE 测试

```text
npm run build
→ npm run tauri:build
→ 直接运行构建产物
```

仍然不需要安装。

### 9.4 只有发布候选版本需要安装测试

以下情况才进行完整安装、升级和卸载验收：

- 正式发布前；
- 安装目录或快捷方式变化；
- 数据目录策略变化；
- 自动更新机制变化；
- 卸载策略变化；
- 代码签名方式变化；
- 发布脚本或 NSIS 配置变化。

正确开发节奏是：

```text
日常开发直接运行
→ 自动化测试
→ Tauri 开发模式验收
→ 生成发布候选版本
→ 最后测试安装、更新和卸载
```

不是：

```text
每改一行代码
→ 安装
→ 测试
→ 卸载
```

## 10. 开发版、测试版和正式版数据隔离

开发测试不得使用正式数据目录。

推荐：

```text
正式安装版
→ %LOCALAPPDATA%\TeacherWork\data\

开发版
→ %LOCALAPPDATA%\TeacherWork-Dev\data\

自动更新验收版
→ %LOCALAPPDATA%\TeacherWork-UpdateTest\data\

便携测试版
→ 测试便携目录\data\
```

产品显示名称也可以区分：

```text
正式版：教师工作台
开发版：教师工作台 Dev
测试版：教师工作台 Update Test
```

不同构建不得争用同一数据库、端口、日志目录或更新状态文件。

## 11. Tauri 官方 updater 在安装版中的职责

当前项目使用 Tauri v2。安装版推荐采用 NSIS，并接入 Tauri 官方 updater。

Tauri updater 负责：

- 读取更新端点；
- 比较语义化版本；
- 下载 Windows 更新安装包；
- 使用内置公钥验证更新签名；
- 调用 Windows 安装机制替换程序文件；
- 支持被应用控制的检查、下载和安装时机。

项目自身仍需负责：

- 更新提示 UI；
- 未保存内容检查；
- 本地 Node 服务的正常关闭；
- 数据库和附件升级前快照；
- 数据库迁移；
- 新版业务健康检查；
- 数据迁移失败时恢复；
- 更新日志和用户提示。

安装器能处理程序文件替换，但不能自动理解教师工作台业务数据。

推荐配置方向：

```json
{
  "bundle": {
    "active": true,
    "targets": ["nsis"],
    "createUpdaterArtifacts": true
  },
  "plugins": {
    "updater": {
      "pubkey": "内置的更新验签公钥",
      "endpoints": [
        "https://updates.example.com/stable/latest.json"
      ],
      "windows": {
        "installMode": "passive"
      }
    }
  }
}
```

### 11.1 v0.9.0 已落地的原生链路

v0.9.0 已完成 updater 的桌面层最小接入，但还没有把它误认为完整发布能力：

- `web/src/desktop/updater.js` 暴露 `checkForUpdate` 和 `installUpdate`，浏览器返回 `unsupported(browser)`，便携版返回 `unsupported(portable)`，只有安装版调用 Tauri updater；
- 下载进度统一转换为 `started`、`progress`、`finished`，网络、签名和安装异常只返回用户可理解的错误状态，不把原生异常堆栈显示到页面；
- Rust 端仅在 `installed` feature 下注册 `tauri-plugin-updater` 和 `tauri-plugin-process`，更新安装完成后请求重新启动；
- 安装版配置保留公钥和 endpoint 的占位契约，`scripts/build-tauri.mjs` 构建时必须通过 `TAURI_UPDATER_PUBLIC_KEY` 与 `TEACHER_WORK_UPDATE_ENDPOINT` 注入真实值。生产私钥通过 `TAURI_SIGNING_PRIVATE_KEY` 传给构建环境，不写入 Git；
- 当前阶段已验证测试密钥下的 x64 NSIS 安装包与 `.exe.sig` 生成。真实 endpoint、生产签名密钥、更新清单、更新前备份和安装升级实机验收仍属于后续阶段。

以上只是设计示例，正式实施时必须依据当前 Tauri v2 配置 schema 和实际插件版本验证。

## 12. 自动更新需要哪些云资源

最小自动更新系统只需要公开静态资源：

```text
latest.json                  最新版本清单
安装更新包                    NSIS Setup.exe
安装更新包签名                Tauri .sig 内容
更新说明                      HTML 或 Markdown 页面，可选
```

不需要：

- CloudBase 数据库；
- CloudBase 云函数；
- 教师账号登录；
- 小程序身份体系；
- 把学生和班级数据传到云端；
- 动态更新 API 服务。

自动更新云端和教师业务数据云端化是两件独立的事。

## 13. 自有域名、CloudBase、COS和服务器如何分工

推荐原则：

> 客户端永远请求自己的域名；底层托管服务可以更换。

推荐结构：

```text
用户客户端
    │
    ├─ 检查版本
    │   └─ https://updates.example.com/stable/latest.json
    │       └─ CloudBase 静态托管
    │
    └─ 下载新版
        └─ https://downloads.example.com/teacher-work/0.8.1/setup.exe
            └─ 腾讯云 COS + CDN

GitHub Release
    └─ 正式版本历史存档和备用下载地址

自有服务器
    └─ 备用下载源、发布管理或更新说明后台
```

### 13.1 自有域名

自有域名是客户端长期稳定入口：

```text
updates.example.com
downloads.example.com
```

如果未来从 CloudBase 迁移到其他服务，只需要调整 DNS 或 CDN，不必先修改所有已安装客户端。

不推荐把 CloudBase 默认域名永久硬编码为唯一更新地址，因为一旦更换平台，旧客户端可能无法获取新地址。

### 13.2 CloudBase 静态托管

适合：

- `latest.json`；
- 更新签名；
- 更新说明；
- 小型公开静态资源；
- 测试阶段的安装包。

优势：

- 自带 HTTPS；
- CDN 加速；
- 支持自定义域名；
- 不需要维护服务器；
- 支持控制台、CLI和 CI/CD 部署。

生产环境应使用自定义域名。`latest.json` 应设置不缓存或很短缓存。

### 13.3 COS + CDN

更适合长期承载大型安装包：

- 安装包体积可能超过 50 MB；
- 支持大对象存储；
- 适合 Range 请求和断点续传；
- CDN 可以分担源站带宽；
- 版本化文件可以长期缓存。

### 13.4 自有服务器

可以承担：

- 备用下载；
- 更新管理后台；
- 发布审核；
- 更新说明页面；
- 在资源规模很小时直接托管静态文件。

不建议在用户量增长后长期让业务服务器直接承担所有安装包流量。大文件下载可能挤占出口带宽并影响其他服务。

### 13.5 GitHub Release

适合：

- 保存正式发布历史；
- 关联 Git 标签和提交；
- 保存完整安装包和便携包；
- 提供公开备用下载地址；
- 供开发者核对发布来源。

国内用户主要下载可走自有域名和腾讯云 CDN，GitHub 保持正式归档和备用能力。

## 14. 云端文件结构

推荐：

```text
desktop-updates/
├─ stable/
│  └─ latest.json
├─ beta/
│  └─ latest.json
├─ releases/
│  ├─ 0.8.0/
│  │  ├─ teacher-work_0.8.0_windows_x64-setup.exe
│  │  └─ teacher-work_0.8.0_windows_x64-setup.exe.sig
│  └─ 0.8.1/
│     ├─ teacher-work_0.8.1_windows_x64-setup.exe
│     └─ teacher-work_0.8.1_windows_x64-setup.exe.sig
└─ notes/
   ├─ 0.8.0.html
   └─ 0.8.1.html
```

文件名建议只使用英文、数字、点、下划线和连字符，减少 URL 编码、CDN和上传工具兼容问题。

## 15. latest.json

Tauri 静态更新清单示例：

```json
{
  "version": "0.8.1",
  "notes": "优化完整备份和成绩导入，修复若干问题。",
  "pub_date": "2026-09-10T12:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "构建生成的签名文件内容",
      "url": "https://downloads.example.com/teacher-work/releases/0.8.1/teacher-work_0.8.1_windows_x64-setup.exe"
    }
  }
}
```

要求：

- `version` 必须是合法 SemVer；
- `windows-x86_64` 与实际构建目标一致；
- `signature` 必须是签名内容，不是签名文件 URL；
- `url` 必须是 HTTPS；
- 正式发布后版本目录不得原地覆盖；
- `latest.json` 必须最后发布。

## 16. 缓存策略

推荐：

```text
/stable/latest.json
→ 不缓存或缓存 1～5 分钟

/beta/latest.json
→ 不缓存或缓存 1～5 分钟

/releases/0.8.1/*
→ 文件名带版本号，允许长期缓存

/notes/*
→ 短期缓存
```

安装包路径必须不可变。发布 v0.8.1 后，不应把同一路径悄悄替换成另一个构建结果；如果必须修复，应发布 v0.8.2。

## 17. 更新签名和 Windows 代码签名

自动更新至少涉及两类签名。

### 17.1 Tauri 更新包签名

作用：防止客户端安装被篡改的更新包。

```text
签名私钥
→ 只保存在安全发布电脑或 CI Secrets

验签公钥
→ 编译进客户端

签名结果
→ 放入 latest.json
```

私钥不得：

- 提交到 Git；
- 上传到 CloudBase、COS或普通服务器目录；
- 打包进 EXE；
- 写入客户端配置；
- 出现在构建日志中。

### 17.2 Windows Authenticode 代码签名

作用：

- 证明 EXE 和安装包的发布者身份；
- 减少 SmartScreen 的未知发布者警告；
- 帮助用户核对程序来源。

Tauri 更新签名和 Windows 代码签名解决的问题不同，正式版本建议两者都做。

## 18. 自动更新与数据安全

云端更新系统只保存公开程序文件，不保存教师业务数据。

即使：

- 用户完全断网；
- CloudBase 暂时不可用；
- COS 下载失败；
- 自有服务器维护；
- GitHub 无法访问；

工作台也必须能够继续离线打开并使用本地数据。网络故障只能导致“暂时无法检查或下载更新”，不能影响 SQLite 本地业务。

更新前必须检查：

- 是否存在未保存表单；
- 本地服务是否能够正常关闭；
- 数据库是否可以创建快照；
- 磁盘空间是否足够；
- 用户数据目录是否可写；
- 更新包签名是否正确。

只有全部通过后才能调用安装步骤。

## 19. 数据库升级和程序回滚

安装器能够替换程序文件，但数据库升级仍需项目负责。

例如：

```text
应用 v0.8.0 → SQLite user_version 7
应用 v0.8.1 → SQLite user_version 8
```

升级前创建：

```text
%LOCALAPPDATA%\TeacherWork\backup\pre-update-v0.8.0-to-v0.8.1\
├─ teacher.db
├─ files\                  本次迁移涉及附件时包含
└─ backup.json
```

数据库迁移流程：

```text
读取当前数据库版本
→ 检查迁移路径
→ 创建恢复点
→ 开启事务
→ 按版本顺序执行迁移
→ 验证表、字段、索引和关键数据
→ 更新 user_version
→ 提交事务
→ 启动新版业务
```

迁移失败：

```text
回滚事务
→ 保留原数据库或恢复快照
→ 阻止新版进入业务页面
→ 给出明确恢复说明
```

只回退程序但不回退不兼容数据库，可能导致旧程序无法打开。因此数据库发生破坏性升级时，必须记录程序和数据库的联合恢复点。

## 20. 安装版与便携版并行发布

推荐 Release 资产：

```text
教师工作台 v0.8.1
├─ teacher-work_0.8.1_windows_x64-setup.exe
├─ teacher-work_0.8.1_windows_x64-setup.exe.sig
├─ teacher-work_0.8.1_windows_x64-portable.zip
├─ checksums-sha256.txt
└─ 发布说明
```

README 明确推荐顺序：

```text
普通用户
→ 推荐下载 Setup.exe

U 盘、临时电脑或不能安装
→ 下载 Portable.zip
```

便携版可以暂时继续手动升级，不要求第一阶段同时实现两种自动更新机制。

## 21. 从旧便携版迁移到安装版

推荐两种方式。

### 21.1 完整备份迁移，优先推荐

```text
旧便携版导出完整 ZIP
→ 安装新版 Setup.exe
→ 新安装版选择“从完整备份恢复”
→ 预检
→ 创建空数据目录恢复点
→ 导入
→ 验证班级、学生、附件和业务记录
```

优点：路径清楚、校验完整、可以生成导入报告。

### 21.2 选择旧便携目录迁移

未来可以提供：

```text
[从旧便携版迁移]
→ 用户主动选择旧“教师工作台”目录
→ 程序识别 data/、backup/ 和版本信息
→ 只读预检
→ 显示迁移范围
→ 用户确认
→ 复制到安装版数据目录
→ 校验文件哈希和数据库完整性
```

程序不得自动扫描整台电脑寻找疑似数据目录，也不得未经用户确认移动或删除旧便携数据。

迁移成功后，旧便携目录仍应保留，直到用户自行确认并删除。

## 22. 发布流水线

正式安装版发布顺序：

```text
1. 确定产品版本、数据库版本和备份格式版本
2. 同步 package.json、tauri.conf.json、Cargo.toml 和更新记录
3. npm test
4. npm run build
5. 构建 Tauri NSIS 安装包和 updater artifacts
6. 构建便携版
7. 执行安装版和便携版 QA
8. 执行旧数据库升级和恢复测试
9. 执行安装版与便携版备份互导测试
10. 对 EXE 和安装包执行 Windows 代码签名
11. 生成 Tauri 更新签名
12. 计算并记录 SHA-256
13. 上传 GitHub Release
14. 上传 COS/CDN 版本目录
15. 从公网地址重新下载并复验
16. 最后发布 latest.json
```

必须最后发布 `latest.json`，避免用户先发现新版本但安装包尚未上传完成。

## 23. 当前项目实施前置问题

### 23.1 版本契约必须统一

当前工作树需要继续核对：

```text
package.json                 0.7.0
src-tauri/tauri.conf.json    0.7.0
src-tauri/Cargo.toml         当前工作树显示 0.6.0
```

桌面应用暴露的版本来自 Rust `CARGO_PKG_VERSION`。自动更新前必须保证：

- 包版本；
- Tauri 配置版本；
- Cargo 版本；
- 更新记录；
- 安装包文件名；
- `latest.json`；

全部一致。版本检查失败必须阻止构建和发布。

### 23.2 数据目录服务需要抽象

当前便携版通过 EXE 所在目录定位数据。安装版需要切换到 `LOCALAPPDATA`。

推荐统一：

```text
resolveRuntimeProfile()
→ installed / portable / dev / update-test

resolveDataRoot(profile)
→ 返回唯一、已验证的数据根目录
```

服务器路由、备份模块和附件模块不得自行拼接安装目录。

### 23.3 当前构建方式需要扩展

当前 `tauri.conf.json` 中 `bundle.active` 为 `false`，并采用 `tauri build --no-bundle` 生成便携 EXE。安装版实施时需要新增正式 NSIS 构建配置，而不是破坏现有便携构建链。

可以采用独立配置：

```text
tauri.conf.json                 公共配置
tauri.installer.conf.json       安装版配置
tauri.portable.conf.json        便携版配置
```

具体合并方式应以当前 Tauri CLI 支持为准，并加入配置一致性测试。

## 25. 安装版测试矩阵

### 25.1 安装

- 全新安装成功；
- 不需要管理员权限；
- 中文 Windows 用户名；
- 安装路径包含空格；
- 桌面快捷方式正常；
- 开始菜单入口正常；
- WebView2 缺失时提示正确；
- 首次启动创建正确数据目录。

### 25.2 更新

- 无更新时不打扰用户；
- 有更新时提示版本和说明；
- 用户可以暂不更新；
- 下载进度和取消正常；
- 断网后当前版本继续使用；
- 更新包损坏时拒绝安装；
- 签名错误时拒绝安装；
- 未保存内容时阻止安装；
- Node 服务正常关闭；
- 更新完成后版本号正确；
- 数据库和附件完整。

### 25.3 数据和迁移

- 全新数据库；
- 每个已承诺历史版本数据库；
- 大量班级、学生和附件；
- 安装版导出、便携版导入；
- 便携版导出、安装版导入；
- 迁移失败时恢复；
- 新版备份被旧版安全拒绝或正确迁移；
- 重复导入不会静默制造重复数据。

### 25.4 卸载和重装

- 默认卸载保留数据；
- 重装后识别原数据；
- 用户明确选择后才删除数据；
- 删除数据前二次确认；
- 卸载程序不误删其他目录；
- 正式版卸载不删除开发测试数据，反之亦然。

### 25.5 云端分发

- CloudBase `latest.json` 可访问；
- 自有域名 HTTPS 正常；
- COS/CDN 安装包可下载；
- Range 请求正常；
- 缓存不会长期返回旧版本清单；
- GitHub 备用资产存在；
- 发布顺序错误时流水线阻止开放版本；
- 下载文件与本地发布产物哈希一致。

## 26. 非目标

第一阶段不要求：

- 强制静默更新；
- 在用户录入数据时自动关闭程序；
- 增量二进制补丁；
- 自动更新便携版；
- 建设复杂动态更新服务器；
- 使用 CloudBase 数据库记录每个用户更新状态；
- 把教师业务数据上传到更新服务；
- 自动删除用户本地备份；
- 发布未经签名的正式自动更新。

## 27. 风险和约束

### 高风险

- 更新调用前未关闭数据库写入；
- 数据库升级后旧程序无法回退；
- 更新签名私钥泄露；
- 安装器误删 `LOCALAPPDATA` 数据目录；
- 安装版和便携版使用不同数据模型；
- `latest.json` 先于安装包发布；
- 开发版误用正式数据目录；
- 版本号不一致导致客户端错误判断更新。

### 中风险

- CDN 缓存旧版本清单；
- 自有服务器下载占满带宽；
- Windows 杀毒软件暂时占用文件；
- SmartScreen 阻止未知发布者程序；
- 用户在安装过程中关机；
- 安装包和便携包构建来源不一致。

### 低风险

- 更新说明暂时无法打开；
- 检查更新超时；
- GitHub 备用下载不可达；
- 用户长期选择暂不更新。

## 28. 最终产品策略

推荐正式说明：

```text
教师工作台 Windows 安装版
→ 推荐日常使用
→ 支持自动检测、手动下载、确认后自动安装
→ 默认保留本机数据

教师工作台 Windows 便携版
→ 适合 U 盘、临时电脑和不能安装的环境
→ 与安装版使用同一数据格式
→ 可以通过完整备份双向迁移
→ 初期继续手动升级
```

最重要的原则是：

> 安装版和便携版只是同一产品的两种交付形式。程序可以采用不同安装和更新方式，但教师的业务数据、备份格式、迁移规则和兼容承诺必须始终保持统一。
