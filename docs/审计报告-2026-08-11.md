# 教师工作台全面审计报告

审计日期：2026-08-11  
审计基线：`master` / `c6be128` / v0.2.0  
审计范围：Web 前端、Express/SQLite 后端、Tauri 运行时、构建发布脚本、依赖与现有测试。

## 1. 结论摘要

当前项目可以完成构建，现有自动化测试全部通过（24/24），但“测试通过”不等于“全面可靠”。下一轮应优先处理数据安全边界、输入校验一致性和高频教学流程，再扩展新功能。

审计命令结果：

- `npm test`：通过，24 个测试全部通过；版本契约检查通过。
- `npm run build`：通过。
- `npm audit --omit=dev --audit-level=moderate`：失败，报告 11 个依赖漏洞，其中 9 个 high、2 个 moderate；当前审计输出对 `nanoid/postcss` 与 `uuid/exceljs` 标记为暂无直接修复版本。
- Git 基线干净；已创建独立 worktree 分支 `codex/comprehensive-improvement`。

## 2. 问题清单

### P0：必须在继续扩展前处理

| 编号 | 类别 | 位置/证据 | 问题与影响 | 处理方向 |
| --- | --- | --- | --- | --- |
| P0-1 | 备份恢复安全 | `server/routes/backup.js` 的 `/import` | 恢复接口会清空业务表并按输入恢复；当前只检查表名是否齐全，未对版本、表结构、行数据类型、主键/外键关系和总记录规模做完整校验。损坏或恶意备份可能导致恢复失败、数据被清空或内存/磁盘压力。 | 增加严格 schema 校验、大小/行数配额、预校验报告、事务回滚和恢复后完整性检查；保留可验证的恢复前快照。 |
| P0-2 | 上传安全 | `server/routes/documents.js` 的 multer 配置 | 文件类型主要依据原始文件扩展名白名单，允许压缩包、音视频等大文件，未做内容签名校验、总容量/数量配额和异常清理策略。恶意内容可伪装扩展名，长期上传会耗尽磁盘。 | 按类型做 magic number 校验；限制单文件、单类、总目录容量；生成安全文件名；失败/超时可回收；下载统一 `nosniff` 与附件策略。 |
| P0-3 | 本地 API 暴露 | `server/app.js`、`web/src/platform/runtimeConfig.js` | 桌面模式使用 query token 生成文件 URL（`?__token=...`），token 可能进入历史、日志或 Referer；同时 JSON body 上限 50MB、上传上限 200MB，但没有统一资源配额/并发限制。 | 文件访问改为一次性授权或受控 header；缩小 token 暴露面；统一 body/upload 配额、超时和并发限制；增加安全回归测试。 |

### P1：高优先级缺陷与功能问题

| 编号 | 类别 | 位置/证据 | 问题与影响 | 处理方向 |
| --- | --- | --- | --- | --- |
| P1-1 | 输入校验 | 多个 `server/routes/*.js` | `class_id`、学生/考试/文档 ID、日期、月份和数值字段的校验规则不统一；部分非法输入返回 HTTP 200 的 `{ok:false}`，部分返回 400。`Number()` 对 `NaN`、小数、负数的处理也不一致。 | 建立统一 `validation` 模块；所有资源 ID、外键、日期、数值使用同一规则；错误统一 HTTP 4xx + 可读错误码。 |
| P1-2 | 数据一致性 | `server/routes/students.js`、`attendance.js`、`leaves.js`、`scores.js` | 多个批量操作只在请求层过滤无效 ID，结果可能是“部分写入但客户端只收到成功/失败概述”；部分更新未明确校验学生仍属于目标班级、是否已删除。 | 明确 all-or-nothing 或逐行结果契约；写入前做外键/在册状态校验；增加批量冲突报告与回滚测试。 |
| P1-3 | 考勤/请假联动 | `server/routes/attendance.js` 与 `web/src/views/Attendance.vue`、`Leaves.vue` | 已批准请假会影响考勤展示，但系统联动记录、人工覆盖和请假变更后的回滚语义仍依赖备注字符串；容易覆盖教师手工登记，且缺少“待确认请假”明确提示。 | 改为结构化来源字段与优先级；区分系统建议和人工确认；请假变更可追溯、可撤销。 |
| P1-4 | 成绩功能 | `web/src/views/Scores.vue`、`server/routes/scores.js` | 科目配置散落在考试表单，缺少可复用科目模板、导入预览、重复表头/未知学生/非法分数的完整错误汇总；切换考试/班级时矩阵重建仍需加强回归覆盖。 | 增加科目模板、导入预检与事务提交；明确科目修改对既有成绩的影响；补齐切换和空数据测试。 |
| P1-5 | 删除与文件生命周期 | `classes.js`、`documents.js`、学生/记录相关路由 | 软删除、彻底删除、物理文件删除和备份之间缺少统一操作日志；批量删除前端使用 `Promise.all`，部分成功时反馈与刷新容易不完整。 | 后端提供原子批量接口和结果明细；删除前自动快照；建立审计日志与孤儿文件扫描。 |
| P1-6 | 日期与时区 | `Attendance.vue`、`Leaves.vue`、`Overview.vue` 等 | 当前多处直接使用 `new Date()`/ISO 字符串；本地日期与 UTC 边界可能导致“今天/月初/月末”偏移。 | 统一本地日期工具；API 明确使用 `YYYY-MM-DD`/`YYYY-MM`；为东八区午夜边界补测试。 |

### P2：质量、可维护性与扩展能力

| 编号 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P2-1 | 依赖漏洞未闭环 | 安全告警会持续进入发布门禁；当前没有修复版本时仍需记录豁免边界。 | 建立依赖升级矩阵、锁文件定期审计和发布前风险豁免记录；优先评估替代包/升级主版本。 |
| P2-2 | 前端加载状态与并发请求 | 部分页面虽已使用 `Promise.allSettled`，但需要统一序列号/取消请求策略，防止快速切班时旧响应覆盖新状态。 | 封装 `useSeqLoad`/AbortController；为每个高频页面增加竞态测试。 |
| P2-3 | 缺少端到端发布验证 | 自动化测试未覆盖真实浏览器交互、上传下载、打印、Excel、Tauri 便携包启动和迁移失败恢复。 | 增加 API 集成矩阵、浏览器 smoke、便携包 QA 和迁移故障注入。 |
| P2-4 | 新功能入口不足 | 首页仍偏信息概览，缺少待办、日历、提醒、操作历史等工作台能力。 | 按实施计划分阶段增加统一时间线、首页待办、报表/通知和数据安全中心。 |

## 3. 现有功能缺口

1. 学生详情的成长、健康、成绩、考勤、请假、家校沟通尚未形成可追溯的统一时间线。
2. 成绩缺少可复用科目模板、导入预览和可解释的冲突处理。
3. 考勤缺少“请假待确认/系统建议/教师覆盖”的清晰工作流。
4. 首页缺少今日待办、即将到期事项、请假提醒和近期考试聚合。
5. 缺少面向删除、恢复、导入、备份恢复的操作日志与恢复中心。
6. 缺少自定义字段、标签、通知模板和班级日历等通用能力。

## 4. 审计边界

本报告未把依赖审计告警直接判定为可利用漏洞；是否可利用取决于实际运行路径和依赖版本。下一阶段必须用升级后的 lockfile、最小复现和回归测试逐项关闭或登记豁免。报告也未执行真实 Windows WebView2、文件系统权限、打印机和发布 ZIP 的人工验收，这些属于发布前专项验证。
