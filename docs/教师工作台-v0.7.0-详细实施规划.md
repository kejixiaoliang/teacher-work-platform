# 教师工作台 v0.7.0 详细实施规划

> 文档性质：版本实施规划与验收基线  
> 目标版本：v0.7.0  
> 当前基线：v0.6.0，提交 `32925fb`  
> 当前工作分支：`codex/v0.7.0-from-v0.6`  
> 文档状态：待确认后执行

## 1. 版本目标

v0.7.0 的核心目标不是继续增加零散页面功能，而是把教师工作台的数据能力做成可靠、可迁移、可恢复、可演进的基础设施。

本版本完成后，教师应能够：

- 将整个工作台导出为 JSON 文件；
- 将整个工作台连同附件导出为完整 ZIP；
- 从 JSON 或 ZIP 恢复工作台；
- 把旧版本导出的数据导入新版本；
- 在不清空现有数据的情况下执行更新导入；
- 在导入前查看数据数量、附件状态和冲突信息；
- 在恢复失败后回到恢复前状态；
- 在启用密码保护后，仍然保持教师工作台和班级公开两种模式；
- 通过使用指南准确理解备份、恢复、更新导入和两种访问模式。

本版本暂不实现完整的 CloudBase 在线同步和小程序，但数据格式、业务模型和迁移层必须为后续 CloudBase、小程序以及 AI 辅助迁移预留边界。

## 2. 当前基线与问题

### 2.1 当前基线

本版本必须从 v0.6.0 的正确合并基线开始，不能从旧的 v0.7.0 临时分支继续叠加。

v0.6.0 已包含：

- 教师密码设置和校验；
- 教师工作台模式；
- 班级公开模式；
- 模块级访问策略；
- 自动锁定和恢复密钥机制；
- `app_settings` 配置表；
- 数据库版本 6；
- Tauri Windows 便携版运行基础。

### 2.2 现有数据功能问题

当前版本已有 ZIP 备份雏形，但仍存在以下问题：

1. 现有导出格式主要是数据库表快照，不是稳定的业务交换格式；
2. 没有正式实现 JSON-only 导出；
3. 旧版数据导入依赖当前数据库表和字段，缺少版本迁移器；
4. 数据关系主要依赖本地自增数字 ID；
5. 班级备份和完整备份的恢复语义不够清晰；
6. 当前恢复更接近“整体覆盖”，没有真正的更新导入；
7. 导出过程没有明确的数据一致性快照机制；
8. 数据库事务和附件文件系统之间没有完整的原子替换流程；
9. 新增业务模块容易被备份表清单遗漏；
10. 密码配置、安全设置和可迁移业务设置没有完全分离；
11. 使用指南尚未完整解释两种访问模式和不同数据操作的风险。

### 3.1 必须完成

- 附件清单、大小和 SHA256 校验；
- 导入前预览；
- 数据库和附件的失败回滚；
- 备份覆盖审计；
- 使用指南更新；
- 访问模式权限校验；
- 完整测试和便携版验证。

### 3.2 本版本暂不完成

- CloudBase 在线同步；
- 多设备实时合并；

这些能力只做接口和数据格式预留，不进入 v0.7.0 的交付验收范围。

## 4. 总体架构

本版本采用四层结构：

```text
页面层
  ↓
备份/导入业务服务层
  ↓
统一业务交换模型
  ↓
SQLite 数据库 + 本地附件目录
```

页面不能直接读取数据库表，也不能自行拼装备份 JSON。所有导出、恢复和更新导入必须经过服务端统一入口。

未来 CloudBase 接入时，扩展为：

```text
本地版 ─┐
        ├─> 统一业务 API ─> CloudBase 数据库/云存储
小程序 ─┘                 └> 云函数与审计服务
```

因此 v0.7.0 的统一业务模型必须独立于 SQLite 表名、Vue 页面名称和当前菜单位置。

## 5. 数据模型设计

### 5.1 核心业务对象

统一交换模型至少包含以下对象：

- `workspaces`：工作空间或教师数据集；
- `classes`：班级；
- `students`：学生；
- `studentHistory`：学生体征和成长历史；
- `exams`：考试；
- `scores`：成绩；
- `attendance`：考勤；
- `leaves`：请假；
- `assessment`：表现量化规则、项目、记录和修订；
- `seats`：座位和座位布局；
- `duties`：值日、班委和课代表；
- `contacts`：家校沟通；
- `followUpTasks`：学生跟进事项；
- `documents`：文档元数据；
- `settings`：非敏感业务设置。

即使某一集合为空，也必须输出空数组，不能因无数据而省略字段。

### 5.2 稳定身份策略

本版本分阶段处理 UUID，不要求一次性重写所有数据库表。

第一阶段优先为以下核心实体建立稳定 UUID：

- 班级；
- 学生；
- 考试；
- 文档；
- 跟进事项；
- 家校沟通；
- 成绩记录。

当前数据库数字 ID可以继续保留，用于本地外键和兼容。交换层使用：

```text
旧数字 ID → 交换 UUID → 当前数据库数字 ID
```

旧版数据没有 UUID 时，导入器生成 UUID，并在本次导入中建立映射。后续再次导出时保持该 UUID。

考勤、量化等明细记录可先通过父对象 UUID、日期和本地记录 ID建立稳定关系，待后续版本再逐步固化 UUID 字段。

### 5.3 设置分层

`app_settings` 必须划分为：

| 设置类型 | 示例 | 处理方式 |
|---|---|---|
| 业务设置 | 默认学期、显示偏好、非敏感界面设置 | 可导出、可恢复 |
| 安全设置 | 密码摘要、盐、恢复密钥摘要、Token、会话 | 永不导出、不恢复 |

恢复备份后，当前设备的密码、访问模式、访问策略和恢复密钥必须继续有效。

## 6. 文件格式

### 6.1 JSON-only 文件

文件扩展名：`.teacher-work.json`。

顶层结构建议为：

```json
{
  "format": "teacher-work-backup",
  "formatVersion": 1,
  "appVersion": "0.7.0",
  "databaseVersion": 6,
  "exportId": "uuid",
  "exportedAt": "2026-08-25T12:00:00.000Z",
  "source": {
    "platform": "desktop",
    "product": "teacher-work",
    "timezone": "Asia/Shanghai"
  },
  "content": {
    "classes": [],
    "students": [],
    "attendance": [],
    "assessment": [],
    "scores": [],
    "leaves": [],
    "contacts": [],
    "followUpTasks": [],
    "documents": [],
    "settings": {}
  },
  "attachments": {
    "included": false,
    "omittedCount": 0
  },
  "integrity": {
    "algorithm": "sha256",
    "scope": "canonical-json-without-integrity-value",
    "value": ""
  }
}
```

JSON-only 导出不包含附件内容，但必须保留附件原始名称、关联对象和省略状态。

### 6.2 完整 ZIP

结构：

```text
教师工作台完整备份.zip
├── backup.json
├── manifest.json
└── files/
    ├── file-a
    └── file-b
```

要求：

- `backup.json` 使用统一交换模型；
- `manifest.json` 保存附件相对路径、大小、MIME 和 SHA256；
- 不保存本地绝对路径；
- 不保存密码、Token、恢复密钥；
- 所有文档附件都必须在 manifest 中有对应条目；
- 所有 manifest 文件都必须能在 ZIP 中找到。

### 6.3 完整性校验

JSON 校验采用规范化序列化：

- 对象键递归排序；
- 数组保持业务顺序；
- UTF-8 编码；
- 不输出额外空格和换行；
- 禁止 `NaN`、`Infinity` 和未定义值；
- SHA256 小写十六进制。

ZIP 导入还必须校验：

- 路径穿越；
- 绝对路径；
- 重复文件；
- 文件数量上限；
- 单文件大小上限；
- 总解压大小上限；
- 附件大小和哈希。

## 7. 导出实施方案

### 7.1 导出前置条件

- 只有教师模式允许全量导出；
- 班级公开模式不能导出成绩、学生隐私或完整备份；
- 导出前显示敏感数据提示；
- 导出开始时生成 `exportId` 和 `snapshotId`。

### 7.2 一致性快照

导出必须尽可能代表同一个时间点的数据：

1. 记录导出开始时间；
2. 获取数据库一致性读取快照；
3. 在同一快照中导出业务数据和文档元数据；
4. 生成附件 manifest；
5. 校验导出期间文件是否被修改；
6. 若文件修改，重新读取或明确导出失败；
7. 生成最终统计和完整性值。

导出期间应阻止恢复和更新导入，避免同时改写数据库和附件目录。

### 7.3 完整性审计

导出完成前自动检查：

- 所有业务集合是否存在；
- 所有核心对象 UUID 是否唯一；
- 所有父子关系是否有效；
- 所有文档是否能找到附件或明确标记缺失；
- 导出表注册清单是否与数据库业务表一致；
- 导出统计是否与实际记录数一致。

审计失败时不得返回“导出成功”。

## 8. 导入、恢复和更新

### 8.1 导入格式识别

导入器按以下顺序识别：

1. `.teacher-work.json` 规范 JSON；
2. v0.7 完整 ZIP；
3. v0.5/v0.6 旧版 ZIP；
4. 旧版 `app/version/tables` JSON；
5. 不支持格式明确拒绝。

禁止根据文件内容进行无规则猜测。

### 8.2 统一导入流水线

```text
上传文件
  ↓
文件大小和路径安全检查
  ↓
解析 JSON 或解压到临时目录
  ↓
校验 SHA256 和附件 manifest
  ↓
识别格式版本
  ↓
转换到统一内部模型
  ↓
补 UUID 和默认字段
  ↓
检查关系、重复项和冲突
  ↓
生成预览
  ↓
教师确认
  ↓
事务写入
  ↓
生成结果报告
```

### 8.3 完整恢复

完整恢复表示替换当前整个工作台：

1. 仅教师模式允许执行；
2. 明确提示会覆盖所有业务数据；
3. 展示来源版本、班级数、学生数、记录数和附件状态；
4. 创建当前数据库快照和附件快照；
5. 在临时数据库中写入和校验；
6. 校验外键、UUID、业务关系和附件；
7. 原子替换数据库和附件目录；
8. 刷新当前工作台；
9. 失败时恢复快照。

不能先清空正式附件目录，再逐个复制新附件。

### 8.4 更新导入

更新导入不清空当前数据：

- 相同 UUID：进入更新候选；
- 新 UUID：进入新增候选；
- 当前存在但备份中不存在：默认保留；
- 删除标记：默认不直接删除，先进入冲突预览；
- 成绩、考勤、表现等历史数据：默认追加或生成冲突，不静默覆盖；
- 学生基本资料：允许字段级更新；
- 文档附件：按 UUID 和 SHA256 判断新增、替换或缺失。

第一版优先支持“导入为新班级”或“新增数据集”，复杂字段级合并可在后续版本增强。

### 8.5 导入预览

预览至少显示：

- 来源软件版本；
- 数据格式版本；
- 导出时间；
- 班级、学生、考试、成绩、考勤、请假、量化、沟通、跟进数量；
- 附件总数、缺失数和校验失败数；
- 新增、更新、冲突和忽略数量；
- 是否覆盖当前工作台；
- 是否保留当前密码和访问模式；
- 需要教师确认的异常。

## 9. 旧版本兼容

### 9.1 兼容目标

v0.7.0 至少支持：

- v0.5 旧版表快照和 ZIP；
- v0.6 旧版表快照和 ZIP；
- v0.7 JSON-only；
- v0.7 完整 ZIP。

### 9.2 迁移器

```text
legacy-tables-v1 ─┐
legacy-tables-v2 ─┼─> 统一内部模型 ─> 当前数据库写入器
teacher-work-json-v1 ─┘
teacher-work-zip-v1 ──> 解包后进入同一链路
```

迁移器必须处理：

- 字段改名；
- 新增字段默认值；
- 旧数字 ID 映射；
- 缺少表；
- 空值和类型转换；
- 附件缺失；
- 业务关系校验；
- 警告和统计输出。

不能把成绩缺失默认成 0，也不能把未知关系静默丢弃。

### 9.3 兼容矩阵

每个支持版本都必须有真实样本和测试：

| 来源 | 目标 | 预期结果 |
|---|---|---|
| v0.5 ZIP | v0.7 | 业务数据可迁移，显示字段转换警告 |
| v0.6 ZIP | v0.7 | 业务数据和附件可迁移，安全设置不导入 |
| v0.6 JSON | v0.7 | 转换表结构并补 UUID |
| v0.7 JSON | v0.7 | 校验后导入或更新 |
| 损坏文件 | v0.7 | 拒绝且不修改当前数据 |
| 缺附件 ZIP | v0.7 | 可选择仅恢复业务数据 |

## 10. 访问控制和使用指南

### 10.1 教师工作台模式

教师模式用于：

- 维护学生隐私资料；
- 录入和查看成绩；
- 上传和下载文档；
- 完整备份；
- JSON 导出；
- 恢复；
- 更新导入；
- 修改访问策略。

### 10.2 班级公开模式

班级公开模式用于投屏、课堂现场或公开查看：

- 只开放策略允许的模块；
- 默认不显示成绩、学生隐私、文档和备份入口；
- 不能执行恢复和更新导入；
- 自动锁定后回到班级公开模式。

恢复数据后，当前设备的密码、模式、访问策略和恢复密钥不被备份覆盖。

### 10.3 使用指南新增内容

必须详细说明：

- 第一次如何设置教师密码；
- 如何切换教师工作台模式和班级公开模式；
- 自动锁定如何处理；
- JSON 导出和完整 ZIP 的区别；
- 如何恢复整个工作台；
- 如何只导入一个班级；
- 如何执行更新导入；
- 升级软件前如何备份；
- 备份文件应如何保存；
- 恢复失败或附件缺失时如何处理。

## 11. CloudBase、小程序和 AI 预留

本版本不直接开发在线同步，但必须保留以下边界：

- 交换格式不依赖 SQLite 表名；
- 业务实体有稳定 UUID；
- 附件使用逻辑文件标识，不保存本地绝对路径；
- 导入、更新和恢复使用统一业务服务；
- 安全配置与业务数据分离；
- 所有数据变更可以记录来源、操作人和时间。

未来 CloudBase 接入后：

```text
本地版/小程序
      ↓
统一业务 API
      ↓
CloudBase 数据库、云存储和云函数
```

本地版可以作为客户端或离线缓存，不应使用内置管理员密钥直接修改云端数据库。

未来 AI 可以协助：

- 识别旧字段和新字段；
- 找出重复学生；
- 发现孤立附件；
- 生成迁移计划；
- 检查数据质量；
- 生成导入预览和解释。

AI 不直接拥有生产数据库最高权限。AI 的写入必须经过：

```text
分析 → 变更预览 → 教师确认 → 云函数校验 → 事务执行 → 审计记录
```

## 12. 测试计划

### 12.1 单元测试

- 规范化 JSON 键排序；
- SHA256 正确性；
- UUID 生成和唯一性；
- 旧数字 ID 映射；
- 字段默认值；
- 字段重命名；
- 附件 manifest；
- 路径穿越防护；
- 文件大小和数量限制；
- 安全设置排除。

### 12.2 集成测试

- 空数据导出和导入；
- 多班级完整数据导出和恢复；
- 成绩、考勤、请假、量化、沟通和跟进往返；
- 带附件 ZIP 导出和恢复；
- JSON-only 导入后附件标记正确；
- 旧版 v0.5/v0.6 样本导入；
- 更新导入只新增和更新，不默认删除；
- 恢复失败后数据库和附件均回滚；
- 恢复后当前密码仍然有效；
- 班级公开模式无法执行敏感数据操作。

### 12.3 完整性往返测试

```text
创建全量样例数据
  ↓
导出 JSON 和 ZIP
  ↓
导入空数据库
  ↓
再次导出
  ↓
比较业务内容、关系、统计和附件 SHA256
```

比较时忽略导出时间、本次 `exportId` 和本地自增 ID 的差异，但不能忽略业务记录、关系和附件内容。

### 12.4 覆盖审计测试

数据库新增业务表时，测试必须要求开发者明确登记：

- 是否导出；
- 是否属于敏感配置；
- 如何迁移；
- 如何恢复；
- 是否包含附件。

未登记的业务表应使测试失败。

## 13. 便携版验收

便携版交付前必须执行：

- `npm test` 全部通过；
- `npm run build` 成功；
- `npm run tauri:build` 成功；
- 生成 v0.7.0 ZIP；

## 15. 交付判定

## 16. 最终原则

v0.7.0 的数据工作遵循以下原则：

1. 页面可以移动，数据模型不能依赖页面位置；
2. 菜单可以重组，交换格式不能依赖菜单名称；
3. 数据库可以升级，但必须有明确迁移器；
4. 旧数据可以导入，但不能静默丢失；
5. 恢复和更新必须是两种不同操作；
6. 附件必须可校验，数据库和附件必须保持一致；
7. 密码保护属于本机安全配置，不属于业务备份内容；
8. AI 可以辅助分析和迁移，但不能绕过权限直接修改生产数据；
9. CloudBase 和小程序未来共用统一业务模型；
10. 所有重要数据变更都应可追踪、可解释、可回滚。
