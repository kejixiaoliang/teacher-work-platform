## 一、设计定位

v0.8.0 定义为教师工作台的“云端数据基础与微信小程序接入版本”。本版本不是简单增加一个小程序目录，而是建立电脑端、小程序端、管理员后台和 CloudBase 之间的统一边界。

本版本完成后，后续可以在不破坏核心数据契约的前提下分别优化：

- Windows 便携客户端；
- 微信小程序；
- 管理员 Web 后台；
- CloudBase 云端服务。

这里的“统一”主要指数据模型、身份权限、业务规则和接口契约统一，不要求电脑端和小程序使用相同页面或相同交互。当前阶段先完成电脑端 UI；小程序开发时根据手机屏幕、使用频率和操作场景重新设计页面。两端可以有不同的导航、布局和交互，只要读写同一套云端数据并遵守同一套业务规则即可。

## 二、统一架构

```text
Windows 便携客户端
├─ Vue 前端
├─ 本地 SQLite
├─ 本地附件
└─ 同步模块
          │
          ▼
CloudBase
├─ 文档型数据库：统一业务数据
├─ 云托管：Express API
├─ 云函数：授权、导入、扫码绑定等特权操作
├─ 身份认证：微信身份和教师归属
├─ 静态托管：管理员后台和更新清单
└─ 云存储：未来再启用附件
          ▲
          │
微信小程序 ───── 管理员 Web 后台
```

CloudBase 是云端唯一业务数据源。腾讯云服务器不作为第二套正式业务数据库，便携客户端的 SQLite 只作为本地缓存和离线副本。

## 三、仓库目录方案

不移动、重命名或重构现有目录，只在根目录按阶段新增子目录：

```text
teacher-work/
├─ web/                    # 现有 Vue Web/桌面端前端，不移动
├─ server/                 # 现有本地 Express + SQLite，不移动
├─ src-tauri/              # 现有 Tauri 桌面壳，不移动
├─ data/                   # 本地运行数据，不纳入源码提交
├─ tests/                  # 现有测试
├─ scripts/                # 现有构建和发布脚本
├─ docs/                   # 设计、规划、审计和发布文档
│
├─ project.config.json     # 新建：微信开发者工具项目配置，项目根目录
├─ project.private.config.json # 新建：本机私有配置，不提交敏感内容
├─ miniprogram/            # 新建：微信小程序代码
├─ cloudfunctions/         # 新建：实际云函数根目录
├─ cloudbase/              # 新建：CloudBase 配置、文档和迁移资料
├─ shared/                 # 新建：跨端数据契约和公共规则
└─ admin/                  # 后续新建：唯一管理员后台
```

这里采用“现有桌面项目作为仓库、微信小程序作为配置子工程”的方式：不移动、不重命名现有目录；微信开发者工具打开整个 `teacher-work/` 根目录，但通过根目录配置只编译 `miniprogram/`，并把 `cloudfunctions/` 识别为云函数根目录。

第一阶段只需要准备根目录微信项目配置、`miniprogram/` 工程入口和 `cloudfunctions/` 的最小函数结构；`shared/` 在数据契约确定后创建，`admin/` 在兑换码和管理需求进入实施时创建。

## 四、各目录职责

### 4.1 `web/`

继续承载现有电脑端 Vue 页面、路由、状态和本地 API 调用。后续只增加：

- CloudBase 登录/扫码绑定适配；
- 云端同步适配；
- 导入预检和同步状态显示。

不把小程序页面复制到这里。

### 4.2 `server/`

继续支持本地便携客户端：

- SQLite 访问；
- 本地文件访问；
- 本地备份和恢复；
- 本地 API；
- 离线工作。

后续应逐步把 SQLite 查询从路由中抽离，使业务接口可以映射到 CloudBase，但不立即删除本地后端。

### 4.3 `miniprogram/`

只承载微信小程序代码：

```text
miniprogram/
├─ app.js
├─ app.json
├─ app.wxss
├─ pages/
├─ components/
├─ services/
├─ utils/
└─ assets/
```

微信开发者工具项目配置放在仓库根目录，而不是 `miniprogram/` 内，核心配置应明确：

```json
{
  "miniprogramRoot": "miniprogram/",
  "cloudfunctionRoot": "cloudfunctions/"
}
```

小程序使用 `wx.cloud` 体系，不使用电脑端 Web 登录代码或 SQLite 代码。这样既能保持桌面端和小程序在同一仓库内协同开发，也不会让微信开发者工具把 `web/`、`server/` 或 `src-tauri/` 当作小程序源码。

### 4.4 `cloudbase/`

```text
cloudbase/
├─ cloudrun/
│  └─ api/                 # 云托管 Express API
├─ database/
│  ├─ collections.md
│  ├─ indexes.md
│  ├─ permissions.md
│  └─ migrations/
└─ hosting/
   └─ admin/               # 管理员后台静态托管说明
```

`cloudbase/` 只保存 CloudBase 相关配置、数据库设计、迁移脚本说明、云托管和静态托管资料，不作为微信开发者工具的实际云函数根目录。

实际云函数统一放在仓库根目录：

```text
cloudfunctions/
├─ bind-desktop/            # 电脑端扫码绑定
├─ import-data/             # JSON 预检和导入
├─ redeem-code/             # 兑换码验证
└─ sync-data/               # 同步批次和冲突处理
```

云函数数量保持最少，只承担身份、授权、导入、同步和需要服务端权限的操作。普通业务读取不为了形式而拆成大量函数。

### 4.5 `shared/`

```text
shared/
├─ contracts/              # 云端 DTO、请求和响应结构
├─ constants/              # 状态、枚举和错误码
├─ exchange/               # JSON 交换格式解析和迁移规则
└─ validation/             # 跨端数据校验规则
```

共享的是数据契约和规则，不是 Vue 组件、Element Plus 页面、SQLite 查询或 Tauri API。

## 五、版本关系

```text
产品版本：v0.8.0
电脑端便携包：v0.8.0
CloudBase 数据结构：按迁移版本管理
JSON 交换协议：继续 formatVersion = 1
微信小程序：属于 v0.8.0 产品阶段，内部构建号独立管理
```

v0.8.0 的电脑端必须支持旧版本数据导入，同时增加登录、云端导入和同步基础能力。v0.7.0 便携包可以继续导出 JSON，由 v0.8.0 或 CloudBase 导入服务接收。

## 六、数据统一边界

### 6.1 统一交换格式

唯一交换格式基线是[教师工作台 JSON 备份交换格式 v1 规范](教师工作台-JSON备份交换格式-v1规范.md)。

```text
teacher-work-backup
formatVersion: 1
exportId
source
content
attachments
integrity
```

Excel 继续用于人工录入，ZIP 继续用于电脑端完整备份，JSON 用于电脑端、云端和小程序之间的结构化数据交换。

### 6.2 统一记录身份

跨端业务记录使用持久化 `uuid`。CloudBase 的 `_id` 只作为云端内部文档 ID，SQLite 的整数 `id` 只作为旧版兼容字段。

```text
uuid
cloudId
ownerId
datasetId
createdAt
updatedAt
deletedAt
revision
source
```

记录之间通过 `classUuid`、`studentUuid`、`examUuid` 等稳定引用建立关系。

### 6.3 历史兼容

新版本必须保留：

- v0.7.0 `teacher-work-backup` JSON v1；
- 已承诺支持的旧版 JSON；
- legacy `tables` JSON v1/v2；
- v0.4.2 及更早版本的电脑端 ZIP 恢复能力。

导入流程统一为：格式识别 → 迁移 → 规范化 → 校验 → 预览 → 提交 → 报告。

## 七、认证和授权

### 7.1 小程序

小程序使用微信身份，不设计账号密码登录页面。云端根据当前微信身份取得用户标识，并关联 `teachers`、`licenses` 和业务数据。

### 7.2 电脑端

电脑端通过小程序扫码绑定：

```text
电脑端显示一次性二维码
  ↓
教师用微信打开小程序扫码
  ↓
确认绑定电脑
  ↓
CloudBase 创建短期电脑会话
  ↓
电脑端登录并查询授权
```

### 7.3 管理员后台

管理员后台是独立 Web 页面，由你唯一的微信身份扫码登录。服务端检查 `admins` 集合中的 `owner` 权限，不能只依靠前端隐藏按钮。

### 7.4 兑换码

兑换码绑定教师账号，不直接绑定机器。首次兑换必须联网，后续可以有短期离线宽限期。兑换码原文不保存到数据库，云端只保存哈希和授权状态。

## 九、实施顺序

```text
1. 校正 v0.7.0 基线和文档引用
2. 固定历史 JSON/ZIP 测试样本
3. 完成 UUID 和交换格式兼容
4. 完成 CloudBase 集合、索引和权限
5. 完成本地 JSON 导入预检和回滚
6. 完成 CloudBase 导入
7. 创建 miniprogram/ 最小工程
8. 小程序实现班级和学生只读
9. 小程序实现考勤和表现记录
10. 电脑端加入扫码登录和同步
11. 增加兑换码和管理员后台
12. 增加便携包更新器
```

任何阶段都不能删除旧版导入逻辑或跳过数据迁移测试。

## 十、协同开发规则

- 电脑端和小程序使用同一份数据契约。
- 每个云端接口先定义请求、响应、错误码和权限边界。
- 每个字段变更先更新迁移规则，再改页面。
- 小程序先做云端只读，再做写入，最后做双向同步。
- 本地 SQLite、CloudBase、交换 JSON 使用各自版本号，不能混用。
- 不把本地绝对路径写入云端业务数据。
- 不把 CloudBase 管理密钥放进小程序或便携包。

## 十一、验收标准

- 现有 v0.7.0 软件可以继续运行。
- v0.8.0 电脑端可以读取和导入历史数据。
- 历史 JSON 导出可以进入 CloudBase。
- 小程序可以读取 CloudBase 中的班级和学生。
- 电脑端和小程序使用同一个 `uuid` 识别业务记录。
- 小程序新增考勤或表现后，电脑端可以通过同步识别。
- 重复导入不会产生重复记录。
- 导入失败不会留下半成品。
- 附件暂不上传不会阻塞结构化业务数据导入。
- 教师之间的数据无法互相读取。
- 便携包更新不会覆盖本地数据和附件。

## 十二、前置资料

开始实际创建小程序工程前，需要提供或确认：

1. 微信小程序 AppID。
2. CloudBase 完整 `EnvId`。
3. 当前 CloudBase 环境模式和所在区域。
4. 是否允许电脑端首次登录必须联网。
5. 兑换码是永久、按年还是按版本授权。
6. 云端首次导入默认创建新数据集。
7. 需要纳入兼容测试的历史 JSON/ZIP 样本。

在这些资料确定前，可以创建空的目录和工程配置，但不应写入真实业务数据或部署正式云函数。
