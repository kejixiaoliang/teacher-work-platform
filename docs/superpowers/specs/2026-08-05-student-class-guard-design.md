# 学生录入班级前置门禁设计

日期：2026-08-05

## 问题

学生档案必须归属班级，但当前学生管理页在尚未创建班级时仍允许打开新增表单和选择 Excel。用户填写或解析数据后才发现无法正常保存、显示，容易误以为数据丢失；后端也缺少对有效班级的强制校验，存在产生孤立学生记录的风险。

## 目标

- 用户开始填写或导入前就能看到“必须先创建班级”的要求。
- 没有当前班级时不能打开新增学生表单，也不能选择导入文件。
- 如果表单打开后当前班级失效，保存操作不得提交，表单及已填内容必须保留。
- 后端不得创建或导入未关联到有效班级的学生数据。
- 已有班级时，现有新增、编辑和导入流程保持不变。

## 交互设计

学生管理页根据 `store.currentClassId` 显示两种状态：

1. 有当前班级：显示现有工具栏、筛选器和学生表格。
2. 无当前班级：显示专用空状态，说明“学生档案需要归属班级”，并提供“前往新建班级”按钮，跳转到 `/classes`。

页面顶部仍可保留“新增学生”和“导入 Excel”按钮，但在无班级时处于禁用状态并显示原因；专用空状态是主要操作入口。导出按钮遵循现有无数据提示，无需改变。

## 前端保护

- 新增入口调用统一的班级检查；无班级时不初始化或打开表单。
- 导入入口先检查班级，再触发隐藏文件选择器，避免用户先选择和解析文件。
- 新增学生保存前再次检查当前班级。检查失败时只显示提示，不关闭表单、不清空字段。
- Excel 确认导入继续保留现有二次检查，防止解析期间班级状态变化。
- 编辑已有学生不受新增门禁影响，因为记录已经拥有班级归属。

## 后端保护

- `POST /api/students` 必须收到有效的 `class_id`；缺失或找不到对应班级时返回业务错误，不执行插入。
- `POST /api/students/import` 必须在事务开始前验证 `class_id`，无效时返回业务错误，不导入任何学生。
- 不自动创建默认班级，也不保存“未分班草稿”。

## 测试与验收

自动化测试覆盖：

- 没有班级时，后端拒绝单个学生创建，数据库没有新增记录。
- 不存在的班级 ID 同样被拒绝。
- 没有有效班级时，批量导入被整体拒绝。
- 有效班级下的新增学生仍然成功。
- 前端学生页包含入口门禁、专用空状态和保存兜底逻辑。

人工验证覆盖：

- 空数据库首次启动，进入学生管理页无法开始填写，并可跳转新建班级。
- 新建班级后返回学生页，可以新增并正常显示学生。
- 打开新增表单后模拟当前班级失效，点击保存时内容仍保留。
- Release ZIP 在中文和带空格路径下启动正常。

## 非目标

- 不设计未分班学生池。
- 不引入本地草稿自动保存。
- 不修改既有班级切换、学生编辑或数据库迁移结构。
