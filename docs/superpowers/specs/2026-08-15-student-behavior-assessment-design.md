# 学生日常行为表现量化设计

## 1. 文档状态

- 日期：2026-08-15
- 目标版本：下一版本
- 设计范围：学生日常行为表现记分模块
- 当前状态：待用户审阅
- 工作分支：`codex/student-assessment-quantification`

本文只定义产品规则和技术设计，不包含具体实现代码。实现前应根据审阅意见修订本文，并以本文作为后续实施计划的依据。

## 2. 背景与目标

教师工作台已经具备学生、成绩、考勤、成长档案和家校沟通等能力，但当前“学生表现”主要以自由文本记录存在，无法稳定回答以下问题：

- 某名学生本月的综合表现如何？
- 加分和扣分分别来自哪些行为？
- 哪些行为在班级中最常发生？
- 某次记分是否被修改过，修改前后是什么？
- 如何把班级表现结果导出为 Excel、CSV 或 JSON？

本模块的目标是建立一套简单、可配置、可追溯的日常行为量化机制：

1. 教师可以维护全班级共用的行为分类和行为项目。
2. 教师可以按学生、全班、值日组或班委组批量记分。
3. 行为项目使用固定分值，避免同类行为出现随意分值。
4. 数据按月统计、按学期累计，历史记录长期保留。
5. 已录入记录允许修正，但每次修正都保留审计历史。
6. 统计结果可按当前筛选条件导出为 Excel、CSV 和 JSON。

## 3. 非目标

本版本暂不包含以下能力：

- 账号、角色和多人协作权限系统。
- 云端同步或移动端独立应用。
- 宿舍组、学习小组等新的学生分组模型。
- 自动根据成绩、考勤或请假数据换算行为分数。
- AI 自动评价学生或自动生成分数。
- 跨班级学生排名。
- 删除历史业务数据的清理任务。

成绩、考勤和成长档案仍然保持各自的数据模型；本模块可以在后续版本中作为统一学生时间线的数据来源之一，但不在本版本自动改写这些模块的数据。

## 4. 核心概念

### 4.1 行为分类

用于组织行为项目的一级分类，例如：

- 课堂表现
- 学习习惯
- 卫生劳动
- 文明纪律
- 荣誉表现

分类本身不产生分数，只负责筛选、展示和统计聚合。

### 4.2 行为项目

一条可被教师选择并用于记分的规则，例如：

| 分类 | 行为项目 | 默认分值 | 是否允许当天重复 |
|---|---|---:|---|
| 课堂表现 | 积极发言 | +1 | 否 |
| 课堂表现 | 课堂迟到 | -1 | 否 |
| 学习习惯 | 按时完成作业 | +1 | 否 |
| 学习习惯 | 未完成作业 | -2 | 是 |
| 卫生劳动 | 认真完成值日 | +2 | 否 |
| 文明纪律 | 课堂扰乱秩序 | -2 | 是 |
| 荣誉表现 | 获得表扬 | +3 | 是 |

行为项目具有固定分值。记分时不允许临时修改分值；如果规则发生变化，应修改行为项目或停用旧项目，并由新记录使用新规则。

### 4.3 记分记录

表示一次已经发生的学生行为表现。记录至少包含：

- 班级
- 学生
- 行为项目
- 行为名称快照
- 行为分类快照
- 分值快照
- 发生日期
- 备注
- 当前状态
- 创建时间
- 最近修改时间

行为名称、分类和分值必须保存快照。行为项目后续被改名、停用或调整分值时，历史记录的原始含义不变。

### 4.4 修正记录

表示对记分记录进行编辑、撤销或恢复的历史事件。修正记录保存：

- 目标记分记录
- 修正类型
- 修改前快照
- 修改后快照
- 修正字段清单
- 修正原因
- 修正时间

当前业务记录可以展示最新状态，但历史修正记录永不被覆盖。

## 5. 已确认的业务规则

### 5.1 规则作用范围

- 所有班级共用同一套行为分类和行为项目。
- 记分记录必须绑定具体班级和学生。
- 当前班级页面只展示当前班级的学生和记分记录。
- 不支持跨班级排名。
- 值日组和班委组直接读取现有模块数据。
- 本版本不新增宿舍组、学习小组等分组模型。

### 5.2 记分对象选择

一次记分操作支持以下对象范围：

1. 单个学生。
2. 手动多选学生。
3. 当前班级全选。
4. 当前班级的值日组。
5. 当前班级的班委组。

批量记分不是保存一条带有学生数组的记录，而是为每名学生生成一条独立的记分记录。这样可以支持后续按学生单独查询、编辑、撤销和统计。

同一次批量操作应保存一个 `batch_id`，用于展示操作来源和批量撤销。

### 5.3 固定分值

- 行为项目定义默认分值。
- 记分时不可临时修改分值。
- 分值允许为正数或负数，第一版建议仅允许整数。
- 分值范围需要设置合理上限，建议初始范围为 `-100` 至 `+100`。
- 如需不同分值，不通过临时修改完成，而是新增或修改行为项目。

### 5.4 重复记分

- 同一学生、同一天、同一行为项目默认只能记一次。
- 行为项目可以设置“允许当天重复”。
- 不允许重复的项目再次记分时，系统应阻止写入并提示已有记录。
- 允许重复的项目每次生成独立记录，并参与累计统计。
- 编辑记录时不应绕过重复规则；如果编辑后与其他有效记录冲突，应拒绝保存。
- 已撤销记录不计入重复检查，允许重新记录。

### 5.5 时间周期

- 每条记录使用一个明确的行为日期，格式为 `YYYY-MM-DD`。
- 月度统计按行为日期的自然月汇总。
- 学期统计按班级当前或指定学期汇总。
- 进入新月份或新学期不会删除或隐藏旧数据。
- 历史数据可以按月份、学期、班级、学生和行为分类筛选。

### 5.6 历史快照

记分记录必须保存以下快照字段：

- `category_name_snapshot`
- `item_name_snapshot`
- `score_snapshot`

统计使用记录快照，不实时回读行为项目当前名称或当前分值。行为项目发生以下变化时，历史记录都不受影响：

- 修改名称
- 修改分类
- 修改分值
- 停用项目

### 5.7 编辑、撤销和修正留痕

已录入的记分记录允许直接编辑，但不允许无痕覆盖。

编辑规则：

- 编辑前保存完整旧值。
- 保存完整新值。
- 自动生成一条修正记录。
- 统计使用最新有效版本。
- 修改学生、行为项目、行为日期或分值时，必须填写修正原因。
- 只修改普通备注时，修正原因可以不填写。
- 撤销作为一种特殊修正，统计时排除该记录，但原记录和撤销原因保留。
- 已撤销记录允许恢复；恢复也必须产生修正记录。

建议的修正类型：

- `edit`：普通编辑
- `void`：撤销
- `restore`：恢复

### 5.8 初始行为项目

首次启用模块时预置一套基础规则，避免空白页面无法使用。预置规则属于系统模板，用户可以：

- 修改名称
- 修改分类
- 修改分值
- 修改是否允许重复
- 停用项目
- 新增项目

预置项目的变更不修改历史记分记录。

## 6. 建议的数据模型

数据库当前版本为 v3。本模块预计新增数据库迁移版本 v4。建议新增以下表。

### 6.1 `assessment_categories`

行为分类表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 主键 |
| `name` | TEXT | 分类名称，全局唯一 |
| `sort_order` | INTEGER | 展示顺序 |
| `is_active` | INTEGER | 是否启用 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 修改时间 |

停用分类时，应阻止新项目继续选择该分类，但不能影响历史记录。

### 6.2 `assessment_items`

行为项目表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 主键 |
| `category_id` | INTEGER FK | 所属分类 |
| `name` | TEXT | 行为项目名称 |
| `score` | INTEGER | 固定分值 |
| `allow_daily_repeat` | INTEGER | 是否允许同日重复 |
| `description` | TEXT | 行为说明 |
| `sort_order` | INTEGER | 展示顺序 |
| `is_active` | INTEGER | 是否启用 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 修改时间 |

建议约束：

- 同一分类下行为项目名称不能重复。
- `score` 必须是整数且在规定范围内。
- 停用项目不能用于新记分，但历史记录仍可查询。
- 有历史记录的项目不物理删除，只允许停用。

### 6.3 `assessment_records`

学生行为记分表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 主键 |
| `batch_id` | TEXT | 批量操作标识，可为空 |
| `class_id` | INTEGER FK | 班级 |
| `student_id` | INTEGER FK | 学生 |
| `item_id` | INTEGER FK | 当前关联行为项目，可为空 |
| `category_name_snapshot` | TEXT | 分类快照 |
| `item_name_snapshot` | TEXT | 行为名称快照 |
| `score_snapshot` | INTEGER | 分值快照 |
| `behavior_date` | TEXT | 行为发生日期 |
| `remark` | TEXT | 备注 |
| `status` | TEXT | `active` / `voided` |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 最近修改时间 |

`item_id` 用于关联当前项目，快照字段用于保证历史解释稳定。行为项目被停用或删除后，历史记录仍可通过快照展示。

建议索引：

- `(class_id, behavior_date)`
- `(student_id, behavior_date)`
- `(class_id, student_id, behavior_date)`
- `(item_id, behavior_date)`
- `(batch_id)`

重复规则不建议完全依赖数据库唯一索引，因为允许重复的项目和已撤销记录需要动态判断。后端保存前应执行事务内校验。

### 6.4 `assessment_record_revisions`

记分记录修正历史表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 主键 |
| `record_id` | INTEGER FK | 目标记分记录 |
| `action` | TEXT | `edit` / `void` / `restore` |
| `before_json` | TEXT | 修改前快照 |
| `after_json` | TEXT | 修改后快照 |
| `changed_fields_json` | TEXT | 发生变化的字段 |
| `reason` | TEXT | 修正原因 |
| `created_at` | TEXT | 修正时间 |

所有 JSON 字段都由服务端生成，客户端只提交业务字段和原因，避免客户端伪造审计内容。

## 7. 页面与交互设计

建议新增一级页面：`/assessment`，名称为“表现量化”或“行为考核”。

### 7.1 页面布局

页面建议分为三部分：

1. 顶部概览：当前班级、本月总加分、本月总扣分、净分、已记录人数。
2. 主工作区：记分录入和记分流水。
3. 统计区域：月度/学期排名、分类贡献和学生明细。

行为规则维护可以采用页面内 Tab 或独立设置抽屉，第一版建议放在同一页面的“规则管理”Tab，避免增加额外导航入口。

### 7.2 记分录入流程

1. 选择行为日期，默认今天。
2. 选择行为分类。
3. 选择行为项目。
4. 页面展示固定分值、是否允许重复和行为说明。
5. 选择学生范围：手动多选、全班、值日组、班委组。
6. 查看将生成的学生数量和预计总分。
7. 填写可选备注。
8. 提交记分。
9. 后端事务校验所有学生归属、项目状态、重复规则后批量写入。
10. 返回成功数量、跳过数量和逐行失败原因。

批量保存必须采用 all-or-nothing 或明确的逐行结果契约。本模块建议采用“有效行全部写入、冲突行逐行跳过并返回明细”，但前端必须把跳过原因展示出来，不能只提示一个模糊的失败数量。

### 7.3 记分流水

流水默认按行为日期倒序展示，字段建议包括：

- 日期
- 学生
- 行为分类
- 行为项目
- 分值
- 备注
- 状态
- 最后修改时间
- 操作：编辑、撤销、查看修正历史

支持筛选：

- 日期范围
- 月份
- 学期
- 学生
- 行为分类
- 行为项目
- 加分/扣分
- 是否包含已撤销记录

### 7.4 规则管理

规则管理应支持：

- 新增分类
- 编辑分类
- 停用分类
- 新增行为项目
- 编辑行为项目
- 调整行为项目顺序
- 设置固定分值
- 设置是否允许当天重复
- 设置行为说明
- 停用行为项目

编辑行为项目时，界面必须明确提示：修改只影响以后新产生的记分，历史记录保持原快照。

### 7.5 统计视图

统计区域包含以下视图：

#### 今日流水

展示当天的所有有效记分，可按加分、扣分和行为分类筛选。

#### 月度排名

展示当前班级当月每名学生：

- 加分合计
- 扣分合计
- 净分
- 有效记录数
- 涉及行为分类数

默认按净分降序排列；同分时按加分降序，再按学生姓名排序。

#### 学期排名

和月度排名字段一致，统计范围扩大到指定学期。

#### 学生明细

选择学生后展示其加分、扣分、净分和全部记录明细，并可查看每条记录的修正历史。

#### 分类贡献

按行为分类展示：

- 记录数量
- 加分合计
- 扣分合计
- 净分
- 涉及学生数

分类贡献用于帮助教师发现班级表现主要集中在哪些方面，不作为额外排名分数。

## 8. 导出设计

导出必须使用当前筛选条件，避免用户看到一套数据、导出另一套数据。

### 8.1 Excel

建议至少包含以下工作表：

1. 统计汇总：学生排名和班级概览。
2. 记分明细：每条有效或筛选出的记录一行。
3. 分类汇总：行为分类贡献。

如果用户选择“包含已撤销记录”，在明细中增加状态、撤销时间和撤销原因。

### 8.2 CSV

CSV 默认导出当前视图对应的扁平表格。字段使用稳定的英文键或明确的中文表头，建议在导出文件中统一使用 UTF-8 BOM，保证 Windows Excel 打开时中文不乱码。

### 8.3 JSON

JSON 导出建议包含元数据和数据数组：

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-08-15T12:00:00.000Z",
  "filters": {
    "classId": 1,
    "month": "2026-08"
  },
  "summary": {},
  "records": [],
  "categorySummary": []
}
```

JSON 导出不应包含真实磁盘路径、API token 或其他运行时敏感信息。

## 9. API 设计建议

建议新增 `server/routes/assessment.js`，并挂载到 `/api/assessment`。

### 9.1 分类和行为项目

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/assessment/categories` | 查询分类和项目 |
| POST | `/api/assessment/categories` | 新增分类 |
| PUT | `/api/assessment/categories/:id` | 编辑或停用分类 |
| POST | `/api/assessment/items` | 新增行为项目 |
| PUT | `/api/assessment/items/:id` | 编辑行为项目 |
| POST | `/api/assessment/items/:id/disable` | 停用行为项目 |

### 9.2 记分记录

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/assessment/records` | 按班级、日期、学生、分类和状态查询流水 |
| POST | `/api/assessment/records/batch` | 单人或批量记分 |
| PUT | `/api/assessment/records/:id` | 编辑记分并写入修正历史 |
| POST | `/api/assessment/records/:id/void` | 撤销记分 |
| POST | `/api/assessment/records/:id/restore` | 恢复已撤销记分 |
| GET | `/api/assessment/records/:id/revisions` | 查询修正历史 |
| POST | `/api/assessment/batches/:batchId/void` | 批量撤销同一批次 |

### 9.3 统计

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/assessment/stats/daily` | 今日流水与概览 |
| GET | `/api/assessment/stats/monthly` | 月度排名和分类汇总 |
| GET | `/api/assessment/stats/term` | 学期排名和分类汇总 |
| GET | `/api/assessment/stats/student/:id` | 单个学生明细和趋势 |

统计接口应只统计 `status = 'active'` 的记录，除非显式传入 `include_voided=1`。

## 10. 数据校验与一致性

后端必须进行以下校验，不能只依赖前端：

- 分类名称非空、长度受限。
- 行为项目名称非空、长度受限。
- 分值必须是有限整数，并在允许范围内。
- 行为日期必须是有效的 `YYYY-MM-DD` 日期。
- 学生必须存在、未软删除，并且属于请求中的班级。
- 值日组和班委组解析出的学生必须属于当前班级。
- 停用项目不能新建记分。
- 不能重复的项目必须执行每日重复校验。
- 编辑时必须校验新学生、新项目和新日期的归属及重复规则。
- 修正原因必须在要求时填写并限制长度。
- 所有批量操作必须返回明确的成功、跳过和失败明细。

所有写操作建议使用 SQLite 事务，保证记分记录和修正历史同时成功或同时回滚。

## 11. 备份、恢复与迁移

现有备份路由使用固定业务表清单。新增表后必须同步更新：

- 全量备份表清单
- 班级备份范围
- 恢复时的表结构校验
- 恢复后的外键一致性检查
- 数据库迁移测试

数据库版本从 v3 升至 v4 时：

1. 创建新表。
2. 插入预置分类和行为项目。
3. 建立索引和外键。
4. 更新 `user_version`。
5. 在已有数据库升级前创建恢复备份。
6. 验证升级后原有成绩、考勤、学生和备份功能不受影响。

本模块不应修改已有学生、成绩、考勤或成长档案数据。

## 13. 第一版验收标准

第一版完成后，教师应能完成以下闭环：

1. 打开表现量化页面，看到预置行为项目。
2. 新增一个自定义行为项目并设置固定分值。
3. 选择值日组，为组内学生批量加分。
4. 选择全班，为所有学生批量扣分。
5. 对不允许重复的项目重复记分时收到阻止提示。
6. 在月度视图看到学生排名和分类贡献。
7. 在学期视图看到累计结果，且历史月份数据仍然存在。
8. 导出当前筛选结果为 Excel、CSV 和 JSON。
9. 编辑一条记分记录并填写修正原因。
10. 查看该记录的修正历史，能看到修改前和修改后的内容。
11. 撤销一条记录后，统计结果立即排除该记录。
12. 恢复该记录后，统计结果重新包含该记录。

## 14. 当前仍需在实现前确认的细节

以下细节不影响当前规则主线，但实现前需要最终确定：

1. 学期值如何读取：沿用当前班级的 `academic_year + term`，还是允许统计时手动输入学期。
2. 排名是否默认展示所有在读学生，还是只展示有记分记录的学生。
3. 行为项目和分类是否允许物理删除：建议有历史记录时只允许停用。
4. 批量记分遇到部分学生重复时，是否保留其他未冲突学生的成功结果：本文暂定保留成功结果并返回逐行明细。
5. 是否需要提供“复制行为项目”快捷操作。

这些细节在用户审阅后补充，不改变已经确认的固定分值、历史快照、月度统计、学期累计、可编辑留痕和导出规则。
