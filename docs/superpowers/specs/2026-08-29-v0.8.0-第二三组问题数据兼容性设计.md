# 教师工作台 v0.8.0 第二、三组问题数据兼容性设计

## 1. 目标与范围

本设计覆盖两组已有需求：

- 第二组：部分界面词条可自定义、考试科目可配置、值日表按星期显示固定小组。
- 第三组：学生字段显示名称可调整、可启用/隐藏住宿等标准字段、可增加身份证号等学校字段，并同步 Excel 模板与导出。

本设计不新增学生作业管理或班主任台账模块，也不允许用户修改 SQLite 的真实列名、接口字段名或历史记录结构。

## 2. 当前代码审查结论

### 2.1 第二组

- 考试已经支持在 `web/src/views/Scores.vue` 中自由输入科目，`exams.subjects` 以 JSON 数组持久化；成绩表 `exam_scores.subject` 仍直接保存科目名称。
- 科目模板目前保存在浏览器 `localStorage`，不会进入服务器备份；考试本身的科目和成绩会进入备份。
- 值日接口已经有 `week_days` 字段和 `PUT /api/duties/group-days`，但 `web/src/views/Duties.vue` 的值日表仍优先按“每周轮换一组”生成。
- 界面词条目前主要硬编码在 Vue 模板中，没有稳定的显示键和班级级配置。

### 2.2 第三组

- 学生真实字段在 `server/db.js` 固定声明，`server/routes/students.js` 通过白名单 `FIELDS` 写入；任意增加 SQL 列会影响迁移、恢复和备份校验。
- Excel 表头在 `web/src/views/Students.vue` 的 `TEMPLATE_COLS` 固定，解析逻辑在 `web/src/domain/studentImport.js` 通过 `FIELD_ALIASES` 匹配标准表头。
- 备份校验在 `server/routes/backup.js` 中按 `PRAGMA table_info` 严格拒绝未知字段；这能防止脏数据，但不适合把用户自定义字段直接变成动态 SQL 列。
- 交换备份已有稳定 `uuid/sourceId` 和完整性校验，但 `content.settings` 当前未承载业务配置；`app_settings` 还包含密码和访问策略，不能直接导出。

## 3. 核心兼容性决策

### 3.1 不改变核心表结构表达自定义字段

用户自定义字段使用独立的定义表和值表，不执行“每增加一个字段就 `ALTER TABLE students ADD COLUMN`”的方案：

```sql
CREATE TABLE student_field_definitions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  class_id INTEGER NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
  field_key TEXT NOT NULL,
  label TEXT NOT NULL,
  data_type TEXT NOT NULL DEFAULT 'text',
  enabled INTEGER NOT NULL DEFAULT 1,
  archived INTEGER NOT NULL DEFAULT 0,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now','localtime')),
  updated_at TEXT DEFAULT (datetime('now','localtime')),
  UNIQUE(class_id, field_key)
);

CREATE TABLE student_field_values (
  student_id INTEGER NOT NULL REFERENCES students(id) ON DELETE CASCADE,
  field_id INTEGER NOT NULL REFERENCES student_field_definitions(id) ON DELETE CASCADE,
  value_text TEXT NOT NULL DEFAULT '',
  updated_at TEXT DEFAULT (datetime('now','localtime')),
  PRIMARY KEY(student_id, field_id)
);
```

`field_key` 和 `uuid` 永远不因改名、排序或隐藏而改变；删除操作只做 `archived=1`，历史值保留。`data_type` 只允许 `text`、`number`、`date`、`boolean` 四种受控类型。

住宿、身高、视力等现有标准字段仍使用稳定的系统字段键；“隐藏住宿”只隐藏表格、表单和模板列，不删除数据库中的 `is_boarding` 值。

### 3.2 配置按班级保存，密码设置不进入备份

增加两张非敏感配置表：

- `class_display_labels`：`class_id + label_key + label_value`，只允许白名单显示键，例如 `student.boarding`、`student.parentPhone`、`duty.group`。
- `subject_templates`：`class_id + uuid + name + subjects_json`，把当前 `localStorage` 中的科目模板迁移为服务端数据。

不导出 `app_settings`，因为其中含访问模式、密码哈希和恢复信息。新的业务配置表会随班级备份和完整备份导出。

### 3.3 Excel 使用稳定键，不依赖列序号

模板和导出工作簿增加隐藏工作表 `__teacher_work_meta`，每一行记录：`fieldKey`、`label`、`dataType`、`enabled`、`schemaVersion`。可见工作表仍显示用户易读的表头。

- 新模板优先按 `fieldKey` 写入和解析，即使用户改了表头或调整了列顺序也不会错位。
- 没有元数据页的旧模板继续使用现有标准别名解析。
- 无法识别的列进入导入预览的“未映射列”，不得静默写入或丢弃。
- 隐藏字段不出现在新模板和普通导出中，但旧模板中的该列仍可被识别并保存。

### 3.4 备份采用可识别的能力版本

v0.8.0 新备份增加 `formatVersion: 2`、`databaseVersion: 8`、`minReaderVersion: "0.8.0"` 和 `capabilities`。读取规则如下：

| 来源 | v0.8.0 行为 | 数据安全 |
| --- | --- | --- |
| v0.7.0 / formatVersion 1 | 接受，缺少新配置表时使用默认词条、空自定义字段配置 | 核心数据正常恢复 |
| v0.8.0 / formatVersion 2 | 接受定义、值、标签和科目模板 | 字段键按 UUID 映射 |
| 更高版本或未知能力 | 预检阶段拒绝并说明需要升级，不开始事务 | 不静默丢弃字段 |
| v0.8.0 数据给旧版软件 | 旧版应根据 `minReaderVersion` 拒绝并提示升级 | 不覆盖旧库 |

完整性校验覆盖新增配置内容。追加导入时通过稳定 UUID 映射 `class_id`、`student_id`、`field_id`；全量恢复在外键事务中按依赖顺序恢复。类级备份同时包含该班的字段定义、字段值、显示标签和科目模板。

## 4. 用户可见行为

- 学生字段设置提供“显示名称、启用/隐藏、类型、顺序”四项；核心字段不可删除，自定义字段只能归档。
- 隐藏住宿后，学生列表、筛选、编辑表单、详情和新模板均不显示住宿，但已有住宿数据仍可在重新启用后出现。
- 考试科目继续支持输入、删除、排序和模板套用。已有成绩的科目名称不直接重写；有成绩时改名/删除需提示“将影响历史成绩”，v0.8.0 只允许新增或归档，避免字符串科目名产生孤儿成绩。
- 值日表优先显示当天固定星期对应的小组；同一天配置多个小组时全部显示并给出冲突提示；没有固定星期配置时回退原有周轮换。

## 5. 验收底线

1. 自定义字段改名、隐藏、排序后，学生数据和 Excel 映射不变。
2. 完整备份、班级备份和追加更新均能保留字段定义和值；恢复到新版本后可重新显示。
3. v0.7.0 备份导入 v0.8.0 不报未知表错误；v0.8.0 备份给旧版本时明确拒绝，不覆盖数据。
4. 班级模式接口不返回自定义字段值和隐私标签配置，教师模式才可管理这些内容。
5. 已有考试成绩、值日分组和旧 Excel 模板全部通过回归测试。
