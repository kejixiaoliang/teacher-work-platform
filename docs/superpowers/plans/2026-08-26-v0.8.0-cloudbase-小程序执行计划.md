# 教师工作台 v0.8.0 CloudBase 与微信小程序执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在既有 v0.8.0 数据兼容规则和统一架构基础上，完成小程序首个可用数据链路，并为后续云端导入、电脑端同步、兑换码和管理员后台建立可测试的实现顺序。

**Architecture:** 保留现有 Windows 客户端的 Vue、SQLite、Express 和 Tauri 目录不动；小程序使用原生 `wx.cloud`，通过 CloudBase 云函数访问受保护的数据；CloudBase 记录统一使用稳定 `uuid`、`ownerId`、`datasetId` 和导入批次字段。小程序和客户端共享数据契约，但页面和交互独立演进。

**Tech Stack:** 微信小程序原生 WXML/WXSS/JavaScript、CloudBase NoSQL、Nodejs18.15 云函数、现有 Node.js `node:test` 测试、现有 SQLite/Express/Tauri 客户端。

## Global Constraints

- 当前软件基线保持 `v0.7.0`；软件版本、SQLite 版本、JSON `formatVersion` 和 ZIP 版本独立维护。
- 旧版 JSON/ZIP 导入逻辑不得删除；新增逻辑必须先识别、迁移、规范化和校验，再持久化。
- 跨端业务记录使用持久化 `uuid`；本地整数 `id` 只能作为 `legacyId`，不能作为跨端主键。
- 所有 CloudBase 业务记录必须带 `ownerId` 和 `datasetId`；云函数从 `wx-server-sdk` 的 `OPENID` 获取 `ownerId`，不得信任客户端传入值。
- 第一阶段默认“导入为新数据集”，不得静默覆盖已有云端数据；重复 `exportId` 必须可识别。
- 小程序暂不上传附件；只保留文档元数据和附件省略信息。
- 云函数代码实际根目录固定为仓库根目录下的 `cloudfunctions/`，不得放入 `cloudbase/`。
- 不把 CloudBase 管理密钥、API key、密码或本地绝对路径写入小程序、便携包或业务数据。
- 每个任务必须先写测试或静态门禁，完成验证后单独提交；提交信息使用明确的 Conventional Commit。
- 不在没有权限、映射、幂等和失败恢复设计的情况下开放真实批量写库。
