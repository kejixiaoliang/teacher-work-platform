# v0.4.2 备份归档与一次性文件授权实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 v0.4.1 基础上完成带文件本体的 ZIP 备份恢复，并将文档预览/下载改为短时一次性文件授权，降低附件丢失和 URL token 泄露风险。

**Architecture:** 备份接口继续保留旧版 JSON 导入兼容，同时新增 v2 ZIP 归档：`backup.json` 保存数据库表和文件清单，`files/` 保存实际附件；导入时先在临时目录解压、校验路径/数量/大小/哈希，再在数据库事务成功后替换附件。文件访问新增内存中的短时一次性 token，API token 只用于申请 token，真正文件流只能使用绑定文档 ID 的一次性 token；前端通过认证 fetch 获取 Blob URL，不再把长期 API token 放入图片、iframe 或下载链接。

**Tech Stack:** Node.js 22、Express、Multer、SQLite/better-sqlite3、Vue 3、Node test runner、`archiver`、`unzipper`。

## Global Constraints

- 产品版本目标固定为 `0.4.2`，版本契约中的 `package.json`、Cargo、Tauri 配置和 Changelog 必须一致。
- 旧版 `version: 1` JSON 备份必须继续可导入；新版 ZIP 内的 `backup.json` 使用 `version: 2`。
- ZIP 内路径只能是 `backup.json` 或 `files/<basename>`，拒绝绝对路径、`..`、目录穿越、重复条目和超出数量/总大小限制的归档。
- 文件 token 默认有效期 30 秒、成功消费后立即失效，并绑定具体文档 ID；API token 不能继续作为文件 URL 的长期 query token。
- 恢复失败必须保留当前数据库和当前文件目录不变；恢复前数据库快照继续写入 `data/backups/`。
- 所有生产代码先有会失败的测试，再写最小实现；每个任务完成后运行对应测试和全量 `npm test`。

## Task 3: Implement one-time document file authorization

**Files:**
- Create: `server/security/file-access.js`
- Create: `tests/file-access.test.js`
- Modify: `server/app.js`, `server/routes/documents.js`
- Modify: `web/src/api.js`, `web/src/platform/runtimeConfig.js`, `web/src/views/Documents.vue`
- Modify: `tests/desktop-api.test.js`, `tests/workflow-smoke.test.js`

**Interfaces:**
- `GET /api/documents/:id/file-token`：必须带 API header token，返回 `{ token, expiresIn: 30000 }`。
- `GET /api/documents/:id/file?__token=<one-time-token>`：只接受绑定该文档的一次性 token；成功读取后立即消费。
- `api.documents.readFile(id, { download = false })`：申请一次性 token，fetch Blob，并返回 Blob。

- [ ] **Step 1: Write failing tests**

测试签发 token 需要 API header；首次访问目标文件返回 200；同一 token 第二次访问返回 401；token 访问其他文档返回 401；过期 token 返回 401；文件 URL 不再由 `runtimeConfig.toApiUrl(..., true)` 拼接长期 API token。

- [ ] **Step 2: Run tests and verify RED**

Run: `node --test tests/file-access.test.js tests/desktop-api.test.js`

Expected: FAIL because token endpoint和一次性消费逻辑不存在，现有 query token 行为仍可重复使用。

- [ ] **Step 3: Implement token store and route guard**

token store 使用 `crypto.randomBytes(32).toString('base64url')`，Map value 保存 `{ documentId, expiresAt }`；签发时清理过期项；消费时先校验文档 ID 和有效期，再删除 token。`app.js` 仅对 `GET /documents/<id>/file` 放行有效一次性 token，其他 API 不得用该 token 绕过 API token。文件路由保留 `nosniff`、`no-referrer`、`no-store` 响应头。

- [ ] **Step 4: Update frontend to Blob URLs**

`api.documents.readFile` 先用 header token请求 token，再用一次性 query token fetch 文件。`Documents.vue` 为图片/PDF设置 Blob URL，为文本读取 Blob text，下载同样先取 Blob 再触发 `<a download>`；预览关闭、切换文件和组件卸载时调用 `URL.revokeObjectURL`。

- [ ] **Step 5: Run tests and verify GREEN**

Run: `node --test tests/file-access.test.js tests/desktop-api.test.js tests/workflow-smoke.test.js`

Expected: 一次性 token、过期/错文档拒绝、Blob 预览下载和既有 API token 契约全部通过。
