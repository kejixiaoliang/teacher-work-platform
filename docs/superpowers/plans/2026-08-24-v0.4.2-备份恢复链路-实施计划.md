# v0.4.2 备份恢复链路修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复备份导入成功后前端误报失败的问题，增强网络错误可诊断性，并验证数据库、附件和重启后的恢复一致性。

**Architecture:** 保持现有服务端“ZIP 解包与校验 → 恢复前数据库快照 → 文件暂存/回滚 → SQLite 事务导入”的整体结构。前端将恢复成功和恢复后的界面刷新分成两个阶段，使用正确导出的班级加载函数；服务端只对已提交的恢复返回成功，清理临时资源不再覆盖恢复结果。

**Tech Stack:** Vue 3、Element Plus、Express、better-sqlite3、Node.js node:test、ZIP 备份归档。

**Spec:** 本轮备份恢复问题审计结论与用户反馈（2026-08-24）。

## Global Constraints

- 不升级产品版本，继续维护 v0.4.2 修复分支。
- 不改变现有备份格式 v1/v2 和 TABLES 数据表契约。
- 恢复前快照必须继续保留在 data/backups/，不得静默删除。

- [ ] **Step 2: Separate restore success from refresh failure**

服务端导入成功后显示恢复成功；首页刷新失败时单独显示“数据已恢复，但首页刷新失败，请刷新页面”，不得再次显示“恢复失败”。服务端导入请求失败时仍显示“恢复失败”。
