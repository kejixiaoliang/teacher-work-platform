# V0.8.0 客户端视觉与小程序功能一致性重构实施规划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以现有桌面客户端的真实功能、模块分类、信息层级和视觉语言为唯一基准，重构微信小程序的页面布局，使小程序成为客户端的移动端重排版本，并确保所有可见操作均可用、数据字段和业务逻辑不变。

**Architecture:** 保留现有 CloudBase 适配层、数据交换格式、页面路由和业务服务；只重构小程序页面的 WXML/WXSS 与必要的页面状态逻辑。桌面端负责大屏工作区、表格和多面板编辑，小程序端负责同一批数据和操作的移动端顺序重排，不复制桌面端的宽屏尺寸，也不另起一套业务模型。

**Tech Stack:** 微信小程序原生 WXML/WXSS/JavaScript、微信 `wx.cloud`、现有 CloudBase 云函数、Node.js 内置测试运行器、微信开发者工具真机/模拟器预览。

**Spec:** `docs/2026-08-26-v0.8.0-客户端与微信小程序-UI与功能分栏设计规划.md`、`docs/2026-08-26-v0.8.0-客户端与微信小程序统一架构-设计说明.md`、`docs/2026-08-27-v0.8.0-项目文件命名与客户端小程序模块划分设计规划.md`、`docs/2026-08-27-v0.8.0-小程序核心三栏UI返工设计规范.md`

## Global Constraints

- 客户端当前版本为 V0.7.0；本次工作属于 V0.8.0 小程序统一架构阶段。
- 不修改永久兼容的 JSON/ZIP 数据交换格式、稳定 UUID、字段名称、CloudBase 集合名称和数据归属规则。
- 不新增客户端没有的业务功能；小程序只重新排列和承载现有客户端功能。
- 小程序身份范围为班主任/教师本人；所有云端查询和写入必须继续按教师身份与数据集隔离。
- 所有页面必须保留 loading、empty、error、success、disabled 和权限限制等适用状态。
- 页面可见的按钮、入口和列表项必须绑定真实事件；不允许保留“看起来能点但只显示占位提示”的核心操作。
- 小程序页面目录固定为 `miniprogram/pages`；共享样式固定使用 `miniprogram/tokens.wxss`，不移动现有目录。
- 每完成一个独立阶段，必须先运行对应测试，再在当前分支提交；提交信息使用 `feat:`、`fix:`、`test:` 或 `docs:` 前缀。
- 不在本规划阶段部署云函数、修改 CloudBase 权限或发布小程序；真实云端联调单独通过部署门禁后执行。

## 1. 客户端基准与一致性边界

### 1.1 客户端真实信息架构

| --- | --- | --- | --- |

### 1.1.1 小程序工作台分组规则

首页只承载客户端“概览首页”，不在工作台中重复放置“概览”入口。工作台内部必须按客户端原有分组原样展示：

- **常用**：学生管理、座位管理。
- **学习分析**：数据分析、成绩管理、考勤管理、表现量化。
- **班级事务**：文档管理、值日管理、班委学委、课代表选择、请假管理、家校沟通。

如果后续客户端新增“作业管理”，小程序必须使用客户端同名模块和同一模块 ID，并放入客户端实际所属分组；在客户端尚未存在该模块前，小程序不得自行增加或改造出“作业管理”。

三个 tab 只负责一级导航容器：**首页、工作台、设置**；“常用、学习分析、班级事务”是工作台内部的二级分组，不得被替换成面向实现的“班级与学生、日常记录、成绩与资料”等自定义分类。

### 1.2 客户端首页必须迁移的真实内容

客户端概览首页的内容顺序是小程序首页的内容基准：

1. 当前学年/学期、当前班级、班主任身份。
2. 首页快捷操作：排座位、上传文档、值日安排、班委学委。
3. 班级统计：学生、男生、女生、近视、住宿、平均身高。
4. 今日工作台：今日考勤、今日请假、值日安排、近期考试、跟进事项。
5. 今日概览：考勤、请假、最近家校沟通。
6. 最近考试、班委、课代表、今日值日、当前座位表、最近文档。
7. 数据管理：学期存档、完整备份、JSON 导出、备份恢复、更新导入 JSON。

小程序可以将上述内容拆成纵向区块或横向滚动条，但不能只展示“导入数据”和“学生名单”，也不能以一个巨大欢迎卡片代替真实概览。

### 1.3 视觉基准

桌面端 `web/src/style.css` 已经形成明确设计系统，小程序必须复用其语义而不是另创一套：

- 背景：奶油纸 `#fff4dc`，可保留轻微网格纹理，但不得使用大面积纯灰背景。
- 主色：墨黑 `#201b17`。
- 强调色：番茄红 `#d64541` / `#f35b3f`、芥末黄 `#f2c84b`、薄荷绿 `#8bd6af`、天空蓝 `#93c9d8`。
- 组件：粗黑边、实色错位阴影、贴纸标题、胶囊标签、紧凑工具栏。
- 字体：`Noto Serif SC`/`Songti SC` 用于标题，`Noto Sans SC`/`PingFang SC`/`Microsoft YaHei` 用于正文；不使用 Inter、Roboto、Arial、system-ui 或 emoji 图标。
- 密度：移动端优先信息扫描；入口卡片高度约 `88rpx–104rpx`，设置行高约 `60rpx–68rpx`，页面左右留白 `28rpx–32rpx`。
- 阴影：只用于页面主容器、主操作和重要状态，不给每个小文本块附加厚重阴影。

## 2. 文件边界与实施顺序

### 2.1 共享文件

| 文件 | 职责 | 本次允许修改范围 |
| --- | --- | --- |
| `miniprogram/tokens.wxss` | 小程序共享色板、字体、按钮、空状态、分隔线令牌 | 补齐间距、状态、表面和移动端密度变量 |
| `miniprogram/app.wxss` | 全局页面背景、默认字体、按钮基础重置 | 保持暖纸背景和可读性，不写业务页面规则 |
| `miniprogram/app.json` | 页面注册、tabBar、窗口配置 | 只在缺失页面注册或标题不一致时修改 |
| `tests/miniprogram-navigation.test.js` | 路由、模块入口和功能覆盖契约 | 每增加或调整入口时同步更新 |
| `tests/miniprogram-teacher-data.test.js` | 首页数据状态契约 | 同步首页真实内容和状态断言 |

### 2.2 三个主入口

| 页面 | WXML | WXSS | JS 约束 |
| --- | --- | --- | --- |
| 首页 | `miniprogram/pages/index/index.wxml` | `miniprogram/pages/index/index.wxss` | 继续使用 `loadTeacherData`，不得在页面内直接伪造统计数据 |
| 工作台 | `miniprogram/pages/workbench/index.wxml` | `miniprogram/pages/workbench/index.wxss` | `openFeature` 必须按统一模块 ID 路由 |
| 设置 | `miniprogram/pages/settings/index.wxml` | `miniprogram/pages/settings/index.wxss` | 导入、兑换码入口必须保持真实跳转，未接入项必须明确标注其状态 |

### 2.3 业务页面

业务页面只调整移动端呈现，不改变已有页面 JS 的服务调用：

- `students`、`student-detail`：学生档案字段、搜索、详情、编辑、软删除。
- `attendance`、`leaves`、`follow-up`：日期/班级筛选、逐生操作、保存、状态流转。
- `scores`、`analysis`：考试、科目、成绩录入、统计和分析摘要。
- `seats`、`duties`：座位网格、讲台、行列、锁定、自动排座、值日分组和星期安排。
- `contacts`、`documents`：家校沟通记录、文档元数据和现有文件策略。
- `assessment`、`assessment-rules`：记分、规则联动、批量记分、修正历史、撤销/恢复。
- `import`、`redeem`：JSON 导入预检/提交、兑换码验证；不得只做静态表单。

## 4. 数据与功能可用性规则

### 4.1 数据读取

- 页面只能通过现有服务层读取数据，不能在 WXML 中拼接 CloudBase 查询。
- 每次读取必须带 `datasetId`，由当前教师身份对应的有效数据集产生。
- 页面切换班级时，只更新当前班级视图，不改写其他班级数据。
- 请求失败时保留已成功读取的数据，并提供重试动作。

### 4.2 数据写入

- 写入必须调用已有云函数/服务合同，服务端重新校验 owner、dataset 和稳定 UUID。
- 保存按钮在请求期间禁用，成功后刷新当前页数据，失败后保留用户输入。
- 删除、恢复、覆盖导入、规则停用等不可逆或高风险操作必须二次确认。
- 不为小程序单独建立同义字段；例如学生统一使用客户端规定的 `uuid`、`classUuid`、`name`、`schoolNo` 等字段。

### 4.3 导入与同步

- 客户端导出的 JSON 可以导入小程序；旧版数据先经过规范化和迁移，再写入 CloudBase。
- 小程序导出的结构化数据必须继续满足 `教师工作台-JSON备份交换格式-v1`。
- 附件内容与附件元数据分开处理；小程序页面不得假定所有附件已上传云端。
- 任何导入失败必须在写入前尽量完成预检；写入失败时保留批次失败状态和可追溯错误信息。

## 5. 完成判定

只有同时满足以下条件，才可以称为本规划完成：

1. 客户端模块名称、分组、页面入口和小程序路由一一对应。
2. 首页展示客户端概览所需的真实数据区块，而不是单一导入空状态。
3. 工作台和设置页不再出现截图中的贴边、超大卡片、过度留白和宽度失衡。
4. 所有客户端功能在小程序端都有实际页面、真实事件和可恢复状态；暂未支持的附件行为必须明确说明。
5. 旧版 JSON、V0.7.0 客户端导出 JSON 和当前规范 JSON 均可按兼容规则导入。
6. 数据读写始终按教师身份、数据集和稳定 UUID 隔离。
7. 串行全量测试通过，微信开发者工具编译通过，关键页面完成模拟器和真实设备验收。
