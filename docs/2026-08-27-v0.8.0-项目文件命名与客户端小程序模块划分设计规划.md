# 教师工作台 v0.8.0 项目文件命名与客户端/小程序模块划分设计规划

> 文档类型：项目级架构与命名规划  
> 建立日期：2026-08-27  
> 当前客户端基线：v0.7.0  
> 适用范围：Windows 客户端、微信小程序、CloudBase、共享契约、测试和项目文档  
> 核心原则：客户端是业务功能唯一基准，小程序是同一业务模型的移动端适配，不重新发明一套功能系统。

## 一、编制目的

项目同时包含桌面客户端、微信小程序、CloudBase 云函数、数据库规范、共享数据契约和测试文件。本规划通过统一文件名、目录职责和模块 ID，保证新增代码可以被快速定位，并保证客户端与小程序使用同一套业务边界、字段、状态和稳定 ID。

本规划不要求为了命名统一而移动已有目录。已有目录是兼容基线；命名规范从本文件生效后用于新增文件和明确的重构任务。

## 二、总原则

1. 客户端功能名称、业务流程、字段含义、状态枚举和统计口径是唯一业务基准。
2. 小程序只适配布局、操作顺序和控件形式，不重新定义业务功能。
3. 页面可以拆分，数据模型不能拆分成第二套；例如“表现量化”“规则管理”“修正历史”仍属于 `assessment` 域。
4. 跨端记录必须使用 `uuid`；SQLite 整数 `id` 只能作为本地键或 `legacyId`。
5. CloudBase 记录必须使用服务端取得的 `ownerId`、明确的 `datasetId`、`revision` 和软删除字段。
6. 文件名不写临时版本号，不使用 `new`、`final`、`test2`、`temp` 等不稳定名称。

## 三、顶层目录职责

```text
teacher-work/
├─ cloudbase/          CloudBase 结构、索引、权限和部署说明
├─ cloudfunctions/     CloudBase 云函数源码，一个函数一个目录
├─ docs/               架构、数据、UI、验收、发布和变更文档
├─ miniprogram/        微信小程序源码
├─ scripts/             构建、检查、打包和迁移脚本
├─ server/              桌面端本地 Express 服务和本地 API
├─ shared/              桌面端与小程序共享的数据契约和纯业务规则
├─ tests/               跨端、服务端、兼容性和静态契约测试
├─ web/                 桌面端 Vue 页面和组件
└─ src-tauri/           Tauri 外壳、原生命令和发布配置
```

| 内容 | 应放位置 | 不应放位置 |
| --- | --- | --- |
| 小程序页面 | `miniprogram/pages/` | `web/src/views/`、`cloudbase/` |
| 小程序服务 | `miniprogram/services/` | 页面中直接拼接云函数细节 |
| 云函数源码 | `cloudfunctions/<function-name>/` | `cloudbase/`、`miniprogram/` |
| CloudBase 说明 | `cloudbase/database/`、`cloudbase/functions.md` | 页面目录 |
| 桌面端页面 | `web/src/views/` | `miniprogram/pages/` |
| 跨端契约 | `shared/contracts/` | 任意单端页面目录 |
| 本地服务规则 | `server/routes/`、`server/domain/` | 小程序页面复制实现 |
| 测试 | `tests/` | 页面旁边临时散落文件 |

## 五、桌面端命名规范

### 5.1 页面和组件

Vue 页面使用 PascalCase，并与模块名称对应：

```text
web/src/views/Overview.vue
web/src/views/Students.vue
web/src/views/SubjectLeaders.vue
web/src/views/Assessment.vue
web/src/components/StudentCard.vue
```

- 一个顶层业务页面一个 Vue 文件；
- 多词模块使用 PascalCase；
- 可复用组件放入 `web/src/components/`；
- 页面私有的小结构可以保留在页面文件中，避免无意义拆分。

### 5.2 领域逻辑和路由

领域逻辑、组合式函数和工具使用 camelCase：

```text
web/src/domain/studentImport.js
web/src/domain/seatMovement.js
web/src/composables/useSeqLoad.js
web/src/utils/exportAssessment.js
```

路由使用小写 kebab-case，并与模块 ID 对应，例如 `/overview`、`/subject-leaders`、`/follow-up`。

## 六、微信小程序命名规范

### 6.1 页面

页面目录使用模块 ID 或明确的子流程，固定入口文件名为 `index`：

```text
miniprogram/pages/index/index.*
miniprogram/pages/workbench/index.*
miniprogram/pages/settings/index.*
miniprogram/pages/students/index.*
miniprogram/pages/student-detail/index.*
miniprogram/pages/assessment/index.*
miniprogram/pages/assessment-rules/index.*
```

页面文件固定为：`index.js`、`index.json`、`index.wxml`、`index.wxss`。

- 多词页面目录使用 kebab-case；
- 不使用 `page1`、`new-page`、`business` 作为正式业务页面名称；
- `business` 只能作为过渡兼容页面，不能继续承载新的正式模块；
- 页面不直接访问 CloudBase 管理接口，只调用服务层。

### 6.2 服务、组件和资源

```text
miniprogram/services/cloudbase.js
miniprogram/services/teacher-data.js
miniprogram/services/assessment-service.js
miniprogram/services/sync-service.js
miniprogram/components/section-block/
miniprogram/components/empty-state/
miniprogram/assets/icons/assessment.png
```

- 服务文件使用 kebab-case；方法使用 camelCase；
- `cloudbase.js` 只负责初始化和云函数调用；
- 复杂模块建立同名服务，不把数据校验复制到多个页面；
- 组件目录和资源文件使用 kebab-case；
- 不使用 emoji 作为图标。

## 七、CloudBase 命名规范

### 7.1 云函数

云函数目录使用小写 kebab-case，一个函数一个目录，入口固定为 `index.js`：

```text
cloudfunctions/query-data/index.js
cloudfunctions/import-data/index.js
cloudfunctions/student-data/index.js
cloudfunctions/attendance-data/index.js
cloudfunctions/follow-up-data/index.js
cloudfunctions/business-data/index.js
cloudfunctions/redeem-code/index.js
cloudfunctions/admin/index.js
```

函数名称体现业务域和职责；函数内部 `action` 使用 camelCase，如 `batchAssessment`、`contactStats`。所有授权相关逻辑必须从微信上下文取得身份，不能信任客户端传入的 `ownerId`。

### 7.2 数据集合

CloudBase 集合使用小写 snake_case，已建立名称永久保持：

```text
classes, students, attendance, leaves, follow_up_tasks,
scores, exams, seats, duties, contacts, documents,
assessment_categories, assessment_items, assessment_records,
assessment_revisions
```

## 八、跨端字段规范

所有跨端记录至少使用以下公共字段：

```text
uuid          跨端稳定主键
ownerId       服务端取得的教师身份
datasetId     数据集身份
revision      单调递增修订号
createdAt     创建时间
updatedAt     最后更新时间
deletedAt     软删除时间；未删除为 null
source        来源标识
```

- CloudBase 和共享 JSON 使用 camelCase；
- SQLite 既有 snake_case 字段继续兼容；
- 字段转换集中在契约或服务层；
- 日期使用 `YYYY-MM-DD`，月份使用 `YYYY-MM`；
- 状态值使用既有枚举；
- 表现量化保存分类、项目和分值快照，规则变化不能修改历史记录。

## 九、表现量化固定映射

| 概念 | 桌面端 | CloudBase | 小程序 |
| --- | --- | --- | --- |
| 分类 | `assessment_categories` | `assessment_categories` | `assessment-rules` |
| 行为项目 | `assessment_items` | `assessment_items` | `assessment-rules` |
| 记分记录 | `assessment_records` | `assessment_records` | `assessment` |
| 修正历史 | `assessment_record_revisions` | `assessment_revisions` | `assessment` 历史区 |
| 批量记分 | `/api/assessment/records/batch` | `business-data.batchAssessment` | `assessment-service` |
| 撤销/恢复 | `/api/assessment/records/:id/*` | `business-data.void/restore` | `assessment-service` |

不得因为端不同而为同一个概念创建第三套名称或第三套状态。

## 十、页面与功能划分

### 首页

首页只承担概览和每日入口。有数据时显示班级摘要、今日工作台、预警和近期事项；无数据时显示完整产品欢迎空状态及已有的数据导入入口，不把“未选择云端数据集”作为唯一内容。

### 工作台

工作台采用“业务分区块 + 紧凑功能块”，不采用长列表：

1. 班级基础：班级设置、学生管理、座位管理、班委学委、课代表选择；
2. 日常工作：考勤管理、请假管理、表现量化、跟进事项、家校沟通、值日管理；
3. 成绩与资料：成绩管理、数据分析、文档管理。

每个入口只对应客户端已有功能，不增加未定义的快捷统计或新业务。

### 设置

设置只承担数据与安全、身份与授权、帮助与关于，不重复放置班级业务编辑功能。

## 十一、文档和测试命名

文档格式：

```text
YYYY-MM-DD-vX.Y.Z-主题-文档类型.md
```

例如：`2026-08-27-v0.8.0-小程序核心三栏UI返工设计规范.md`。文档类型统一使用“设计说明”“实施规划”“验收记录”“发布检查清单”“开发总结”。

测试文件使用模块或领域名加 `.test.js`：

```text
tests/assessment.test.js
tests/assessment-ui.test.js
tests/cloudbase-database-contract.test.js
tests/miniprogram-navigation.test.js
tests/sync-contract.test.js
tests/legacy-normalizer.test.js
```

## 十二、实施顺序

### 阶段一：规范落地

- 将本文件作为新增文件的命名基准；
- 登记桌面端路由、页面、小程序页面、服务、云函数和集合映射；
- 标记 `business` 等过渡文件；
- 不做无必要的目录移动和机械重命名。

### 阶段二：核心 UI 重构

- 按客户端“小亮实验室”风格重做首页；
- 将工作台改为业务分区块和紧凑功能块；
- 将设置改为分组状态入口；
- 建立小程序共享视觉组件和状态组件。

### 阶段三：业务页面统一

按客户端模块依次统一学生、考勤、请假、跟进、表现、成绩、分析、座位、值日、班委、课代表、沟通、文档及系统数据页面。每项均需完成“页面 → 服务 → 云函数 → 集合 → 稳定 ID”登记。

### 阶段四：跨端验收

- 使用同一脱敏数据执行桌面端和小程序端相同操作；
- 验证新增、编辑、软删除、恢复和统计一致；
- 验证旧版 JSON/ZIP 继续可导入；
- 验证小程序记录能被客户端按 `uuid` 识别；
- 最后配置管理员、兑换码和正式更新地址。

## 十三、完成判定

- 新增文件遵守目录和命名规则；
- 客户端和小程序模块 ID 一一对应；
- 页面、服务、云函数和集合可追溯；
- 旧版导入和构建不受破坏；
- 字段、状态和稳定 UUID 没有页面私有替代版本；
- 首页、工作台和设置符合客户端逻辑与移动端习惯；
- 高风险操作具备权限、确认、失败提示和恢复路径；
- 文档、测试和提交记录能说明每个模块的完成状态。
