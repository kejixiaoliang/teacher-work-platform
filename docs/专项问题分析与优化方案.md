# 教师工作台专项问题分析与优化方案

## 一、目标

本专项针对当前使用中发现的五类问题进行集中修复：

1. 学生列表在桌面窗口内无法完整展示，必须左右滚动。
2. 学生健康信息更新后，历史档案没有同步形成新记录。
3. 座位手动拖拽到空座或其他座位不稳定，操作结果不符合预期。
4. 成绩科目需要适配不同年级和不同考试，字段配置与导入规则还不够完善。
5. 每日考勤需要默认全员出勤，并主动提示当天有效请假学生。

原则：优先保证数据正确性，其次优化高频交互，最后补齐可配置和批量导入能力；每完成一个小阶段都单独验证、提交并推送 GitHub。

## 二、问题分析

### 2.1 学生列表布局受限

当前学生页同时展示选择框、学号、姓名、性别、身高、视力、近视、成绩、住宿、家长电话、职务/特长、状态、跟进和操作列，列总宽度已经超过主内容区。操作列又被固定在右侧，导致中间字段被压缩，最终出现截断和横向滚动。

这不是单纯把页面外框放大就能完全解决的问题。需要同时处理：

- 主内容区最大宽度和左右内边距。
- 表格列的优先级和最小宽度。
- 操作列的按钮数量与展示方式。
- 低频字段的折叠或详情展示。
- 低分辨率窗口下的响应式策略。

方案采用“桌面宽屏优先完整展示 + 中等宽度自动收 compact 列 + 详情抽屉保留完整字段”，不删除数据字段。

### 2.2 健康数据没有进入历史档案

当前编辑学生时只调用学生更新接口，身高、左右眼视力和近视状态只更新 `students` 当前值；历史表 `student_metrics_history` 只有“学期存档”入口才会写入。因此用户直接修改健康信息后，详情页的历史记录不会变化。

需要明确历史语义：

- 当前值保存在 `students`，始终代表最新状态。
- 每次健康字段发生实际变化时，追加一条历史快照。
- 同一次保存中多个健康字段变化只生成一条快照。
- 如果保存内容没有变化，不重复生成历史记录。
- 快照携带学期、记录时间和来源，便于追踪是“编辑保存”还是“学期存档”。

这个写入必须和学生更新放在同一个 SQLite 事务中，避免出现当前值已更新但历史没有写入的半成功状态。

### 2.3 座位拖拽不稳定

当前实现主要依赖 HTML5 原生 `dragstart/drop`。理论上拖到空座应当交换学生与空值，但实际使用容易受到以下因素影响：

- 浏览器拖放事件在座位内部子元素上触发不一致。
- 空座位对象未完整初始化时，目标格读取失败。
- 锁定座位、空座和学生座位的处理路径不够明确。
- 没有点击选择后再点击目标座位的兜底操作。
- 拖拽完成后只改前端内存，缺少明确的“已调整”反馈。

方案保留拖拽，同时增加稳定的“选择座位 → 点击目标座位”换座模式，并统一抽象为一个 `moveSeat(source, target)` 操作。拖到空座是移动，拖到有学生座位是交换，目标锁定时给出明确提示，源座位锁定时禁止操作。

### 2.4 成绩科目配置和导入适配不足

当前考试已经支持多选和自定义科目输入，成绩 Excel 也已有导入入口，但仍需要进一步完善：

- 科目配置散落在考试表单中，无法复用上一场考试。
- 不同年级、不同考试类型缺少科目模板。
- 修改考试科目时，已有成绩的保留和删除规则不够明确。
- Excel 表头、重复科目、未知学生和非法成绩需要更清晰的导入预览。
- 成绩科目应允许用户增加、删除、排序。

方案采用“科目模板 + 当前考试科目”的两层结构：模板用于快速创建，考试保存自己的科目快照；修改考试科目时不自动删除已有成绩，只提示不再展示的历史科目仍保留在数据库中。

### 2.5 考勤默认出勤和请假提醒

后端读取当天考勤时已经对没有记录的学生返回“出勤”，请假模块也已经可以把有效请假同步为“请假”记录。但前端当前主要依赖用户看到表格后手动确认，缺少明显的提醒和处理入口。

目标流程：

1. 打开当天考勤，所有未登记学生显示为“出勤”。
2. 当天有效请假的学生自动显示“请假”。
3. 页面顶部显示“今日有 N 名学生请假，请确认考勤状态”。
4. 每名请假学生显示请假类型、时间范围和原因摘要。
5. 若老师手动改为出勤或迟到，系统尊重手动结果，不在保存时强制覆盖。
6. 请假变更、销假或删除时，只清理由系统联动产生的考勤记录，不破坏老师手动登记。

## 三、实施阶段

### 阶段 A：学生列表布局（P0）

- 放宽主内容区的合理最大宽度。
- 重新设置学生表格列宽和字段优先级。
- 操作列改为紧凑按钮或更多菜单，减少固定列占用。
- 低频字段在中等窗口进入紧凑模式，详情抽屉保留完整信息。
- 验收：常见 1366×768 和 1920×1080 窗口下，主要字段无需横向滚动即可查看；操作入口仍可用。

### 阶段 B：健康数据历史同步（P0）

- 新增健康字段变更检测。
- 在学生更新事务中追加健康快照。
- 增加来源字段或来源备注，区分手动编辑和学期存档。
- 修正导入学生时的历史策略：批量导入只写当前值，不无意义生成历史；明确提供“导入并记录快照”选项。
- 验收：修改身高、任一眼视力或近视状态后，历史页出现一条新记录；只修改姓名等非健康字段不产生快照。

### 阶段 C：座位移动重构（P0）

- 抽取统一的移动/交换函数。
- 补全所有网格空座对象。
- 增加点击选择换座兜底。
- 明确空座移动、有座交换、锁定拦截和撤销提示。
- 增加座位调整前后人数校验，避免学生重复或丢失。
- 验收：学生→空座、学生→学生、空座→学生、锁定座位四种场景均可预测处理，并能保存后重新加载。

### 阶段 D：动态成绩科目和 Excel 导入（P1）

- 增加常用科目模板管理。
- 新建考试支持模板、手动增加、删除和排序科目。
- 修改科目时显示已有成绩影响提示。
- Excel 导入支持表头识别、未知科目提示、重复表头提示、非法分数提示和导入结果汇总。
- 验收：至少覆盖小学、初中、高中三种科目组合，且导入失败行不影响有效行。

### 阶段 E：考勤与请假联动（P1）

- 后端返回当天有效请假摘要。
- 前端加载考勤时自动合并请假状态。
- 增加顶部提醒、行内请假说明和手动覆盖提示。
- 保存后重新加载，确保状态与请假记录一致。
- 验收：新建请假、修改请假日期、销假、删除请假、手动覆盖考勤五种场景都能正确处理。

## 四、提交与验证规则

每个阶段独立完成以下动作：

1. 修改前确认当前分支和工作区状态。
2. 完成一个阶段后运行后端语法检查和 `npm run build`。
3. 对关键接口进行最小回归测试。
4. 使用中文提交信息提交。
5. 推送当前任务分支到 GitHub。
6. 在后续阶段开始前确认本地分支与远程同步。

## 五、暂不扩大范围

本专项不同时引入账号系统、云端同步、移动端重写、复杂低代码字段引擎或成绩排名体系重构。先把当前高频使用链路的数据正确性和操作稳定性做好。
