# 小程序移动端 UI 一致性审查与改造规划

## 1. 审查范围

目标平台为微信小程序，审查范围覆盖 `miniprogram/pages/` 下全部 28 个页面、三栏入口
`首页 / 工作台 / 设置`、共享样式 `app.wxss` 与 `tokens.wxss`，以及微信 CloudBase
身份初始化和设置页身份入口。审查只调整布局、排版、交互反馈与身份状态呈现，不改变数据
集合、云函数接口、权限边界和业务字段。

## 2. 当前问题复盘

### 2.1 页面结构不统一

- 页面内边距同时出现 `24rpx`、`28rpx`、`32rpx`、`34rpx`、`40rpx`，底部安全区也有
  `48rpx`、`60rpx`、`64rpx`、`96rpx` 多套值。
- 标题字号在 `46rpx`、`48rpx`、`62rpx` 间跳变，部分页面没有统一的眉题、标题、说明
  三段层级。
- 同类列表有的使用实色粗边框和偏移阴影，有的使用浅色细边框；按钮高度、圆角和文字
  大小不一致，导致页面切换时操作目标位置和视觉重量变化。
- 表单页面缺少统一字段间距、错误提示区域和底部操作区，长页面容易把主操作推到屏幕
  边缘。

### 2.2 颜色和字体未收敛

- 已有暖纸、墨黑、番茄红、芥末黄、薄荷绿视觉基因，但部分页面仍使用独立的
  `#1d2939`、`#667085`、`#b54708` 等另一套冷灰配色。
- 共享令牌已存在，但约一半页面直接写入颜色、边框和阴影，修改主题时会出现漏改。
- 标题大多已采用 `Noto Serif SC`，正文虽有共享字体栈，控件未全部继承，造成字号和
  字重观感不齐。

### 2.3 移动端可操作性不足

- 多个页面同时放置筛选、导出、批量操作，窄屏时按钮折行规则不一致。
- 列表行高度和点击反馈没有统一的最小触达尺寸，部分操作需要精确点击小文字。
- 页面底部没有统一避让安全区，固定或长列表场景可能被系统手势条遮挡。
- 空状态、加载态、错误态的文案和留白密度不同，恢复操作不总是出现在用户视线内。

### 2.4 第三栏缺少清晰的“当前用户”入口

- 设置页已有“微信身份与授权”跳转，但入口只是普通设置行，用户看不出当前身份是否
  已就绪。
- 小程序不应构造 Web 式账号密码登录。微信小程序通过 `wx.cloud.init({ traceUser: true })`
  使用微信原生身份，云函数从 `wx-server-sdk` 上下文取得 `OPENID`。
- 需要把“登录”解释为“微信身份已就绪”，在设置页顶端提供状态摘要，并保留身份检查、
  授权说明和失败重试；不展示 OPENID、不落地长期 token。

## 3. 统一视觉规范

### 3.1 视觉方向

Editorial / magazine：暖纸背景、墨黑标题、实色强调块和克制的偏移阴影，形成适合教师
快速扫读的“纸面工作台”。页面通过左侧编号眉题、非对称标题区和分组横条建立阅读锚点。

### 3.2 令牌

| 类别 | 统一值 |
| --- | --- |
| 背景 | `#FFF4DC`；内容纸张 `#FFF9EA`；输入面板 `#FFFDF4` |
| 文字 | 墨黑 `#201B17`；次要文字 `#685F55` |
| 强调 | 番茄 `#D64541`；芥末 `#F2C84B`；薄荷 `#8BD6AF`；天空 `#93C9D8` |
| 边框/阴影 | 线条 `#D9CBB0`；墨黑偏移阴影 `6rpx 6rpx 0` |
| 页面边距 | 横向 `32rpx`；顶部 `40rpx`；底部 `calc(96rpx + env(safe-area-inset-bottom))` |
| 触达尺寸 | 主按钮最小高度 `84rpx`；列表行最小高度 `88rpx`；圆角 `16rpx` |
| 字体 | 标题 `Noto Serif SC, Songti SC, serif`；正文 `Noto Sans SC, PingFang SC, Microsoft YaHei, sans-serif` |

### 3.3 页面骨架

所有页面统一采用：`page-shell → page-topline → page-title → page-lead → section-head →
content → bottom-safe`。列表和表单可以保留业务差异，但必须复用共享的页眉、分组标题、
状态块、按钮和输入令牌。

## 4. 逐页改造分组

### A 组：三栏与核心导航（第一优先级）

`index`、`workbench`、`settings`：统一首屏节奏、横向滚动班级选择、今日工作入口和设置
分组；设置页新增“当前微信身份”摘要行，显示“已就绪 / 检查中 / 需要重试”，点击进入
身份页。三栏仍保持首页、工作台、设置，不增加额外 tab。

### B 组：高频业务（第二优先级）

`students`、`student-detail`、`attendance`、`leaves`、`follow-up`、`scores`、`assessment`、
`analysis`：统一筛选栏、列表行、批量操作和底部操作区，确保单手操作时主按钮固定在
可见区域附近。

### C 组：班级与协作（第三优先级）

`class-settings`、`seats`、`duties`、`leaders`、`subject-leaders`、`contacts`、`documents`、
`business`：统一表单字段节奏、分组卡片和空状态，复杂网格在窄屏下支持横向滚动而不挤压
文字。

### D 组：数据交换、身份与信息（第四优先级）

`import`、`backup`、`sync`、`identity`、`redeem`、`guide`、`about`、`changelog`、
`assessment-rules`：统一风险提示、成功/错误反馈和操作确认样式；身份页只呈现微信原生
身份状态，不引入登录表单。

## 5. 微信身份登录设计

1. `app.js` 保持 CloudBase 原生初始化和 `traceUser: true`，不新增账号密码或 Web OAuth。
2. 增加轻量的全局身份状态：`checking / ready / unavailable`。状态检查通过现有
   `identity-status` 云函数完成；管理端无法获得 OPENID 时只显示检查失败，不暴露标识。
3. 设置页首屏放置身份摘要：状态徽标、当前数据按微信身份隔离的说明、进入“身份与授权”
   的整行按钮。
4. 身份页继续提供重新检查和授权边界说明；所有云函数调用仍以服务端上下文身份为准。
5. 失败时给出“重新检查”操作和可读文案，不阻塞本地页面浏览；需要真实身份的读写操作
   仍由云函数返回 `AUTH_REQUIRED` 进行保护。

## 6. 实施顺序与验收

1. 先收敛 `tokens.wxss`、`app.wxss` 和公共页面骨架类，补充安全区、触达尺寸、状态块、
   按钮和输入令牌。
2. 依次改造 A/B/C/D 四组页面，优先只改样式和结构，不改业务服务调用。
3. 接入全局身份状态和设置页身份摘要，补充空态、错误态、加载态的一致文案。
4. 对每个页面执行 WXML/WXSS 静态检查；运行现有 Node 测试和构建；检查无新增业务接口
   变更。
5. 由用户在屏幕空闲时使用微信开发者工具进行真实点击验收，重点检查窄屏、底部安全区、
   横向滚动、表单提交和身份状态入口。

## 7. 完成标准

- 28 个页面均使用统一页眉、横向间距、底部安全区和状态反馈令牌。
- 高频操作的按钮/列表行满足最小触达尺寸，窄屏不出现不可点击或文字溢出。
- 设置第三栏可一眼看见微信身份是否就绪，并能进入身份检查页；不出现 Web 登录表单或
  OPENID 泄露。
- 自动化测试、构建和静态检查通过；真实微信开发者工具点击验收由用户完成并记录结果。
