# 教师工作台 v0.7.0 客户端数据兼容与版本升级规范

> 建立日期：2026-08-28  
> 适用对象：Windows/Tauri 便携客户端及其本地数据  
> 文档类型：数据兼容与版本升级规范  
> 当前基线：v0.7.0

## 1. 目的与范围

本规范规定桌面客户端在版本升级、换电脑、备份恢复和历史数据导入时必须遵守的兼容规则。当前验收主体是客户端，不要求小程序参与客户端升级验收；未来小程序或 CloudBase 仍可通过 JSON 交换格式接入，但不得改变客户端的数据兼容承诺。

本规范覆盖四条独立兼容链：

1. SQLite 本地数据库结构迁移。
2. 完整 ZIP 备份恢复（数据库和附件）。
3. JSON 结构化交换与历史版本导入。
4. 学生/成绩等模块文件交换的字段兼容。

## 2. 永久兼容承诺

### 2.1 必须保证的方向

新版本客户端必须能够读取和导入旧版本客户端已经承诺支持的数据库、ZIP 和 JSON 数据。升级不得要求用户先安装所有中间版本，也不得因为新增表、新增字段或字段重命名而拒绝旧数据。

兼容关系是单向的：

```text
旧客户端数据 ──> 新客户端：必须支持
新客户端数据 ──> 旧客户端：不保证，除非该格式明确声明向前兼容
```

### 2.2 版本号独立

软件版本、SQLite `user_version`、JSON `formatVersion`、ZIP 容器版本和模块文件版本彼此独立。软件版本升级不自动意味着所有数据格式都升级；只有结构、语义、关系或校验规则发生不兼容变化时，才提升对应格式版本。

### 2.3 导出与导入原则

- 新版本默认只导出最新规范。
- 新版本永久保留旧版本导入器和迁移器。
- 历史文件只读，不覆盖改写原文件。
- 迁移必须先识别格式，再转换为统一业务模型，最后校验并写入。
- 不能识别或无法安全转换的格式必须明确报错，禁止静默丢弃数据。

## 3. 四条兼容链

### 3.1 SQLite 数据库迁移

- 每次结构变化追加一个不可变迁移版本。
- 已发布迁移脚本不得修改，只能追加后续迁移。
- 长期未升级的数据库必须能够逐版本迁移到当前版本。
- 迁移前创建恢复快照；迁移失败时保留原数据库可恢复。
- 字段重命名、枚举变化和关系变化必须有明确转换和异常报告。
- 数据库迁移不等同于备份文件迁移，二者必须分别测试。

### 3.2 完整 ZIP

完整 ZIP 用于客户端整体恢复和换电脑，至少包含：

```text
backup.json
manifest.json
files/...
```

导入时必须校验路径安全、文件大小、MIME、SHA-256、数据库完整性和附件引用。恢复前创建数据库与附件目录快照；任何一步失败都不能留下半恢复状态。

### 3.3 JSON 交换

JSON 是长期结构化交换格式，不依赖 SQLite 表名或本地数字 ID。每个格式版本有独立迁移器；旧字段可以读取后转换或丢弃，但不能因其存在而失败。稳定 UUID、父子关系和业务语义必须保持不变。

当前客户端至少承诺支持：

| 来源 | 新版客户端处理 |
| --- | --- |
| v0.7 `teacher-work-backup` JSON v1 | 必须导入 |
| v0.6 及更早兼容 JSON | 按已登记迁移器导入 |
| legacy `tables` JSON v1/v2 | 保留读取器并给出转换报告 |
| 不支持的格式版本 | 明确拒绝，不静默导入 |

### 3.4 Excel 和模块文件

Excel 适合人工录入和模块交换，不替代完整备份格式。字段映射、空值、日期、重复行和公式注入防护必须独立版本化并测试。升级后仍应读取已承诺支持的旧模板；删除字段时保留兼容读取，不把缺失成绩默认为 `0`。

## 4. 恢复、更新导入和安全边界

- “恢复整个工作台”是替换语义，必须显示覆盖警告。
- “更新导入”不得清空现有数据，默认导入为新数据集或新班级。
- 导入前必须预检、预览并显示记录数量、附件状态、警告和冲突。
- 重复导入使用 `exportId` 或等价来源 ID 做幂等保护。
- 密码摘要、盐、恢复密钥、Token、会话和本地绝对路径永不导出或恢复。
- 恢复后保留当前设备的安全设置。
- 导入失败必须能恢复导入前的数据库和附件状态。

## 5. 发布前兼容性门槛

客户端新版本发布前必须同时完成：

1. 当前版本导出后再导入，业务数据和关系保持一致。
2. 最近两个交换格式版本导入测试。
3. 已承诺支持的 v0.5/v0.6/v0.7 脱敏样本导入测试。
4. 跨多个 SQLite `user_version` 逐级升级测试。
5. ZIP 附件完整、缺失、重复和恶意路径测试。
6. 导入中断、磁盘不足、数据库损坏和回滚测试。
7. 升级前后班级、学生、座位、成绩、考勤、请假、文档和附件数量核对。
8. 记录迁移前版本、目标版本、结果、警告和错误类型。

没有历史样本、回滚证据或真实升级记录时，只能称为“代码已实现”，不能称为“版本兼容已验证”。

## 6. 当前基线与待补齐项

当前已有 JSON v1 规范、SQLite 迁移序列、ZIP 备份恢复、legacy tables v1/v2 读取器和对应自动化测试。仍需持续补充真实脱敏的 v0.7、v0.6、v0.4.2 数据样本，并在每个客户端发布版本中执行兼容矩阵回归。

小程序、CloudBase 和跨端同步不属于本规范的客户端验收范围；它们只能复用本规范定义的 JSON、UUID 和业务字段，不能反向削弱客户端的旧数据导入能力。

## 7. 一句话规则

> 新版客户端可以不认识新版数据，但绝不能不认识自己已经承诺过的旧版数据；任何不兼容变化都必须先有迁移器、样本和回滚证据，再进入发布。
