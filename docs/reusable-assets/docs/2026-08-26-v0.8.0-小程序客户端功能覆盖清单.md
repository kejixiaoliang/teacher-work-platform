# 教师工作台 v0.8.0 微信小程序客户端功能覆盖清单

> 建立日期：2026-08-26  
> 当前客户端基线：v0.7.0  
> 目标：确保小程序最终完整覆盖客户端已有功能  
> 状态：执行基线

## 一、使用说明

本清单是小程序 UI 实现和验收的功能边界。小程序不增加新的业务模块，也不删减客户端已有能力。

“移动端适配”只允许改变布局、页面拆分、操作顺序和控件形式；客户端已有的查看、新增、编辑、删除、导入、导出、调整和保存能力，都必须在小程序端提供对应入口。

数据字段、稳定 ID、状态枚举、统计口径、权限和 CloudBase 数据契约以现有 v0.8.0 数据规划为准，本清单不重新定义数据模型。

## 二、三栏归属

| 小程序栏目 | 主要职责 | 功能范围 |
| --- | --- | --- |
| 首页 | 概览和每日入口 | 概览首页、今日工作台、现有预警和待跟进事项 |
| 工作台 | 全部班级业务功能 | 班级、学生、考勤、请假、表现、成绩、座位、值日、班委、课代表、沟通、文档和分析 |
| 设置 | 系统、数据和帮助 | 班级设置中的系统入口、数据导入/备份/恢复/同步、登录授权、版本更新、使用指南和联系作者 |

三栏是导航分组，不是功能删减。任何功能必须能从这三栏中的某个入口进入。

## 三、功能覆盖矩阵

| --- | --- | --- | --- | --- |
| F01 | 概览首页 | 首页 | 查看概览、预警、近期考试和待跟进事项，并跳转到对应模块 | 使用现有统计口径和关联 ID |
| F02 | 班级设置 | 工作台 → 班级设置 | 新建、编辑、切换、删除班级，维护班级基础信息和座位网格 | 保持 `classUuid`、`datasetId` 和班级字段一致 |
| F03 | 学生管理 | 工作台 → 学生管理 | 列表、搜索、新增、编辑、删除、批量导入、导出和学生详情 | 保持学生稳定 ID、字段和父班级关系 |
| F04 | 座位管理 | 工作台 → 座位管理 | 查看、移动、交换、调整布局、保存布局和查看历史布局 | 使用统一学生 ID，不产生移动端临时主键 |
| F05 | 数据分析 | 工作台 → 数据分析 | 查看现有班级结构、健康、成绩和表现统计及趋势 | 不改变指标定义和时间范围规则 |
| F06 | 成绩管理 | 工作台 → 成绩管理 | 新建考试、维护科目、录入、导入、编辑、删除、排名、统计和趋势 | 保持考试、科目、学生和成绩记录关系 |
| F07 | 考勤管理 | 工作台 → 考勤管理 | 选择日期、登记、修改、批量处理和查看汇总 | 使用统一日期、学生 ID 和考勤状态 |
| F08 | 表现量化 | 工作台 → 表现量化 | 维护分类和规则、选择对象、批量记分、修改、历史和统计 | 保持规则、对象、记录和修订关系 |
| F09 | 请假管理 | 工作台 → 请假管理 | 新增、查看、编辑、处理状态和查看请假记录 | 与考勤联动时使用同一学生和日期规则 |
| F10 | 跟进事项 | 学生详情 / 首页待跟进 | 新增、查看、编辑、完成、修改结果和历史 | 保持学生关联和事项状态枚举 |
| F11 | 家校沟通 | 学生详情 / 工作台 | 新增、查看、编辑和管理沟通记录 | 保持学生关联、方式和日期字段 |
| F12 | 值日管理 | 工作台 → 值日管理 | 查看、创建、编辑、删除和维护值日安排 | 保持学生和日期/周期关系 |
| F13 | 班委学委 | 工作台 → 班委学委 | 查看、设置、调整和保存班委学委关系 | 保持学生 ID 和职务语义一致 |
| F14 | 课代表选择 | 工作台 → 课代表选择 | 按科目查看、选择、调整和保存课代表 | 保持科目与学生关联 |
| F15 | 文档管理 | 工作台 → 文档管理 | 查看、上传、重命名、删除和管理文档；按既定规则处理下载 | 元数据使用统一关联；附件策略遵守 CloudBase 规划 |
| F16 | 数据导入 | 设置 → 数据导入 | 选择 JSON、预检、预览、确认、提交和查看失败报告 | 使用永久兼容规则、`exportId` 和 `importBatchId` |
| F17 | 数据备份与恢复 | 设置 → 数据备份 | 创建备份、选择恢复内容、确认、恢复和查看结果 | 不覆盖旧格式兼容能力；恢复前保留快照 |
| F18 | 数据同步 | 设置 → 数据同步 | 查看状态、首次确认、上传/下载变更、重试和查看冲突 | 使用统一 `uuid`、`revision`、软删除和同步游标 |
| F19 | 登录与授权 | 设置 / 首次进入 | 微信身份识别、授权状态、兑换码状态和电脑端绑定 | 服务端取得 `ownerId`，不信任客户端传入 |
| F20 | 使用指南 | 设置 → 使用指南 | 查看与客户端一致的功能说明和操作步骤 | 文案使用现有功能名称 |
| F21 | 版本更新 | 设置 → 版本更新 | 查看版本记录、更新内容和客户端更新入口 | 不改变本地数据和附件 |
| F22 | 联系作者与关于 | 设置 → 关于/联系作者 | 查看现有作者联系方式、软件信息和隐私说明 | 不新增用户社交或消息业务 |

## 四、移动端适配约束

### 4.1 页面形式

- 电脑端宽表格改为列表、分段信息或横向滚动区域；
- 电脑端右侧详情面板改为独立详情页；
- 多步骤批量操作改为步骤页或底部操作面板；
- 复杂表单按信息组拆分，但提交仍是同一条业务记录；
- 座位等复杂交互允许使用“选择学生 → 选择目标位置 → 确认保存”的移动端流程；
- 图表改为窄屏可读的纵向布局或分段查看。

### 4.2 操作体验

- 常用操作应能在单手操作下完成；
- 所有写入操作都显示加载、成功、失败和重试状态；
- 删除、恢复、批量修改和同步等高风险操作必须二次确认；
- 页面返回不能造成未保存数据静默丢失；
- 列表、详情、编辑和结果页之间的返回路径清晰；
- 空数据、无权限、网络失败和云端处理中状态必须明确区分。

### 4.3 不允许的简化

- 不得把可编辑模块改成永久只读；
- 不得只实现首页和学生查看而省略其他客户端功能；
- 不得因为手机屏幕小而删除字段或改变统计口径；
- 不得把导入、备份、恢复和同步混成无法追溯的一键操作；
- 不得用小程序专属 ID 替换统一业务 ID。

## 五、数据映射登记要求

每实现一个页面，必须同时登记以下内容：

```text
页面名称
对应客户端功能
读取的 CloudBase 集合
写入的 CloudBase 集合
datasetId 来源
ownerId 来源
使用的稳定 ID
字段和状态枚举
错误码和空状态
```

页面开发完成前，先确认数据映射；页面完成后，再用客户端和小程序各执行一次同样的业务操作进行对照。

## 六、分阶段实施顺序

### 阶段 A：基础框架

- 三栏导航；
- 首页和工作台目录；
- 设置目录；
- 班级、学生只读基础链路；
- 统一加载、错误、空状态和权限状态。

### 阶段 B：高频业务闭环

- 学生管理完整操作；
- 考勤和请假；
- 表现量化；
- 跟进事项；
- 家校沟通。

### 阶段 C：班级事务和成绩

- 成绩管理；
- 数据分析；
- 座位管理；
- 值日管理；
- 班委学委；
- 课代表选择；
- 文档管理。

### 阶段 D：系统和数据能力

- 数据导入、备份和恢复；
- CloudBase 同步；
- 微信登录、授权和电脑端绑定；
- 兑换码状态；
- 使用指南、版本更新和联系作者。

阶段 A 只是先建立可验证的安全基础，不代表阶段 B、C、D 的功能被取消或降为电脑端专属。

## 七、完成判定

只有满足以下条件，才可以宣称“小程序功能与客户端完整覆盖”：

- F01 至 F22 均有可进入的小程序页面或明确入口；
- 每项功能都能完成客户端已有的对应操作闭环；
- 每项写入都使用统一数据契约和稳定 ID；
- 客户端新增或修改的数据能在小程序正确显示；
- 小程序新增或修改的数据能被客户端按同一 ID 正确识别；
- 旧版 JSON/ZIP 兼容导入不受页面改造影响；
- 所有页面通过移动端可操作性、错误恢复和权限隔离验收；
- 没有以“移动端暂不支持”长期搁置的客户端功能。
